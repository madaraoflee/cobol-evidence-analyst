# 框架参考资料接入规格

日期：2026-09-19；范围：当前网页与源码问答流程。

当前问答栈和源码快照新鲜度的最新边界见[当前实现与已知限制](../docs/16-current-implementation-status.md)。本规格中的引用/快照要求不表示普通元数据复用路径已提供内容级新鲜度保证。

实现采用 Python 标准库、本地 SQLite 与三语言静态网页。`framework_knowledge.py` 负责读取、分段、检索和来源信息，`analyze_source.py` 在入口详细解析后建立本次上下文，`run_agent.py` 绑定快照并传递，`agent_loop.py` 核对两类引用，`web_app.py` 和 `web/app.js` 显示加载／匹配／解释状态。现有路径执行器不属于此接入。

## 可观察要求

- 当配置 `FRAMEWORK_REFERENCE_PATH` 时，系统读取指定私有文档；相对路径以项目根目录为准，进程环境优先于 `.env`。
- 当只接入源码目录时，系统不为框架知识重新解析全部源码；当选定入口后，只在当前入口的局部结构索引中检索。
- 当源码词项匹配资料时，系统保留源码行号、源 hash、文档 hash、文字行号和可用页码；只有问题命中文档不能显示源码匹配成功。
- 当 COPY 或调用对象不可见时，系统继续保留已有源码观察，框架约定不能升级为闭源实现或执行结果。
- 当模型提出框架解释时，系统要求有效源码引用和此次资料引用；两类 ID 不可互换，文档指令不得改变工具能力。
- 当源快照失效或取消分析时，系统撤销本次源码匹配；当资料更新时，新结果使用新文档 hash，旧结果不得自动升级。

## 非功能约束与验收

参考资料上限 2 MiB，检索最多 10 段／16,000 字符；入口扫描最多 120,000 个索引单元／8 MiB，最多显示 20 处源码匹配。达到预算须显示范围限制。工具与模型输入继续遵守原有证据读取预算；系统不执行文档命令，也不跟随其中链接。

`test_framework_knowledge.py` 覆盖加载、检索、来源、更新、预算和入口隔离；`test_agent_framework_context.py` 覆盖双引用、注入与权限边界；`test_framework_workflow.py` 使用实际结构索引、运行器和模拟传输检查整条流程；网页测试覆盖三语言、转义和旧状态隐藏。

## 尚待现场确认

词项匹配只支持候选关联，不能独立证明业务相关性、分支可达性、隐式调用图或完整值流。该实现是否足以准确解释目标公司程序，仍需真实源码、现场元数据和获准模型的参考案例验收。后续优先根据实际未命中项扩展检索与语义关联，避免用更宽泛的成功状态掩盖缺口。
