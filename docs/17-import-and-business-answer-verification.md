## 修复内容

新文件导入不再为删除不存在的旧记录而扫描已有全文索引；规则写入按文件聚集，减少大库随机写入退化；批量保存目录缓存。未修改文件复用已建立的结构、调用关系和全文索引，取消业务导入中的重复整库内容读取。需要主动完整核对时，仍可执行已有的完整内容验证。

文件创建时间不再参与当前源码校验。新增回归模拟持续变化的 `ctime_ns`，覆盖导入、缓存复用、源码读取、框架资料读取与旧缓存兼容；真实内容修改仍可由完整内容校验识别。

最终回答使用 Markdown 正文，网页支持加粗、段落、列表、表格和引用。兼容常见的整篇 Markdown 围栏和旧回答外层包装，格式不规范不会新增阻断或要求模型付费重试。渲染器随项目提供，不依赖外部 CDN。

默认面向业务分析师解释问题：先给业务结论，再按需要说明条件、计算口径、例外和影响，不固定套一组栏目，不限定业务主题。只有明确要求源码或开发实现时才展示必要的代码。问题涉及程序、文件或字段定位时保留准确名称，来源依据可以展开查看。

框架资料原文进入正式对话的每轮分析上下文；回答要求把资料约定与当前程序的传入数据、调用条件和后续分支对应起来，再解释业务含义。传入资料时保留有界的匹配词和源码位置，作为定位线索，不能代替对原文的理解或证明缺失源码的内部行为。

修复了弱问题词匹配挤掉基础框架说明的情况：在原有预算内保留最多两段、共 1,600 字符的基础概览，再选择相关原文。基础背景不冒充实际源码匹配。本机用户手册离线加载正常；没有源码匹配的示例问题现在保留总体架构与分布式业务语义，仍不会凭空生成源码匹配。
