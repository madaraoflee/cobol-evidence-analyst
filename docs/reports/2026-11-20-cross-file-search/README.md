# 跨文件字面检索与业务问答复测

基线为合入 PR #34 的 `c838384860806d2e06d2bbe335ec66f585dab68b`。在 134 个定长合成 COBOL 文件中，`XADJKEY` 出现在条件中的长代码 `PM/XADJKEYENDORSED` 内。正常建立的本地索引按完整词匹配，返回零个文件。原有后备检索检查前 128 页后达到上限。最终交付的 8 页都没有目标条件，同一输入上的固定字符串搜索可以定位第 4 行。另一方面，检索 `PREMIUM COLLECTION` 仅命中注释和屏幕文案；实际算式位于经 `CALL` 到达的单独文件中。修复前的具体输出见 `local-before.json`。

## 修改范围

本地单纯增加回退页数会把遗漏推到更靠后的文件。每次从磁盘打开全部源码又会重复付出读盘和版本检查的代价。本次本地修改限于已经导入的源码中的字面定位及实际问答供证；仍按所选文件范围、源码版本、证据行和既有调用关系生成回答。在线入口按每周固定提交检索，定位结果用作回读原文的线索。公司现场的扣减顺序和目标设备耗时仍由原有现场条目跟踪。

## 实测结果

- 本地在已保存的完整原文页中查找明确的业务标识，优先选择含该标识的条件或操作。对于 `XADJKEY`，词检索仍为零，实际给首个模型请求的页已经包含条件和原文引用。独占文件范围、取消、旧版本失效、同页分散的多个条件及调用后参数改名均有回归。没有保存为完整页的内容仍须沿已知文件的原文读取入口核验。
- 在线把各文件可包含的短文字片段编码为分组压缩的候选过滤信息，允许多选候选；按版本取回候选原件确认物理行，再读具体行提供引用。旧材料使用词表候选，超过词表预算则返回剩余范围及已有的目录入口。模拟问答先定位调用方，续查时沿三个改名参数核对子程序的公式及适用条件。分页定位不会将文件记为已完成全量公式评审。
- 独立建立 10,001 个定长小程序。`REMITKEY` 只出现在 `member09999.cbl` 第 4 行的较长代码中。在同一已建资料库中，旧本地检索两次都找不到该条件，新检索两次都找到并只对命中的一个文件校验内容。在相同快照上导出旧、新两套在线材料；新版使用 191,319 字节的本机材料读取得到唯一位置，只打开一个源文件。新程序读取旧材料也在这个样本找到同一行。该规模样本每份源码很短，不代表公司源码体量或网络耗时。逐项记录见 `large-snapshot.json`。
- 单文件有 8,192 个命中时，取前 8 页的 160 个行号，以前解码原件 8 次，现在解码 1 次，返回相同位置。每次查询仍验证传入的源文件。详见 `dense-locations.json`。
