## 原始问题与检查依据

**Q1 原文：**

> fee.cbl 的手续费如何计算？请按执行顺序说明基础公式、ROUNDED 舍入、最低/最高收费和 REVIEW 的后续覆盖；本金为 100、500、2000，费率均为 1.25% 时各收多少？再说明本金 201.20 的舍入结果。

应说明先按本金乘以 1.25 再除以 100，按接收字段的两位小数舍入，随后执行最低 2、最高 15，最后由 REVIEW 分支覆盖为 0。非 REVIEW 时，四组结果分别为 2.00、6.25、15.00、2.52；REVIEW 时最终均为 0。数值采用 Decimal 复算，前提和源码位置见 [预期结果](oracle.json)。这不是 COBOL 编译执行结果。

**Q2 原文：**

> ENTRY-RULE 在什么条件下调用 FEE-RULE？请说明三个参数怎样传入、手续费怎样返回；不是 STANDARD 时，FINAL-FEE 会怎样变化？

应说明 CALL 受 `REQUEST-KIND = 'STANDARD'` 控制，三个实参按 `BASE-AMOUNT`、`FINAL-FEE`、`REQUEST-STATE` 的顺序按引用传入，第二个 LINKAGE 字段的写入回到调用方。非 STANDARD 路径跳过调用并保持原值；声明初值为 0 不等于每次激活都归零。夹具在条件与 CALL 之间放置了 300 行无句点的 CONTINUE，用于检查远距离控制范围。逐行解释 CONTINUE、额外提供初值算例不属于原题必答项，但回答主动给出的解释也不能被核验错误改写。

用户质疑的关键成立：**解析器没有识别或证明某句话，不能据此断言源码不支持它。** 修补由早期“有效引用但找不到同目标事实时保留原文”，进一步收敛为“尚未证明只记入账本，不据此替换正文”。后续发现的裸常量等式、链式代入等式和合法 `END-COMPUTE` 结束符问题，分别属于操作角色和语法完整性的边界；不能靠截取半段等式，把状态或推导误判为源码赋值冲突。明确冲突、引用真实性及最终值的控制与覆盖分析仍须分别处理；有限核验器不因此获得证明任意业务语义的能力。
