基线为 `5f321d4e453b62a4c74937f7f025adadb3b4f0ba`。以下样本全部使用合成业务程序，问答由受控模型驱动。实际检查的是送给模型的源码、上下文与可回读路径。

本地样本在一个文件中显示业务标签，在另一个文件中使用包含该标签的代码作为扣减条件。单行 `IF`、将比较值移到次行、将第二项放在 `AND` 续行，三组测试的业务逻辑相同。旧版在后两组的所有模型请求中都漏掉了条件和扣减原文。修复范围限于已引入的本地字面检索证据排序。提高页数或重建词索引无法区分同为命中的屏幕文字与跨行条件。数据见 `local-before.json`。

在线样本在同一固定版本上保存两段约 11 KB 的长答，前缀相同，最后分别讨论两个不同的金额字段。下一条新问题均询问刚才最后一项的适用条件。旧版发给模型的上下文完全相同，同时还能从持久化记录中读到不同的原始回答。这证明跨题指代在制作下一轮请求时丢失。数据见 `online-before.json`。

修复后的三组本地问答均在首次模型请求中提供了真实条件与扣减语句。另用默认检索页大小将分界移到 `IF` 与条件值之间、或条件值与扣减动作之间。两种情况下都有来自同一源码版本的完整证据。跨页显示操作数、固定格式第 7 列的注释和字符串里的动作词都有反例。对照见 `local-after.json`、`page-boundary-before.json` 与 `page-boundary-after.json`。

在线新问题首轮可分别看到上一条长答的开头和结尾，按字符位置分页可还原中段。进入当前对话历史目录还可按需回到初始窗口之外的消息；内容和定位线索仍须在本题核对固定提交原件才能引用。两段对照中的对应末项均能在第一次请求的末段预览中找到，见 `online-after.json`。原探针另试的 `read_draft` 是同题续查操作，新问题使用本次新增的 `read_history`。
