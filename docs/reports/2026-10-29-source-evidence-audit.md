# 源码证据链与回答恢复审查（2026-10-29）

本轮发现的主要风险是：配置、词法边界或恢复日志失真，会让分析漏掉真实规则，或把未经证明的内容当成确定事实。修复围绕这条证据链展开；索引成功仍不能等同于业务回答已经完整。

## 已复现并修复

| 环节 | 原问题及影响 | 修复与回归依据 |
| --- | --- | --- |
| 编译配置 | `conditions_complete: "false"` 被当成真，把未知编译分支判断为关闭；字符串形式的 COPY 库列表被逐字符拆开。 | 严格校验布尔开关、列表和编译条件，配置集合固定为不可变值。真实 `CompilationGuardState` 回归验证未知分支仍保持未知。 |
| 模型配置 | 超时覆盖发生在验证之后，`0`、`301` 等非法值仍能返回；`True` 被当成 1 秒。 | 覆盖值通过统一配置验证，拒绝布尔超时。 |
| 索引质量 | SQL 字符串、注释和宿主变量中的 `END-EXEC` 误终止语句，漏掉字段写入；`EXEC` 与 `SQL` 分行会漏索引。结构索引还可能把 SQL 注释中的程序头当作真实恢复边界。 | 逐行保留 SQL 词法状态，以完整标识符边界识别终止符；保留换行、屏蔽注释和字面量后识别宿主读写。规则超过缓冲上限仍继续维护词法边界，并标记为部分解析。 |
| 框架解释 | SQL 内的假调用、假程序头可能生成框架事实；源码缺行隐藏 `REPLACE` 后，后续调用仍被误标为依赖已覆盖。 | SQL 及其尾随跨行注释保持隔离，合法后续调用仍可识别；缺行范围保留不完整状态，不能确认操作语义。 |
| 回答与质量回溯 | 中断重放保存了第一个候选的完成状态，而不是实际选中候选；完整与截断可能互换，拒答或空答失败原因也会丢失。 | 保存选中候选的完成状态和固定拒答标记。空 `stop/length` 仅在原响应满足条件且预算允许时恢复；过滤、歧义、工具响应和解析错误保留分类，不伪造正文或额外重发。 |
| 索引升级 | 本轮提升解析器版本后，既有升级白名单仍以 v1.9 为目标，完整回归发现旧库不能自动升级。 | 明确允许 v1.7/v1.8/v1.9 到 v1.10 的本地升级，验证读取配置保留、升级完成后不重复执行；未知版本和不完整源码范围仍拒绝自动重建。 |

## 验证

最终验证：4,349 项 Python 主测试全部通过，零失败、零跳过；262 项网页测试和 1 项工具测试通过。四组 Python 报告的发现清单、测试文件哈希一致，实际执行 ID 的并集与全部发现 ID 完全一致，且每项只执行一次；测试文件哈希已与最终工作区复核。结果及本轮源码指纹保存在 [源码回归摘要](2026-10-29-source-evidence-regressions.json)。

测试使用原创夹具、固定公开源码和本机模拟接口，没有调用真实模型，没有构建应用、安装包或 release。最初受限环境禁止监听回环端口，因此该批 HTTP/TLS 环境失败不计为通过；最终完整测试在允许本机回环连接的环境运行。验证平台为 macOS，不能替代 Windows 最终 EXE 的同包验收。

固定公开语料使用本机已有目录 `/private/tmp/qa-public-source-20261028`，8 个参与文件均与 `docs/eval/public-business-v1/manifest.json` 的 SHA-256 一致。通过 `PUBLIC_BUSINESS_SOURCE_ROOT` 配置该目录，原先因缺少环境变量而跳过的测试进入最终完整回归；没有下载或外传源码。

## 对完整性和效率的判断

必须分别判断文件是否进入索引、原文是否实际送达模型、回答所需的依赖证据是否完整。当前完整工作集的 `physical_complete` 只描述候选文件范围；`closure_complete` 另行描述依赖闭包，二者都不证明真实运行或全部业务语义。默认检索回答也明确保留 `full_repository_semantics_verified=false`。

本轮修复消除了已复现的漏索引和伪事实来源，但没有把默认检索变成每题全库通读。新增源码仍需显式更新索引；动态调用、闭源实现、运行值和不支持的语义继续是具体边界。只有对当前问题逐项核对实际源码及未决义务，才能判断答案覆盖到了哪里。

效率方面保持逐行扫描和有界规则缓冲，避免为修复词法边界反复扫描整个累计 SQL；恢复复用已收到的响应和已读证据。源码测试可以验证预算与缓存行为，不能据此声称真实模型回答更快或业务质量已完成实机验收。
