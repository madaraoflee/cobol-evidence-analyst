# 完整业务回答的独立审查

当前改动补的是此前漏掉的业务散文审查，不是更换编排框架。旧流程可以识别少数源码矛盾，但归档的 B2 结算回答仍会把显示语句写成日志、推定文件类型、排除其他入口，并原样交付。该失败原件及原评分保持不变。

本次在 PR #11 的隔离分支整合主分支 `a82ac474e9708a18dab00acc2e078716aed61c07`，保留另一边已经提交的业务边界、慢速本地分析和桌面升级恢复改动。没有编辑主工作区，没有执行应用或安装包构建，没有合并 PR 或发布。

## 行为变化

详细回答达到 600 字符，或带实际框架引用且达到 300 字符时，增加一次独立审稿请求。短事实回答仍走原有直接交付路径。审稿使用同一个已配置模型、独立上下文，提供原问题、完整答案的全部分段及其 SHA、答案实际见过的源码与手册全文节录、版本、行范围和 COPY 实例；不带聊天历史或索引摘要作为事实。

每段必须恰好评一次，区分有支持、证据不足、与原文冲突或不含断言；审查也检查原文能支持、当前问题确实需要的业务因果解释是否遗漏。不是因为出现变量名就判错，也不要求正确首答仅为文风而重写。结构、全文覆盖、版本绑定和逐字引文都由本地校验。假 ID、旧答案摘要、错位引文、漏段、重复段、额外键或把所有段都标成非断言，均不能获得完成状态。

审稿有具体问题时最多改写一次，再审查新正文一次。初稿无问题则原样保留，不制造内容变化。所有请求继续共用原有总请求上限，改写计入已有修订额度；修订额度为零仍可审稿，但不会改写。请求过大时不裁掉待审答案或证据后假装完整审核；审查未完成、仍有问题、无复审额度或最终本地处理改变了已审正文，都保留可读答案及明确的 PARTIAL 状态。

审稿 JSON 从增量和完成两条预览路径都隔离。核对期间保留真实首稿；改写时显示新正文的真实增量。阶段和可读草稿在进度通知、请求发送前保存，收到但未处理的审稿或修订响应可以按原阶段恢复；远端结果未知仍禁止自动重发。

修订进展还改为按具体断言及来源版本追踪：两处同类问题修好一处，不再误判为完全没有进展；把错误从一个程序转移到另一个程序，也不能因为类别相同而通过。最低 32768 字节请求下先压缩重复说明和调查导航，再考虑缩减原文，保留原问题和真实来源。

## 证据范围与后续验收

本轮源码验收使用离线脚本响应和受控原生 SSE。它验证供证、协议、状态、恢复与交付，不代表真实模型理解能力已经提高。完整回归统计与文件摘要记录在同目录的验证报告中；此前整合中失败的检查也保留。原 B2 失败正文进入新通用审查的测试没有把原评分或正确答案送给模型，也没有改写历史失败记录。

`model_reviewed` 只表示模型已返回结构有效的审稿意见。一个真实引文仍可能被模型误读；本地校验不能证明其语义支持结论，`semantic_verification` 和 `claims_semantically_verified` 始终为 false。这是同模型的另一次审查，不是第二个独立模型，更不是人工验收。新增阶段会增加最终答案等待，不能把提前展示草稿等同于最终答案加速。

设计参考 [Ragas Faithfulness 的断言及上下文判断](https://github.com/vibrantlabsai/ragas/blob/main/src/ragas/metrics/_faithfulness.py)与 [LlamaIndex 的答案上下文评估](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/evaluation/faithfulness.py)。本次没有引入它们的依赖或复制实现；采用覆盖全文的有界分段、精确供证绑定和明确的未完成状态。平均评分或单个 YES 不能代替关键业务结论逐项验收。
