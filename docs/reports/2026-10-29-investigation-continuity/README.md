# 自动调查、补查历史与自定义回答要求修复

本次修复针对实际执行链路，并保留上次 Bitbucket 接入反馈修复。应用版本标识为 `question-evidence-v59` / `business-chat-v50`；没有新增要求回答必须套模板才能显示的产品门槛。

## 已复现的原因

- 旧默认60秒交付目标扣除45秒正文预留后，约15秒便停止可选调查。真实索引配合模拟时钟表明：首答耗时20秒或上下文耗时16秒时，只调用一次并交付未完整答案；移除默认软目标后自动第二次补完。6轮调查、8次请求与无进展停止保留，完整答案仍可一轮结束。明确保存的时间限制不自动改写。
- 手动补查完成后，同一助手消息直接覆盖旧正文。现在使用独立修订表保存补查前的原文、来源、引用和调查编号；刷新、历史重开及导出均保留，模型历史只使用当前版本。失败或相同正文与来源不重复生成修订。
- 旧答案因长度截断后再修改回答要求，手动继续曾复用旧请求中的提示词，诊断却记录新提示词散列。现在新发起的继续使用当前保存的要求，清空也生效；原请求的断线恢复仍保留原请求语义。
- 模型按自定义要求返回单段英文后，本地事实补齐曾追加固定中文技术段落。现在自定义格式下保留原正文，遗漏事实作为同版本源码候选供已有复核流程整合，不自行增加模型调用；明确事实错误仍可纠正。
- 同一句提到调用方计算和空段落调用时，旧检查曾把计算误归给空段落并删除整句。现在要求明确的主语与直接谓语，同名多实现不冒称已确定归属；准确的调用方解释保留，明确误说空段落执行计算的反例仍会修正。

## 验证范围

`default-one-round-diagnosis.json`、`prompt-continuation-before.json` / `after.json`、`prompt-postprocessing-diagnosis.json` 与 `noop-attribution.json` 保留原因对照。单段英文、紧凑请求、提示词修改和清空、重启恢复、同名程序、中文连续书写及旧引用授权均有自动回归。

长源码测试 `test_collection_flow_delivery.py` 实际建立6037行、约21万字符的中性程序索引，四个扣减段落分散在远处。测试检查实际请求供应主流程顺序、每项条件、算式和初值，再让模拟接口首答等待20秒后返回“需要完整段落”；现有复核自动第二次完成解释。模拟答案不代表真实模型业务准确率。

`browser-before.json` 记录22项旧行为复现；`browser/report.json` 的41项真实Chrome检查覆盖原文展开、失败与取消、刷新历史、旧引用、两种语言和明暗主题、390px窄屏。浏览器检查期间五个服务代码文件散列一致。

`source-http-continuity.json` 使用真实桌面HTTP入口与本机TLS模拟接口，共6次模拟请求、12项检查：默认策略下真实等待20秒后自动补查；普通补查和截断续写分别修改提示词并重启；新旧答案主消息编号、版本、引用原文和原调查编号均核对。报告明确标为源码预览，不冒充最终EXE验收。
