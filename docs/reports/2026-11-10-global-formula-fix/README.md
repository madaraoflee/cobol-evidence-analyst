# 全库公式调查、累计交付与恢复修复

用户在四项具体诊断后明确要求“找到缺陷你要帮我修复啊”。本轮据此实施已说明的本地范围、公式批次与最终完成检查例外，同时修改独立在线调查；没有把本地冻结当作不修已授权缺陷的理由，也没有借此重构无关本地功能。

## 实现范围

显式全系统公式问题现在以固定索引快照中已纳入的源码建立清点目录，不再把英文关键词命中及其调用闭包当成全部范围。旧的单文件历史限制会被当前明确全库要求解除；当前问题明确限定程序或文件时仍保持局部范围。每个物理算术位置和原文窗口都有核对义务，不能仅凭文件名、段落名或缩写猜业务含义。

本地按持久批次推进，累计保留每项业务解释、公式、适用条件和来源；已经接受的结果退出当前源码窗口后仍留在最终清单。目录只在固定快照首次创建，继续时复用。最后的来源审稿也分批保存进展，不将原有审稿上限扩大或跳过。审稿发现原先公式写错时，可按候选编号和来源纠正，保留旧记录历史，重新检查后再交付；防遗漏检查不强迫保留错误公式。

在线增加固定版本文件分页清点及算术候选入口。未翻完的搜索、未核对的位置、原文覆盖和累计业务发现有独立台账，不能被模型的空 remaining 或最近观察窗口清掉。模型提前宣布完成时保留草稿和已确认发现，继续实际待办。已总结原文可转为带提交、位置和哈希的归档记录，按需重读校验；未总结的原文与全部未完工作不因此被丢弃。

最终累计清单仍需检查全部引用、保存的回答要求和实际业务内容。来源完整、位置完整、业务分类正确、运行时完整性是不同结论；本次没有把其中一项冒充其他项。

## 独立验收

独立编写的中性金标含18个文件、12个独立入口和14个业务公式位置，包括中文业务标签、改名调用参数、COPY、logical view、相同公式在不同物理位置，以及无关计数器和单纯搬运负例。验收比较真实供应的原文、保留的业务发现和用户最终看见的正文；仅返回“完成”或只保存位置目录不能通过。

本地正例实际跨批次、跨上下文整理和显式继续交付全部金标位置；最早的公式退出分析请求的当前原文窗口后仍在最终答案。另有70公式正例验证分析与最终审稿均可续跑。在线正例跨观察窗口并保留全部金标位置及已验证的CALL/COPY/LV来源关联。所有模型输出均为注入的测试控制输入，不能据此声称真实模型已具备相同业务判断质量。

独立验收详情见 `acceptance-handoff.json` 和 `independent-acceptance-final.log`；本地相关回归见 `LOCAL-FIX-HANDOFF.json` 和 `fix-targeted-regressions.json`。开发期间所有失败证据保留，旧测试断言不作降低。

## 万文件容量补查

用户补充实际仓库超过10,000文件后，本轮将10,001个独立程序、20,002个原文与公式核对项加入规模验证。中性源码和独立金标由单独测试生成器创建；预期清单不用于生成调查响应。索引、文件分页、恢复、实际业务清单与最终导出分别核对物理位置、原文哈希、业务内容和首中末位置，不能仅比较总数。

扩展验证确认了旧单对象容量的实际障碍：在线目录加候选在分析结束前便超过4MiB检查点；本地累计来源编号可以触发压缩容量上限；万项最终内容会被历史和展示投影截断。仅缩短回答或调大模型上下文不能修复这些数据通路。

显式全库调查现在使用独立、带版本的SQLite归档。目录、累计业务发现、待办、原文定位和逐批叙述保留在归档中；模型请求只供应当前调查窗口，检查点保存恢复引用。已发布的结果引用固定在当时版本，继续调查或从旧答案分支都不能改写旧结果。模型请求结果未知时仍保留原来的人工确认门禁，不因新存储自动重发。

界面按页读取已保存的清单，可直接跳到末页；每条仍可查看已验证来源，并可完整导出所有内容。线上长正文的聊天预览另有完整说明入口。翻页、查看保存的全文及导出均不会触发模型调用。历史只保存结果描述，避免打开对话时同时载入所有历史大清单。普通问题不创建全库清单存储，也不扩大为全库调查。

这些是存储、覆盖与恢复的离线验证。注入模型响应的耗时不能估算公司API实际耗时和费用；文件数量也不能单独代表复杂CALL、参数绑定和logical view链路的难度。实际业务解释质量继续保留现场验收边界。
