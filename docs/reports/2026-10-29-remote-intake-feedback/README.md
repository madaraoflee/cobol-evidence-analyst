# Bitbucket 接入结果消失修复

“进度闪一下就消失”不能视为导入成功。已复现的界面缺陷是：远端任务失败或取消后恢复旧资料库，却又因旧源码可用而跳回工作台；顶部通知被隐藏，唯一错误排在全部旧聊天记录之后。真实 Chrome 中，24 条旧消息后的错误位于约 11,292 像素，1,000 像素高的当前窗口完全看不到。基线为 `8870217`，应用与上一候选 `6cc18a9` 一致。

失败、取消和成功现在都会留下独立结果卡，并将焦点和滚动位置移到固定顶栏下。保留旧资料库和对话时不再强制跳页；首次下载成功也明确显示结果，缓存复用继续说明没有重新下载。进度或请求响应丢失时标为结果未确认，不自动再次提交。表单新增说明：公开仓库可只填链接，私有仓库需要应用自己的授权，浏览器登录不会自动传给应用；没有增加凭据必填或新的回答校验。

刷新后可恢复失败或取消结果；当原表单操作上下文已不在时，不猜测连接或更新意图，而引导重新选择接入或检查更新。刷新前重试仍使用原 `/update`，不会误走 `/remote` 打开缓存后冒称更新成功。成功重新使用可用本地缓存后，旧索引失败或取消任务不会在刷新时复活；问题任务和正在运行的任务不受影响。

## 验证

最终冻结文件的本机完整回归：4,135 项 Python、256 项前端测试全部通过，零失败、零跳过。源码散列和完整用例结果随本目录保存。

实际 Chrome、本机 HTTP、真实索引及持久化验证分两组：`browser/report.json` 的49项主矩阵覆盖长对话、源码页、历史页、鉴权失败、POST拒绝、取消、首次成功、同步缓存、刷新、两种语言、明暗主题、390px窄屏和失联未知结果；最终刷新重试修复另由 `retry/report.json` 的20项检查验证更新端点、无隐式新请求、无重复下载、结果卡及凭据清除。两组均通过；各自运行期间服务的10个前端资源散列不变。`before/report.json` 记录15项基线复现检查及修复前截图，不代表旧版产品通过验收。

远端下载和鉴权响应使用中性受控样本，不访问企业仓库或调用模型。鉴权失败样本证明反馈缺陷，并不证明用户当时服务端返回了哪一种错误。用户只提供链接时，私有库缺少授权是待确认原因；401/403、隐藏无权限仓库的404、网络或证书错误应以实际结果卡为准。官方认证说明见[Bitbucket API token](https://support.atlassian.com/bitbucket-cloud/docs/using-api-tokens/)。
