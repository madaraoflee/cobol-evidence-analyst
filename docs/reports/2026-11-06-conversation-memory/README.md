# 对话记忆与恢复修复（2026-11-06）

本轮确认仍存在会表现为“失忆”的缺陷：对话已经保存，但后续模型请求没有正确取得前文要求或源码；另有恢复后的显示顺序和资料库状态问题。本轮修复这些可复现路径，不将有限离线测试解释为所有业务问题的质量保证。此前中文紧贴文件名、启动检查和关系图预览修复继续保留。

## 修复范围

回答已经将调查焦点从入口程序推进到下游程序时，普通追问曾被更早的用户问题拉回入口。现在只让最近回答之后的新指令覆盖已确认焦点。指定字段并要求“沿用刚才的格式”等表达也会保留前答；独立源码提问则先排除不需要的助手长文，再分配历史预算，避免长答案占完额度后又被丢弃，连带挤掉用户的早期约定。

历史读取改为分别取出必要的源码引用和导航字段，不再因为整个诊断记录超过 64KB 而一起丢弃小型引用。177KB 长程序的回归直接检查下一次实际模型请求：加入 192KB 诊断后，末尾关键 DISPLAY 仍然存在；切回旧投影会丢失该语句。正常 24 文件影响查询也检查了保存后的引用恢复。上下文仍有条数和字符预算，不承诺无限记忆。

取消旧问题、完成新问题后再重试旧问题，迟到答案现在排列在所属问题之后；重开和后续重试使用相同顺序。新历史投影同时保留旧身份匹配路径，旧调查继续使用原源码记忆身份。旧版部分回答缺少保存的入口或调查编号时，只从同一问题、资料库、快照和调查记录恢复，防止续查失败或误接另一项调查。未知的远端请求结果仍不能自动重发，语言切换也不会复用另一语言的草稿。

空白新对话不再抢占最近有效历史的名额，达到历史展示上限时明确提示仍有较早记录。失败索引升级的尝试标记改为按资料库保存，切换另一资料库再返回、重开后不会再次自动执行相同失败升级。

业务问题在同一本机服务会话中使用固定提交标识。页面没收到受理回执时，查询原任务；重复到达的同一提交不会再次调用模型。请求内容改变、结果未知或服务已重启时不会自动作为新题重发。跨资料库恢复同时刷新所属资料库和对话；恢复时没有有效资料库会清除旧画面，恢复查询失败仍保留核对入口。

调查管线升为 `question-evidence-v70`，提示版本和原79样本验收合同不变。桌面与办公验收工作流保持仅手动触发。

## 验证与交付边界

本机完整 **4,665 项 Python、283 项网页及 1 项工具测试全部通过**，无失败、无跳过。四组发现清单与源码哈希一致，执行 ID 并集恰好覆盖全部发现项，最终测试文件哈希复核通过，见[源码验证摘要](source-regressions.json)。测试仅使用原创／固定公开源码和本机合成接口，零外部模型请求。

最终包补充检查增加重开后的下游源码追问、格式指代以及提交回执重复查询，要求实际请求保留同版本源码、原回答、引用与调查记录；同一提交只产生一次任务。它们与已有补充检查共32项、21次本机合成请求，仍须在 Windows 最终 EXE 上执行并核对包身份后交付。
