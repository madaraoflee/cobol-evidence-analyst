# 交互问答延迟修复

本轮修复针对已复现的失控路径：密集字段布局产生平方规模的数据、请求裁剪反复重编码、升级后提问隐性重建全库，以及不覆盖连接阶段的网络期限。默认路径仍为 `indexed_chat → business_chat`，使用原有 SQLite 检索、源码版本捕获、COBOL 语义服务和 ClaimLedger。没有接入第二套 Agent 或新的数据库。

比较基线是已发布的 `b8b63899080e2fe52f18c24159da21254b5f11c0`，没有回退到最初审阅版本。现场问题原文、库规模及接口耗时尚未取得，因此以下是已复现机制，不宣称现场只有这些原因。

## 根因与实测

| 场景 | 原行为 | 修改后 |
| --- | --- | --- |
| 一个组项下的 2,000 个字段 | 普通兄弟字段两两标为重叠；50,180 bytes 源码产生 162,314,255 bytes IR | 父子包含与直接重定义边分开保存，覆盖查询按需展开；IR 为 2,328,302 bytes，真正别名及未知覆盖仍保守处理 |
| 同一布局的解析、序列化与哈希 | 1.7089 秒 | 0.1214 秒；同一源码哈希，绑定及 `* 2` 表达式一致 |
| 同布局的默认问答准备 | 首次 3.2410 秒、重复 0.5679 秒 | 首次 0.5326 秒、重复 0.1427 秒；实际供应原文均为 50,179 字符 |
| 5,000 条导航关系裁剪至请求预算 | 每删除一条都重新编码整个请求，44.674 秒 | 分段二分查找保留前缀，约 0.075 秒；相同 144 条关系、32,654 bytes 请求和完整源码证据 |
| 旧解析器或编译配置的现存索引 | 提问退回导入路径，可能等完整源码库重建 | 明确提示更新源码；本次提问零扫描、零模型请求，旧 SQLite 与历史保持不变 |
| 连接或 HTTP headers 长期阻塞 | 正文读取期限不能及时中断连接阶段 | 原生请求整体期限覆盖连接和正文；等待中支持取消，有界后台连接不被误称远程已取消 |

10,000 字段的新布局 IR 为约 11.6 MB，解析、序列化与哈希约 0.61 秒；没有运行旧实现的超大平方展开来冒险耗尽内存。密集记录的原始对照保存在 [布局结果](2026-10-14-semantic-layout-scale.json)。时间是本机离线测量，不是办公室电脑或真实模型响应承诺。

另建 12,024 文件、2,712,992 行、59,039,908 bytes 的中性合成库，含 25,000 行长程序和 156,000 条已解析静态关系。相同问题、相同离线 transport 的首轮对照中，旧版首次准备为 7.318 / 4.200 / 3.177 秒，新版为 7.042 / 4.186 / 2.524 秒；重复运行有明显抖动，**未证明普通万级库整体稳定加速**。答案中的两项结构化公式/条件检查通过，独立未知说明保持未核验，供应源码哈希与原文范围检查均无错误。详见 [完整对照](2026-10-14-workbench-scale-latency.json)。

完成恢复边界、未知布局闭包和会话身份修正后，最终冻结代码另跑 9 次默认工作台完整离线链，前后非测试 Python 实现指纹均为 `9261d3d8e53af8b48a36cead932457b8a6e2ed15cc88d8228ea36c2183453fa1`：首请求 2.426–6.467 秒，包含假模型及最终核验的完整链 4.078–7.978 秒。9/9 保留答案，每次两项公式与条件获得支持，引用版本及实际源码节录核对均通过；独立未知说明保持未核验。旧版基线与中间版本测量保留在 JSON 中，没有覆盖。该时间排除了真实模型成本，不能用于承诺用户完整回答延迟。

## 默认行为与质量保护

未知布局沿父组、子项、数组和显式重定义传播到保守闭包，覆盖查询与字段服务采用同一规则；无法限定覆盖范围时保留全局影响。回归确认未知子项的写入可以到达另一个根字段的读取，同时保留直接赋值事实。普通已解析兄弟字段仍保持独立，IR 不展开平方规模的重叠列表。取消中断不会缓存未完成的程序，语义服务版本进入流缓存身份。

整题交互调查默认共用 120 秒墙钟预算，单请求使用接口配置与剩余时间的较小值；原有首轮 3 秒、本地深分析 15 秒和最多 5 次模型请求仍分别约束成本。接口超时上限不是预测耗时，合法的 120/300 秒接口配置不会禁用首轮检索。观察到的请求耗时决定何时保留最后的合成窗口；已取得足够内容时不再做临近截止的可选修订。

截止不跳过结论核验。已收到并持久化的答案继续经过 ClaimLedger，故“真实 `* 2`、模型 `* 999`、真实证据 ID”的反例仍能修正。源码读取中截止会保存 frontier 和已完成步骤；响应已保存后中断可以重放，不再发出同一次模型请求。远程结果未知时，不因改动超时或预算配置就自动再次收费。

界面区分定位、读取、模型请求和答案核验，显示模型请求序号、等待时间及剩余调查预算。剩余预算不是完成时间预估。预算使用协作检查点；证据核验、清理和持久化仍需完成，不宣称操作系统级硬实时期限。

## 参考与使用

参考了 Zoekt 对搜索时间与显示数量预算的区分、aider 的预算内仓库地图、CodeQL 的起点/终点约束数据流，以及 LangGraph 对步骤期限和恢复状态的分离。[研究记录](2026-10-14-interactive-latency-reference.md) 列出官方文档和固定提交。本项目保留自己的 COBOL 前端、字段绑定、切片、框架约定和证据核验。

更新后直接打开现有工作区。若提示“已有源码索引需要更新”，主动执行一次“更新源码”，完成后再提问；兼容索引继续复用。不要把索引重建时间计入普通问答。预算停止后，点击原问题的“重试这个问题”或在同一会话原文重问，会复用原调查和待查动作；仅输入“继续调查”目前不会自动绑定失败轮次。不同会话的调查身份已隔离。遇到远程结果未知，先核对原请求状态，避免把重复请求当作恢复。

## 本地验收状态

冻结实现的完整 Python 回归 2,427 项通过，126.556 秒；网页端 166 项通过，4.940 秒。公开固定版本样例的六轮机制检查与此前版本一致：预期路径 6/6，原始 gold 范围完整轮次 5/6，沿用既有文件末尾标注说明后为 6/6，未改写 gold 或宣称真实模型准确率。

本机 HTTPS 模拟服务另验证了持续发送未结束 headers 时的取消、整题期限、重启后未知请求不重发，以及真实证据 ID 搭配错误 `* 999` 的默认出口修正。独立 `MOVE` 结论仍获支持，未支持的说明保持未核验。对应桌面编译产物还需用同一脚本重放；平台构建与交付验证单独记录，源码测试通过不等同于正式发布。

可复现的离线命令：

```sh
python3 poc/benchmark_semantic_layout.py --help
```

第二条是截获首请求的准备时间测量，不调用模型；各次探针独立建立调查身份，避免将真实请求的未知结果保护误判为缓存提速。真实公司模型正确性、首字及完整回答延迟尚未验收，没有产生收费调用或发送企业源码。
