# 同请求压缩验收修正

Windows 构建 [38621345002](https://github.com/madaraoflee/cobol-evidence-analyst/actions/runs/38621345002) 在源码测试阶段被拦截，没有生成 EXE：2,656 个测试运行 1,736.379 秒，1 项失败、2 项跳过。失败项把两个独立调查请求的总字节相减，得到 146,921 → 136,534，仅约 7.07%，未达到原 10% 门槛。此构建不能作为候选验收通过记录。

默认调查有本地时间预算。冷缓存、暖缓存和机器速度会影响预算内完成的供证步骤，所以两次独立调查不能先验视为同一份材料。本地只读复现中，将本地时钟放大 20 倍，冷、暖运行分别供应 11、16 个源码页，均准确记录 `local_analysis_budget_reached`；分别对同一个 canonical 请求无损编码，减少 17.65%、16.59%。普通 LF、CRLF 以及更大本地预算的机制复测均供应 28 页，减少 15.15%。没有取得失败运行的完整请求，不能宣称已经直接证实其具体材料差异，也不能把 CRLF 当作根因。

修正仅涉及测量合同：保留两次真实默认链的离线 transport 调用，每次使用该次实际 outer envelope，比较该次完整 canonical 与无损编码的请求字节，仍要求节省超过 10%。每次独立验证全部字段往返不变、真实请求 body 哈希、trace 字节、证据 ID、版本、行范围、包含链与完整源码节录；独立解码器覆盖导航、slice 和 tool-result 语句编码，另加 occurrence、guard、未知效果和查询计数回归。没有降低压缩目标、丢弃源码或义务，也没有改动产品压缩实现及问答预算。冷、暖性能与完整度仍由独立延迟回归及最终 EXE 验收检查。

本机相关验证：8 项压缩、8 项截止时间、2 项 trace 回归通过，两个 Actions 工作流的 actionlint 通过。Windows 全量源码测试的步骤超时从 30 分钟调至 45 分钟，以容纳已经实测的约 29 分钟执行；这只影响构建基础设施，产品的本地分析预算、单题截止和现场 p95 目标不变。必须重跑 Windows 全量测试、编译与最终 EXE 门禁，不能继承被拦截运行的通过状态。
