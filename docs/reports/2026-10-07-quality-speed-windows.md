# 业务回答质量、耗时与 Windows 验证记录（历史轮次）

最新修复、默认详细模式及 Windows 验证包见 [本轮交付记录](2026-10-07-detailed-business-correction.md)。以下保留较早轮次的原始判断与数据。

本轮修复了可以确定复现的结构事实遗漏和空回复处理缺口，但还不能称为业务回答质量的质跃，也没有实现全局提速。最终完整重跑的 30 个关键项通过 29 个，8 题核心答案通过 7 题；把附加正文中的实质错误也算进去，整篇答案通过 6 题。另计的保存场景仍失败。最终挑战题总耗时比基线增加 14.5%，虽然请求体积减少 7.6%、中位耗时下降 17.8%，这些变化不足以支持稳定提速的结论。

评估日期为 2026-10-07。本报告不披露私有模型名称、服务地址或业务源码。Windows x64 已完成[原生构建与自检](https://github.com/madaraoflee/cobol-evidence-analyst/actions/runs/37511714204)，交付 ZIP 已下载并在本地复核；办公室电脑的图形界面与真实接口操作尚未验收。

**已验证的工程改动及其边界。** 新增有界 token/statement AST 前端，识别受支持的 IF、ELSE、EVALUATE 顺序及赋值；保留原始行列范围，对未知结构、缺失上下文和不透明调用明确保留边界。结构索引仅保守接入完整、受支持的同行复合语句，修复旧逐行收集器遗漏分支和第二次写入的问题，不作全语法迁移。适配器保留中间句点，依据子节点范围和词边界识别显式终止符，避免字段名后缀被误认，以及嵌套结构复用同一终止符造成重复单元。消费端按来源列恢复同行语句与条件顺序。索引解析版本随之更新，使旧结构事实及相关语义缓存按版本失效，后续仍可复用缓存。

外部 GitHub 解析器的固定版本、许可、覆盖和耗时实测另见[解析器试验记录](../research/2026-10-07-external-parser-trial.md)。该试验未证明现成解析器可以直接替代业务语义层，因此本次产品没有引入未经 Windows 验证的原生语法库。

这些改动已有针对同行 IF 双写入、EVALUATE 顺序、句点、嵌套终止符、落库唯一性及实际错误路径消费者的回归依据；它们证明结构事实修复，不证明任意 COBOL 方言或模型业务解释正确。最终默认只在旧收集器确有同行漏识别风险的片段附加语法提示，普通多行题不重复加入完整 AST 派生上下文。完整提示仍可用于实验。最终提交的本地完整后端回归为 2,008 项通过，耗时 67.656 秒；此前 162 项前端测试通过，其后未修改前端。这些工程检查与上面的业务答案评分分开计算。

协议层增加一次有预算约束的空正文恢复，只处理明确的 `finish_reason=length` 空回复形态，保留两次请求的计量，不把拒答、过滤、鉴权错误、超时或歧义响应纳入重试。第二次仍空时停止，也不追加第三次续写。本报告生成时，相关 9 项离线回归全部通过；最终真实重跑未触发该恢复，故不能声称已在真实服务上复现并验证了恢复成功。

基线代码为 `35eed48`，最终完整模型重跑对应 `88cbd52`。其后的 `9c3bd61` 补充 Windows 回归环境、测试夹具的原始字节校验和数据库初始化失败时的连接释放；`d3671e3` 修复了资料同元数据快速改写时误用旧缓存的问题。后两次提交没有调整解析规则或问答提示，也没有据此新增模型质量得分；模型评估显式关闭框架资料输入。

**评估口径。** 每轮挑战集为同样的 5 组、8 题，包含 30 个关键项和 20 条禁止断言；另有 1 道 neutral 保存场景。对照每题 gold 和对应源码快照，全文检查主结论、正文附加陈述、前后矛盾和外部实现缺失时的证据边界。所有结果是代理审读，不是人工业务分析师验收，也没有执行 COBOL 来验证运行结果。题目属于开发集，已参与问题发现与实现验证，不是留出的盲测集。

`pass` 要求相关业务含义明确且不矛盾；`fail` 包含错误、缺答和禁止断言；复合项只回答一部分记为 `unclear`。严格逐题结果按“任一 fail 则失败，否则任一 unclear 则不明确”汇总。核心答案只评主问题，整体答案还计入附加正文中的实质错误。程序运行状态 `COMPLETED` 不代表答题正确。原始报告的 `human_review` 没有被代理复核填充。

下表所有三元数均为 **pass / unclear / fail**；neutral 不混入挑战集分母。基线复核未单独统计整体答案字段，不据后续口径补造一个通过率。

动态目标题虽然列对了配置查询状态和动态调用加载异常，却随后把“查询失败因而不发起调用”推广到全部失败，包含只有已经尝试调用才可能出现的加载异常。同一答案中的正确表格不能抵消核心解释的矛盾。这既是一个关键项失败，也是一个禁止断言失败。

复制参数题的正常返回结论和参数传递边界正确，但额外声称任意层调用异常都会使根层得到同一个状态，混淆了根层调用中层失败与中层调用叶子失败的不同状态。因此主问题通过，整篇答案失败。部分主动改码建议还存在调用方与被调用方传参模式是否同时改变的歧义，单独记录为不明确，没有将歧义夸大为已经证实的错误。

neutral 保存题三轮都越过了证据边界：调用方的赋值、SAVE 调用及返回状态检查不能证明外部存储实现确实同时持久化金额和状态，也不能证明提交语义或 RESTORE 内部刷新行为。最终回答承认外部实现缺失，却仍描述这些效果，因此不能验收。费率题和跨程序题的参数模式、闭区间及回写细节在最终轮更完整；校验题主结果正确，但仍留有一处截断半句与重复续写的展示瑕疵。

**所有尝试都保留。** 初始 candidate 的嵌套题消耗一次请求、输出预算达到 8192 后以 `length` 结束，没有可用业务正文，结果为 `NOT_READY`。该题按缺答失败，不能以代码测试通过、后续重跑成功或最终全套重跑覆盖首次失败。基线动态目标题虽然报告状态为 `COMPLETED`，最终正文仍在请求补读而没有回答关键状态区分，也按失败保留。两次独立 recheck 与最终全套重跑分别记录；它们不是初始报告的替换值。

本报告覆盖 20 份原始运行报告、29 次题目尝试：24 次挑战题、3 次 neutral、2 次 recheck。合计题目耗时 **1,063.922 秒**、**43 次模型请求**、**3,628,613 请求字节**。这是这些报告所记录的评估范围开销，不代表整个开发过程的 API 账单。两次 recheck 都在第一次响应得到正文，不能用来证明空正文自动恢复已经真实触发。

三轮不是随机交错的重复实验，模型输出、续写路径和服务响应都可能波动；实现与提示也在开发期间变化，因此不能把单题变化归因于 AST 提示，或从单次结果推导因果提升。本轮没有观察到因 `effects_unknown` 而明确拒答一个本可由完整源码判断的问题，但这也不是已经排除此风险的证据。当前可以确认的是确定性结构缺陷被修复，以及这组开发题的关键项完整度在最终轮提高；核心矛盾、附加事实错误和缺失实现处的过度断言仍是实际障碍。

**Windows：原生构建通过，办公室实机验收尚未完成。** 首轮真实 Windows 运行（37506743824）失败，暴露了测试文本哈希错误归一化换行、SQLite 连接未显式关闭、子进程编码和工作流全局配置污染等问题。修复提交为 `9c3bd61`；本地模拟 CRLF 的 254 项受影响回归，以及 3 项数据库失败生命周期回归通过。第二次真实 Windows 运行（37508505211）执行 2,005 项测试，仅剩 2 项失败、无 error，另有 2 项平台跳过。其一是剩余测试夹具的换行指纹，其二暴露真实的资料缓存版本问题：同长度快速改写可能保留相同元数据，旧缓存因而误判文件未变。`d3671e3` 将缓存复用移到有界原始字节读取和 SHA-256 校验之后，仍复用未变化内容的解析结果；对应 339 项框架资料回归和 258 项 CRLF 模拟回归通过。第三次 Windows 原生验证（37510309063）完成 2,008 项测试，耗时 442.581 秒，结果为 OK、2 项仅适用于 POSIX 的测试按既有条件跳过；随后源码浏览器入口自检因依赖准备顺序失败。`8231740` 修正工作流，让自检复用正式打包的隔离依赖，并把启动检查前置；第四次运行（37511714204）最终成功：Windows 完整回归执行 2,008 项、耗时 533.681 秒，结果为 OK、2 项既有 POSIX 条件跳过；隔离环境准备、源码浏览器自检、MSVC 原生编译、编译后二进制自检、最终 ZIP 校验和上传均通过。运行来自 PR head `8231740`，实际 checkout 为合并提交 `17c3dae71848566f8c03e5b90f3a9526e83bd86f`。

本地交付位于 `release/windows-x64/run-37511714204/COBOLWorkbench-windows-x64.zip`，大小 16,565,184 字节；旁边保留原始 `.sha256`、`BUILD-INFO.json` 和本地核验记录 `LOCAL-VERIFICATION.json`。ZIP 的 SHA-256 为 `c11685efbee80ef53a9b34a92a6b0bb2d265961d3107cfb1eb06b5169d328d8e`。本地复核通过 ZIP 完整性、包内外构建记录一致性、Windows x64 PE 标识（0x8664）及禁止文件扫描；包内没有 Python 源码、用户配置或本地数据库。构建运行时为 Python 3.13.15，接收者无需安装 Python。

编译后自检确认静态资源、本机 HTTP 服务、服务关闭、桌面依赖导入和 TLS 初始化成功，模型调用数为零。它没有打开实际桌面窗口、选择办公室源码或调用真实接口，不能据此宣称已通过办公室设备验收。解压后应保留完整目录，运行其中的 EXE；需要浏览器入口时使用外层 `OPEN-IN-BROWSER.bat`。

下一轮质量工作的优先级应是约束“答案说了什么”，而不只是继续增加上下文：把调用前阻断、已尝试调用后的异常和外部实现未知分别表达为可核查的断言；检查同一答案内的矛盾；对附加解释采用与主结论相同的证据要求。需要新建未参与调试的留出集，并由业务分析师盲审，保留首次失败和所有额外陈述。在固定配置、交错重复运行下共同衡量正确率、完整答案耗时与请求量，才有依据评价是否真正提高质量和效率。本轮不再针对这组题继续调提示。
