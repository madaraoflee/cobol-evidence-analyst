## 机制验证

本次解除上游同步依赖后，完整在线 Python 测试 **188 项通过**（7.871 秒），全部页面事件测试 **305 项通过**（5.445 秒）。此前网页相关 Python 回归 **103 项通过**（该次运行含 4 项在线 HTTP 测试，其余 99 项为既有回归；目前 5 项在线 HTTP 测试均纳入最终 188 项）。此前还验证既有业务稀疏索引 14 项和源码会话 12 项。计数有包含关系，不相加包装成不同业务案例数。最终代码摘要和验收状态见[验证清单](./verification.json)。主要命令如下：

```sh
python3 -m unittest discover -s poc/tests -p 'test_online*.py'
python3 -m unittest discover -s poc/tests -p 'test_*web*.py'
node --test poc/tests/*.test.cjs
python3 -m unittest discover -s poc/tests -p 'test_business_index.py'
python3 -m unittest discover -s poc/tests -p 'test_source_session.py'
```

HTTP 整链先生成资料，再删除源码目录和临时索引，通过真实本机 HTTP 执行接入、提问、CALL/COPY 补读、模拟模型答复、固定版本引用、导出、连续追问和重启。追问使用上一轮的路径线索重新核验原文；切换版本后旧对话仍对应旧 commit，失败更新不覆盖当前版本。在线 SQLite 只存独立元数据/历史/检查点，不是完整源码索引。基础测试还覆盖只读导出、事务一致性、跨机器路径复现、同内容复用、失效事实、长文件/长行、混合编码与物理行号、重定向/认证/限流、取消、路径安全和资源预算。

用户随后明确不掌握也无需了解同事的同步机器与脚本，因此新增显式仓库快照发布方式，记录固定提交和上游同步完整性未确认；旧同步凭据方式保持兼容。新增验证覆盖无同步凭据的 Git → 资料生成 → 模拟发布 → 删除源码后读取、两种格式兼容、错提交/脏工作区/未跟踪源码拒绝、重复发布复用及页面与重启后的来源状态。Pipeline 模板不再需要同步程序传入凭据，仍未启用。此次未重跑下方历史规模实验；其性能和字节数据仍对应实验时的凭据发布方式。决定见 [ADR-0019](../../adr/0019-index-repository-snapshots-independently-of-sync.md)。

独立审查发现并修复三项实质问题：资料地址变更不能自动继承原地址凭据；凭据保护不能改写带哈希的检查点/原文；最终 release 写入回执丢失时必须返回“发布结果待确认”，不能断言未发布。另补齐了多轮历史的源码定位线索与重新取证。

这些是源码级自动验证，没有运行全部本地 Python 测试或 Windows 设备验收。真实浏览器验收尝试被 Work 设置的“本机浏览器操作已禁用”阻止，未绕过该设置，也没有截图或点击验收通过的声明；临时合成服务已关闭。HTTP 测试的临时端口曾被默认沙箱拒绝，随后使用获准执行方式通过。没有构建应用、安装包、release、触发云端任务、访问真实 Bitbucket 仓库或调用真实模型。

## 基础资料历史对照：18 MiB

[脚本](./benchmark.py)只生成中性的合成源码，在临时目录执行静态索引与资料导出，然后删除源码和索引后查询。[历史结果 JSON](./benchmark-results.json)保留**优化前 v1** 的指纹、环境和计数，供下节对照；当前脚本若用新代码重跑，格式、体积和计数会变化。资源计数使用 POSIX `resource`，历史环境为 macOS arm64、Python 3.14.4、SQLite 3.53.2。

```sh
python3 docs/reports/2026-11-07-online-materials/benchmark.py --output docs/reports/2026-11-07-online-materials/benchmark-results.json
```

| 最大单文件 | 655,496 B，超过 512 KiB |

“读取次数”来自目录对象适配器，**不是已测的 HTTP 请求耗时**。这里的 2.835 / 7.593 秒是本机合成静态处理时间，不含云端 checkout、HTTP、上传、认证、排队或模型。语料含大量重复注释，不能将体积比例、峰值内存或速度外推到真实几 GB 源码。

查询 `ENTRY-0199` 返回目标程序和调用者；目标排名第 2。因为连字符拆词且使用任一词命中，`ENTRY` 让 2,000 个程序均成为词法候选，结果只返回前三项并明确 `truncated=true`。这是底层词法候选检索，不等于唯一程序解析。上层调查模型可以继续选择查找和补读，真实自然语言业务召回仍需公司模型验收；不能把三个返回文件当作完整业务范围。

历史测量发现 18,597 个 postings 小对象占大部分数量，随后实现了短 postings 内联和独立内容地址分包。
