# 多轮追问的主体与供证闭环

本轮修复默认工作台中“首问能定位，省略程序名后却失焦”的问题。实现基于 `main` 的 `1dfd1645e91e61c0935fd6eb9c7609ea09007b3b`，没有回退审阅版本。网页导入、已有索引追问仍走 `indexed_chat.py → business_chat.py`，没有增加第二条问答路径。

## 实现

新增 `conversation_focus.py`，将经本地索引绑定的程序、限定字段和用户明确排列的对象保存为 `conversation-subject/v1`。例如先问“第一种 PAGE-SUM、第二种 ACCOUNT-SUM”，再问“第二种呢”，本轮焦点是 ACCOUNT-SUM；之后问“它从哪里来”继续保持该字段。模型正文、引用出现顺序和检索结果排序都不能建立这种序号关系。

当前明确程序、路径及入口约束优先；当前未知字段、同名歧义和未建立的序号保留具体诊断，不回填成旧字段。只有字段名的首问可以通过唯一声明找到程序，同时保留原有定向语义分析。完整程序已经供应时，明确字段的追问仍执行已有 semantic sidecar，不把全文供证当作数据流分析。

同一主体的追问继续获得既有完整源码预算，并保留此前明确的“仅此文件”限制。切换到新程序后，旧主体不会变成永久范围约束。源码内容变化时重绑字段和哈希，原回答的归档节录仍保留原版本。

会话主体独立限制在 8 KB，从 SQLite 投影读取；即使整块诊断超过历史资料预算也能恢复。重试按原消息位置取历史。运行检查点保存当前检索词和焦点，恢复时重新校验；已持久完成的模型响应不会因此重新发送。最终主体随被接受的答案 manifest 保存，修订失败继续保留初答的主体与证据。

请求压缩保留关键字段指代，优先缩减已确定身份的重复导航信息。修订前比较实际能够供应的新材料；仅在本地读到新页、但发送预算仍将其全部省略时，不因此新增一次模型请求。

版本：`question-evidence-v12`、`business-chat-v17`、`business-analysis-plan/v3`。旧已完成调查保留归档；未完成调查不会静默跨管线版本续跑。

## 使用与交付状态

源码版沿用 `python3 poc/web_app.py` 或 Windows 的 `poc/run_web.bat`，导入源码后在同一会话追问即可，无需新开关或重建另一套索引。

本报告及验证 JSON 记录实现完成时的本地代码与离线验证状态，当时未调用真实公司模型、推送或重新生成发布包。后续发布的实际提交、Windows EXE、Mac 应用及构建自检结果统一见 [GitHub 最新发布](https://github.com/madaraoflee/cobol-evidence-analyst/releases/latest)，不覆盖这份历史验证记录。业务答案质量仍需在获准模型环境下测基线，再确定新的留出问题与准确性目标。
