# 业务解释、框架依据与正文流的真实模型验证

本轮验证使用真实 HTTP 模型和中性源码，评审最终交付正文，不把索引命中、局部状态或草稿出现当成业务正确。Windows 最终 EXE 的同包验收另行执行；这里的 Mac 源码结果不能代替目标办公设备和人工评分。

## 冻结范围

四题在首次请求前冻结，题目、13 项必需结论、禁止推断、物理行段和文件摘要见 [cases.json](phase1/cases.json)。普通新人问法查询余额、普通程序分析结算流程、普通 COPY 的操作约定，以及只改变 REDEFINES 布局的反例，各用新会话。金标准只留在评测端，不作为模型提示。中性夹具来自仓库已有测试，未发送企业源码或私有框架手册。

初始代码为 `52469d636103920371632429d56a78c6f62f4e09`。原始 [计划](phase1/plan.json) 绑定实际加载文件摘要、模型参数与预算；[归档清单](phase1/archive-manifest.json) 绑定保存的原件。模型请求使用现有获准配置，显式低推理、8192 输出上限，每题最多 3 次。全任务保守费用预留上限 2 元，按[官方峰值费率](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)计算输入字节上界与输出额度，发送前持久预留，失败不退回额度；这不是实际账单。

观测复用实际 `analyze_source → run_business_chat → UrllibTransport`，不替换流式实现、不拆分完整答案模拟播放。记录原生正文增量、生产进度接口快照及浏览器 DOM 变化；DOM 收到变化不等于测量物理屏幕绘制。浏览器只增加被动观测，不发送额外问题。隐藏推理、请求头和密钥不进入归档。

## 首测保留的结果

前三题均收到真实 SSE 正文，浏览器在响应结束前多次更新：B1 为 35 次，B2 为 47 次，F1 为 43 次。核对阶段实际发生，但三题首稿与最终正文相同，暴露出局部核验不能识别的语义问题，不能按系统的 ANALYZED 状态算通过。

- B1：业务用途已明确，仍无依据地断言查询不锁定，多行查询的分支解释还自相矛盾。
- B2：解释了结算记录生成规则，但把文件名当作 LF/PF 类型，作出过强的一一对应、无痕迹断言，三处引用使用内部规则编号。
- F1：操作请求与运行效果分开，也带上手册限制；却遗漏普通 COPY 独立存储、后续赋值为什么不覆盖操作码的解释。
- F2：TLS 握手失败，零模型正文；本地回退不是模型答案。该轮立即停止，未自动重发。

逐项独立代理评审及精确答案引句见 [首测汇总](phase1/run/agent-review-summary.json) 和同目录各题记录。它们不是人工验收评分，不换算总体准确率。首轮共 4 次物理请求，保守预留 `698792` 微元，包含失败请求；第二阶段只能使用余下 `1301208` 微元及最多 8 次物理请求。

## 首测引出的修复

交付约束明确要求：业务介绍围绕用途、数据流与决定性条件推进，声明清单只在解释当前行为时展开；查询语句不能证明无锁或具体数据库事件到状态码的映射；写出请求不能代替持久化成功；文件名不能证明 LF/PF；框架约定必须解释调用、布局和最后有效赋值怎样共同支持它。

本地新增有限的 SQL 边界提名，依据实际供应的完整语句和答案中的具体断言进入现有核对、修订、无进展停止及请求预算。它只提名高风险片段，不解释数据库实现，也不证明任意业务散文正确。内部规则编号不能充当用户可解析的引用；代码中的引用格式示例仍可正常说明。正确且有依据的首答不强制增加模型请求，预算不足仍保留局部未核实状态。

修复后完整离线回归为 **3557 项全部通过，零失败、错误和跳过**，用时 204.78 秒，固定公开语料已启用；121 个产品文件的测试前后摘要一致，439 个 Python 文件通过 3.10 语法解析。详见 [源码回归](source-regressions.json) 与 [独立审查](source-review.json)。记录中的 baseline_commit 是未提交修复所基于的 HEAD；实际测试内容由前后文件摘要绑定，不能解释成旧提交本身已经包含这些修复。页面代码未改，上一冻结版的 202 项浏览器回归仍适用于相同文件；Windows 工作流另会重新执行浏览器回归。

独立审查曾发现正确限定语误触发复核，以及多条 SQL 的风险报告挤掉源码。修复后的真实请求裁剪反例在 32768 字节限额下保留唯一原文及风险，100/200 条 SQL 的复核请求分别为 18779/25580 字节，没有裁剪；风险摘要有固定大小和引用数量上限。正常限定语不增加请求，修订也不能引入新的已识别风险。

第二阶段和 Windows 构建结果待冻结后另记，不覆盖首测。
