## 扣费题的源码答案

在样例将调用变量绑定到相应程序、参数按引用传递并正常返回的条件下，每笔保费按以下规则计算。

1. 入口先判断项目类型。等于 `1-RESERVECREDIT`，从当前应收 `NET-DUE` 减去 `CREDIT-AMT`。其他类型跳过这笔准备金扣减。
2. 随后独立判断当前应收。只有余额大于零才进入退款处理。余额为零或负数时直接保留该余额。跳过第一步准备金扣减的项目同样要判断余额。
3. 退款处理比较 `POOL-AMOUNT` 与传入的剩余应收。退款池金额严格小于剩余应收时，扣去池金额。相等或更大时，整笔跳过。

最终应收等于初始应收减去每一步实际扣除的金额。例子中初始 100，符合类型并扣去准备金 20 后为 80。退款池为 30 时结余 50。池金额为 80 时结余仍为 80。引用分别来自入口、转调和末级扣减，验证程序逐一打开所引行并核对原文和文件指纹。[原题与源程序](../../../poc/tests/local_grep_acceptance.py)

## 如何测量

浏览器每次新开普通问答，从实际点击发送开始计时。逐帧检查“已查实的结论”中首次出现的准备金条件、扣款字段和入口文件出处，再记录完整答复首次出现在对话中，两次均检查可见区域。另一次独立测量每 50 毫秒读取工作台进度、比对源码原文，并保留各轮模型实际收到哪些文件。页面显示时间与后台进度时间分别记录。

使用本机浏览器、Python 服务和独立临时设置。模型使用内存中的受控回复。它先返回一次“源码不足以分析”，随后根据已经收到的代码查找调用目标，读到末级后才给出扣费正文。未连接真实模型，未使用企业源码。样例按文件数量贴近现场，其程序长度分布、磁盘、企业网络和模型等待时间仍须实测。

用 [replay.py](replay.py) 选择独立的 `--workspace`，用 `--variant ordinary`、`dense` 或 `report` 选资料，先执行 `--mode index` 再执行 `--mode questions --runs 3`，每次用 `--result` 指定独立的 JSON 路径。浏览器计时使用 [browser_timing.py](browser_timing.py) 和 [页面观察脚本](browser_timing.cjs)，指定同一组 `--workspace`、已安装的 `--browser-executable` 和 `--result`，另需 Node 可加载 playwright-core。`--product-root` 可指向单独检出的修订，用于在同一份合成索引上比较版本。
