# Cloud、本地源码复用与首次业务提问修复

本轮按用户澄清复现“第一次提问就说没有源码”，没有把问题预设成多轮对话丢失。源码修复同时合并了获用户授权的流式回答、继续补查和业务索引 Markdown 检索任务；不构建应用、安装包或 Release。

## 原因和行为变化

- Cloud 地址过去被入口拒绝。现在支持 Cloud 仓库、目录和 HTTPS clone 地址，保留 Server / Data Center 接入；认证只在本次操作内使用。
- 已下载源码、索引和来源登记持久保存在本机。“打开本地副本”及重启不访问远端；相同来源重接复用本地副本。主动检查更新先比较提交，同提交不下载 ZIP；索引不可用时从本地源码重建。失败或取消恢复旧报告、索引与对话。新提交保存独立快照，旧对话继续属于旧版本。
- 固定提交链接仍代表固定版本；显式选择“跟随默认分支”才改为跟踪默认分支。Cloud 有变化时仍下载整仓 ZIP，再提取所选目录，这是持久缓存与版本检查，不是 Git 增量拉取。
- 首问检索流程没有把原文回退和成功的直接读取计为已取得源码，随后又清空请求页。已修复状态传播，并让模型已经请求且成功读到的原文留在后续分析中；没有提高该对照测试的请求额度。
- 带连字符的 `.cbl` 文件名被当成字段，导致已有完整公式仍被标成未定位。现在字段解析先遮蔽完整源码路径，原始问题仍用于文件定位；真正的未知字段仍保持未知。
- 语义导航中旧片段的引用编号和实际供应的完整页编号不一致。现在仅对同路径、同版本、完整覆盖且 COPY/替换实例相同的原文进行出站引用重绑定，保留原始记录和源码内容。
- 自定义回答要求进入实际 system 消息，并覆盖默认的格式、详略和语言要求。流式正文、接续正文、历史搜索，以及按文件名查找业务索引文档也纳入联合源码回归。

合并回归进一步覆盖了两类边界：首次建库取消保留已完成的结构索引，以便恢复时复用；既有库修复仍恢复旧数据。小请求额度下先减少重复协议、已完成动作和计划导航，再考虑原文裁剪，保持 32 KiB 上限；精简调查记录从本地完整记录取值，避免共享编码后丢失 `kind`、`status` 和 `reason`。

## 验证证据与界限

`large-repository-comparison.json` 和 `reproduce_first_question.py` 使用 12,202 个中性生成文件。基线只替换为提交 `4cdbab4665df4d2b6fcbf70b9dccf3f7a286474c` 的 `business_chat` 模块，其余共享依赖使用当前代码；两边均使用相同的显式请求/调查限制。直接读取和公式泛问场景在基线中丢失已读页面，修复后页面及引用进入下一次真实构造的请求。这里的模型传输是受控替身；两次请求的固定测试额度仍会如实记录 `PARTIAL / request_budget`，没有把它算成全库语义理解完成。

真实模型测试通过本机 HTTP 工作台调用已配置模型，仅发送上述中性源码，保存了失败和修复过程：

1. `initial-live.json`、`connection-retry-live.json`：两次 TLS 握手失败；自定义格式请求成功，但文件名误字段问题导致状态不完整。
2. `before-content-review-live.json`：检索、流式和三标题格式已完成，逐句复核仍发现默认零初值的无依据断言、导航旧引用，以及无条件推广可存储结果的问题。没有用 `ANALYZED` 状态代替内容验收。
3. `before-table-repair-live.json`：补测后初值、引用和数值例子已改善，但旧后处理把正确的 `> 0` 与源码 `> ZERO` 当成矛盾，损坏了表格条件。这份原始结果保留为失败证据；后续使用同一份真实返回文本离线重放验证本地修复，不把重放算成新模型调用。

未知初值的提示依据是适用环境未确定时不补造数值。例如官方 [WORKING-STORAGE / LOCAL-STORAGE 初始化说明](https://www.ibm.com/docs/en/cobol-zos/6.4.0?topic=data-comparison-working-storage-local-storage) 明确说明未指定 VALUE 的初值未定义。本项目没有根据文件类型猜定编译器，也没有添加阻断回答的新校验。

`ui-report.json` 记录最终冻结源码的真实本机 HTTP + Chrome 32 项检查，开始与结束的十一个关键文件散列一致。首次受控下载一次，两次显式更新检查只解析版本，缓存重开、重载和同 URL 接入没有重复下载；对话、草稿、凭据清除及明暗主题通过。远端响应是受控替身；这不是企业私有 Cloud 仓库认证验收。公开 Cloud API/ZIP 的读取验证也不能替代企业代理、证书和账号权限验证。

最终结果：4,129 项 Python 回归、250 项前端测试、32 项浏览器检查通过，无失败、无跳过；冻结源码在最终回归期间没有变化。完整结果见 [verification.json](./verification.json)、[Python 用例结果](./python-regressions.json)、[内容复核](./content-review.json)及[源码散列](./tested-source.json)。所有这些记录属于源码和本机测试，不代表最终 Windows EXE 或目标办公设备已经完成发布验收。
