# 候选发布后的持续排查

基于已发布候选的后继主线 `131f38b303ae47b74b5db1bb372bca572e52a8b6`，本轮再次复核配置、源码供应与回答审查，确认并修复五类问题。修复前均有可复现的失败用例；没有调用真实模型或发送私有源码。

| 问题 | 原行为与修复 |
| --- | --- |
| 配置并发保存 | 多实例共用固定 workspace.tmp，导致替换互相干扰和保存失败。改为同目录唯一临时文件，保留原子替换与失败回滚，清理失败残留。 |
| 历史证据截断标记丢失 | 归档忽略 span_truncated，网页又强制标完整，跨轮记忆修改/删除标记也可恢复。新归档保留该标记并单向合并已知截断；网页原样展示；记忆绑定、实际请求记录和归档三者同时核对。旧完整页标识和归档兼容。 |
| 异常 Unicode 审稿 | JSON 转义后的孤立代理码点通过校验，在保存审稿或恢复时引发 UnicodeEncodeError。现明确拒绝这种字符串，保留首稿且不重新发送已收到的请求；合法 emoji 保持支持。 |
| 默认回溯日志复制源码 | 独立审稿的 findings/omissions 在关闭 capture_context 时仍保存源码原句。默认日志改为哈希与长度，内存及恢复库保留恢复所需材料；显式开启采集仍保留原文。 |
| 同页多线索检索遗漏 | 两个独立线索位于同一索引页时，提前按物理页去重丢掉后一个裁剪路线。现保留独立路线，在总预算内分配裁剪额度；不放宽文件范围、总字符或页数预算，单线索行为保持。 |

调查 pipeline 升至 question-evidence-v68，避免旧调查状态冒充新规则完成复核。查询修复未改变持久索引格式，无需重建搜索索引。旧归档若已经丢失截断标记，无法凭空恢复；本轮不推断未知历史数据。
