# 业务解释改造：离线验证

本轮改善回答所用的业务组织方式：从用途和结果出发，沿已有源码确认的调用、参数、表访问与文件读写关系说明职责。只展开有据且与问题有关的环节；不能将名称清单、逐行翻译或反复的“未验证”当作业务解释。用户禁止真实模型调用，本轮外部模型请求和新增费用均为 0。

## 实现与保护范围

业务导航新增来源绑定的关系，保留程序身份、语句条件、编译分支和引用。静态 CALL 只说明请求目标，唯一同名实现仍是候选；LF/PF 关系须有实际定义，不从文件名、共同 COPY 或同一目录猜测数据流。框架闭源时解释可见请求、实参、返回状态和分支，只将实现缺口限定在依赖它的结果上。

回答策略要求先解释业务对象、用途与产出，再说明批处理组织、在线功能输入/输出、程序分工及表文件角色。窄问题仍直接回答，不扩展完整概览。本地审查只提示明显的“只列名字/只说用途”遗漏；提到关系不证明方向、条件或业务意义正确，不产生语义质量通过结论，也不增加请求或修订上限。

每题缓存复用相同源码投影与回答要求，不缓存答案或答案评分；源码、版本、引用、范围、编译与手册输入改变就重新计算。问题结束关闭缓存，复制上下文、线程或异步子任务不能串用。未添加整题固定到点停止规则。

导入、工作区恢复、历史数据库、索引版本和界面布局不在修改范围。完整回归仍覆盖前版的旧 output 复用、历史恢复及一次性兼容升级。

## 源码分析示例（人工整理，非新模型实测）

现有三份固定示例源码可以讲成两条业务流程：

**订单结算记录生成。** 这项批处理把满足条件的订单整理成结算记录。nightjob.clle 声明 ORDERIN 到 APPDATA/ORDERS 的覆盖并请求运行 SETTLE；调用正常返回后才执行撤销覆盖。SETTLE 从 ORDER-IN 读取订单，只对状态 A 且金额大于零的记录，复制订单编号和金额并请求写入 SETTLEMENT-OUT。它不在这段源码中汇总金额或完成付款。不满足条件时发出固定跳过提示。源码足以说明处理职责，实际调度和文件绑定是否生效另由运行配置决定。

**账户可用余额查询。** 注释将 BALANCEQ 定位为供操作员使用的在线查询入口。调用方提供账户号，程序查询 ACCOUNT_BALANCES 中该账户的 AVAILABLE_BALANCE，并通过 CURRENT-BALANCE 参数提供余额。它读取已有余额，不在这段源码中计算或更新余额。控制流到达 SQLCODE 判断时，零分支置业务状态 00，非零分支置 90；90 不能单独解释为账户不存在。调用者应结合状态理解余额，不能把未知结果当作零余额。

三份源码未展示两项功能互调或共享表文件，不能凭“结算”“余额”等名称编造联系，也不能据此断言系统全局完全无关。对应冻结来源与逐项结论见[原源码分析](../2026-10-20-business-boundaries/source-conclusions.json)。

## 验证口径

沿用已有真实问答和对应源码做离线回放，不修改历史回答或失败评审。原 batch/online 答案没有因新增关系审查触发无意义修订；原边界追问中的“没有数据库状态检查”仍被标记为待修订。离线回放、手写响应和合成接口测试仅验证机制与来源，不代表改版模型自然语言质量或真实模型延迟。
