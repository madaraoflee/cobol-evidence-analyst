## 新确认的诊断缺陷

BUG-20261109-014：本机受信任TLS握手完成、服务端收到完整POST后，故意损坏响应TLS帧，实际urllib仍显示“无法建立安全连接”。原因是opener.open包括发送请求与读取响应头，尚未返回响应对象不等于握手尚未完成。请求结果仍正确保持unknown，没有发现因此自动重发或破坏记忆。

证据见 `tls-phase-reproduction.json`、`reproduce_tls_phase.py` 与 `field-audit-report.json`。拟议最小修复 `tls-compatibility-proposal.patch` 只纠正中英繁中文案，解释旧枚举仅为兼容分类，不改传输、重试、预算、记忆或请求状态。准确追踪每个TLS阶段需要重构HTTPS连接/代理处理，不适合为文案归因问题扩大修改。

该提案涉及被冻结的公共本地诊断与界面。旧 `test_business_chat_response_recovery` 的一条预期正好要求原错误文案，必须更正该预期，不能偷偷删除测试、弱化断言或在新文案中塞回旧词骗过检查。原27个测试身份、181个断言语句保留，另新增两项原生/服务端Python回归和一项三语言浏览器回归。已按AGENTS.md要求请求这项最小范围例外及唯一预期更正；在用户决定前不应用生产补丁，本项保持open。
