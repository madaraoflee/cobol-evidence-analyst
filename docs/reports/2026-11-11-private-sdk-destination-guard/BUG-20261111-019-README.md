# BUG-20261111-019 — launcher destination link could be followed before final rejection

This defect was found in the unshipped opt-in launcher materialization for BUG018. On Windows, `Path('python3.exe') == Path('PYTHON3.EXE')`, but the original ignore callback compared the directory listing string case-sensitively. An uppercase listing could therefore survive the exclusion and be copied as a link into the private SDK. The subsequent `copy2(source, destination, follow_symlinks=False)` controls source-link handling; it does not make an existing destination link safe. Final manifest rejection could happen only after a destination target had already been touched.

The independently obtained before reproduction is preserved byte-for-byte as `before-destination-link-reproduction.json`, copied from `/private/tmp/sdk-alias-destination-link-review-reproduction-20261111.json`. It uses two neutral POSIX fixture files and simulated Windows directory spelling. It observed a destination still linked to the source fixture and source ctime changed, even though bytes were identical and copy2 restored mtime. It does not claim an actual Windows interpreter or host runtime was damaged. The exact pre-fix prepare source is preserved as `before-prepare_private_sqlite_runtime.py`, SHA-256 `207a5dce7dbe2129ca44816b66eefe4e26dc6253f1db86194d83caa48d93cc4f`.

The minimal correction makes the ignore callback match directory names with `casefold()`. It reads and verifies the already-private interpreter bytes once, checks the destination with the unchanged no-links guard, rejects any existing destination, and creates the ordinary launcher with exclusive `xb`. It never copies to or applies metadata by the destination path. A link left by copying, inserted after the guard, or inserted after the nonexistence check is rejected without writing through it. A pre-existing ordinary destination is also left unchanged.

Five new regressions cover uppercase directory spelling, residual links pointing to both a source fixture and an unrelated external file, a post-guard insertion, an insertion immediately before exclusive open, and an existing ordinary destination. They verify target bytes/hash, mtime, ctime and inode remain unchanged. The prior ten launcher regression methods and all their assertions are AST-identical to the saved pre-019 version. The original 16 prepare and eight setup tests are byte-identical to HEAD.

`after-destination-link-reproduction.json` is a fresh neutral fixture using the fixed production helper: host hash/mtime/ctime/inode all remain unchanged; the launcher is an independent ordinary file, not a link to the source. No actual SDK or executable is run. The full targeted group passed 39 tests in 0.313 seconds, zero failures/errors/skips; see `targeted-019-final.log`.

Final source/test hashes, five exact IDs and preservation proofs are in `019-final-freeze-handoff.json`. The setup source remains frozen at the BUG018 hash. No business logic, source-analysis behavior, old test, runtime pin, model, company source or app build was changed here. Root must run the complete recorded-bug gate and actual Windows SDK/source/final-EXE acceptance after this freeze.
