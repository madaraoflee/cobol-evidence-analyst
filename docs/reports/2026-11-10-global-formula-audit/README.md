# 全系统 premium 公式查全：诊断与修复方案

当前系统能够检索和解释候选程序，但尚未建立“全系统计算位置清点”的完整合同。缺少全库范围、可持续推进的已知待办以及独立完成校验，会同时造成漏掉独立业务根、继续调查不前进和过早结束。这与答案篇幅、HTTP 500是否限流是不同问题，调大输出长度不能修复覆盖缺口。

本次诊断针对源码 `f7cfd140b22b9b2d5acb254bf9a8e44dd11461c5`，只使用中性合成源码、真实解析/检索/调查流程和注入响应，无真实模型、公司源码或网络调用。本轮没有修改运行代码，没有构建或发布新包。上轮PR #21只更新源码，已有EXE不会自动包含该修复；本次缺口在最新已合并源码上仍可复现。

## 复现结果

- **新 BUG-20261110-009：全库范围与发现完整性缺失。** 用户原句在3文件仓库中只查到英文premium命中的入口及其被调用程序；独立程序的中文注释明确写“此项为保费金额”，紧接实际计算，但它没有进入任何模型请求。程序仍接受“以上是本系统全部保费计算位置”，结果为ANALYZED/sufficient_material。保存默认业务回答要求的对照仍漏同一文件。另一多轮复现中，上轮“只看a.cbl”的排他范围在改问“全系统”后仍被继承；该对照只证明范围错误，不声称虚假完成。
- **重新打开 BUG-20261106-026：旧批次修复遗漏formula-only分支。** 12个独立程序均明确使用PREMIUM-AMT，12个都已发现，但只供应8个；余4个只有缺口数量，没有持久待办游标。显式继续又供应相同8个，新增路径为0，两次都PARTIAL。旧修复只有业务概览分支建立游标，旧测试没有覆盖此公式分支；保留全部旧证据和断言，不能当成新编号掩盖旧修复不完整。
- **新 BUG-20261110-010：在线提前完成。** 25个premium命中可正确按20+5分页；只读1个且前轮明确24个未查，3次模拟模型交换后仍answered，工作区清除pending。这证明终答门禁没有核对未完工作，不说明分页只能返回前20个。
- **新 BUG-20261110-011：在线丢失未完搜索。** 搜索后13次读页使其游标离开最近12条模型上下文；多次显式继续共98动作后，搜索也离开最近96条持久观察记录。97页已读证据仍在，丢失的是未完成工作。与旧BUG-20261109-002的偏移不可执行不同。

负控制保留：本地12路径场景未假称完整，而是持续PARTIAL；跨程序静态CALL确实能供应被调用程序；相隔301行、同段落同结果字段的两条公式仍能经result_adjustments补齐并安排补读，没有据此登记新的公式分组bug。在线6次模型请求或24动作的单次预算正常返回needs_continuation并保留待动作，不把预算本身说成错误。

## 为什么上一轮全量测试仍然通过

5,170个Python和322个浏览器测试证明了当时登记合同的源码回归。现有最强批次测试从明确入口覆盖12文件/37规则，以及部分LV、参数改名、失败恢复，但没有把“无入口全库发现→所有业务计算点→最终用户清单逐项无遗漏”作为成功合同。模拟模型给出引用和一般说明就能满足部分测试；“资料进入过请求”也不能证明最终答案解释了每项规则。详细证据见assessment.md和coverage-audit.json。此次诊断不推翻旧测试的实际通过结果，但推翻把这些结果视作全库查全保证的推论。

## 修复应围绕一个完整调查任务

1. **先明确范围并建立全部候选。** 将“全系统/所有位置”识别为独立范围，覆盖当前固定提交内的已纳入源码，解除旧单文件排他限制；显式单文件问题仍保持原范围。在线暴露固定版本的文件/算术规则/出现位置清单与分页入口，不靠premium单词命中替代全库发现。命中别名必须由注释、字段/参数数据流或适用映射证明，不能猜缩写。
2. **把未完成工作从模型文字中独立出来。** 持久记录待翻页、待核对位置、待追踪调用/逻辑视图、动态目标和未解析文件；所有调查模式复用可推进批次。上下文不足时压缩已经核对的业务发现，保留原文定位和完整待办，不把最近12/96条观察当作全局记忆。
3. **让完成可核对。** 记录总文件、候选计算点、已核对、排除依据、未读与未绑定数量。未完工作不为零就不能宣称“全部/只有这些”，但应交付完整的已知清单和具体余项，而不是一句无法回答。模型的complete=true不能自己清空未完成范围。
4. **最终产出按业务位置检查。** 每个计算发生点列出程序/段落/原文位置、业务角色、公式或分步运算、适用条件、输入来源、调用参数、LV来源、舍入/累加/覆盖及最终影响。相同表达式的不同业务位置不能去重丢掉；搬运、日志和无关计数器不能冒充保费公式。长清单允许分批呈现并完整导出。

验收先建立独立金标，再执行用户原句。完整中性夹具必须所有计算点均进入最终清单、无无关项；缺源码/解析失败/动态绑定不明的夹具必须保留未完范围。覆盖多个独立根、跨语言业务标签、参数改名、LV/COPY、晚批公式、上下文压缩和故障恢复。还要加入故意“只读一个就说全部”的模拟响应，验证门禁确实拒绝。已有所有旧回归仍须全量执行；随后才能在获准环境做真实模型与公司版本验收。
