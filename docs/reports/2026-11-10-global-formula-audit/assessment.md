# 全系统 premium 计算清单：现有验证覆盖评估

5170 个 Python 测试全过，不能证明系统能回答“列出整个系统所有计算 premium 的地方”。现有测试证明了若干重要环节——已选入口的批次继续、局部公式定位、调用参数改名、部分逻辑视图追踪、未解决依赖保留——但没有找到一个把“无指定入口的全库发现 → 全部业务计算点及派生关系 → 最终用户清单漏项检查”串起来的成功合同。

本次只读审计基于 f7cfd140b22b9b2d5acb254bf9a8e44dd11461c5；未执行测试、模型或网络请求，未修改仓库。使用测试源码、断言和缺陷映射判断覆盖，不把缺少测试当作已复现运行故障，也不把合成模型的合格输出当作真实模型保证。

## 现有缺陷应复用，避免重复登记

- BUG-20261106-026/027/028：批次遗漏、全局调用深度、较早未解决依赖。这些已修复合同保护已发现闭包；若新复现显示该同一机制回退，应追加原条目证据。
- BUG-20261107-001：末批完成后压缩或续轮回到首批，属于继续调查和去重同一机制。
- BUG-20261001-006：晚出现的明确目标公式被候选预算截掉；不是无入口全库发现合同。
- BUG-20261106-009/010/012/013：上游挤掉下游、未绑定不等于缺源码、动态字面量候选、重复动态来源挤出源码。
- BUG-20261002-001、BUG-20261015-008、BUG-20261020-111：泛泛计算短答、遗漏实际累加、技术清单冒充业务说明。可用于约束最终业务解释，但没有整个系统计算清单的召回断言。
- BUG-20261106-904 仍 open：公司复杂逻辑视图和子程序的真实业务回答质量未验收。新的中性全库复现不能自动关闭此现场问题。
- BUG-20261110-001/007：失败轮已完成分析的继承、首轮失败没有成功历史锚点。全局调查若跨失败恢复，应复用这些缺陷验证，不另起“失忆”总称。

只有确认实际错误机制后，才能判断它是以上某条回归，还是“全库发现/全库完成判定缺口”的独立新缺陷。缺少端到端测试本身只说明验证空白。

## 新的业务成功合同

输入保持用户自然语言：“列出这个系统所有计算 premium 的地方，说明每项怎样算、何时适用、有哪些调用派生、logical view 来源和最后影响。”不预先提供程序名、结果字段或正确文件列表。运行必须绑定选定仓库提交、分析资料修订、编译/COPY 配置和已纳入文件清单。

金标先于系统运行独立建立，按“业务计算发生点”而非文件、搜索命中、COMPUTE 数量计数。每项标记源码位置和 COPY 实例、业务含义、结果变量、公式或分步运算、适用分支、调用路径、参数映射、输入来源、累加/舍入/覆盖、最终输出作用。LV 数据映射是输入来源依据，本身没有运算时不能冒充一个公式。相同公式在不同业务入口出现要分别列位置，再允许分组说明。

通过需要同时满足：

1. 金标内全部业务计算点均出现在最终交付清单，完整 fixture 的 site recall=100%；不存在漏掉的独立根、改名参数、COPY 实例或晚批计算点。每条清单绑定精确版本原文，precision=100%，不把 DISPLAY、计数器、注释和报表搬运误作保费计算。
2. 输入、分支、派生顺序和最终影响逐项可核对；不能用“MOVE 给某变量”或泛泛“调用模块计算”代替业务说明。有未提供运行配置时明确区分源码规则和实际生效分支。
3. 枚举证书与回答分开核验：已选源码总数、读/解析/未纳入数、发现根、待遍历调用、未决动态目标、别名依据、未完公式批次及引用均可审计。未遍历、跳过、截断、权限失败或动态绑定不明时，**只能交付已核对清单+明确未完成范围**，不能声称“全部/只有这些”；也不能把全部已知内容退化成“无法回答”。
4. 当单轮上下文或读取预算满时压缩并持久化原文绑定、完整枚举集合与未办项，继续后已验证集合单调增加；新进程恢复、一次 HTTP 500、一次未知结果阻断均不能丢已发现位置。未知请求继续维持人工确认，不能为查全绕开重试保护。
5. 同一完整 fixture 的无入口问题、从入口追问“还有其他地方吗”、中英混合问法应覆盖同一业务集合；指定单文件问题必须仍限制范围。可读的完整表和逐业务解释允许分段交付，但最后要能导出完整清单，不靠一条很长的 prompt 塞全库。

## 如何分层验收

先用中性 fixture 及独立 oracle 检查全库枚举、资料供应、保存恢复和完成门禁；合成模型应有故意漏项/只答前一批/声称全部的对抗响应，确保门禁会拒绝虚假完成。随后才在已授权目标环境让真实模型回答同一问题，由业务人员对照金标逐项评分。评分记录必须保留漏项列表，不能只给主观“详细程度分数”。真实公司问题还需固定实际提交并由熟悉保费业务的人确认术语和覆盖边界，源码测试通过不能代替这一步。
