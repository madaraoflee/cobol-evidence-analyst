# P3-C：业务链事实与完整性检查

日期：2026-09-08

本轮修复了会截断业务证据链的三个问题，并让可执行演示明确报告“部分覆盖”。完整业务分析仍未完成：现在能更可靠地取得条件、字段定义和 SQL 输入输出，也能用明确的业务金标准检查缺项；还不能保证模型对任意问题自动找全证据并生成完整业务解释。

## 已实现的效果

多行 IF 保留完整条件与物理行范围。`SYNP000:38–39` 的条件现在完整表示“状态既不是 P，也不是 I”，不会只引用第一行而误判 I 状态。嵌套分支保持独立，句末句号关闭全部开放范围；未支持的内联、缩略或复杂条件保留 `partial/unresolved`。

COPY 数据字段按消费程序生成独立定义绑定。查询 `WS-MODE-FACTOR` 并指定 `SYNP040`，可以得到原始 copybook 字段位置和程序的 COPY 引用链。同名字段不跨程序混绑，重复定义保留歧义。嵌套最多八层；循环、缺失、重复目标、REPLACE 预处理和不支持的 COPY 形式保留边界。定义共享不等于运行时存储共享，CALL USING/LINKAGE 参数位置映射尚未实现。

SQL 提取受支持静态语句的宿主变量读写。`SYNP040:34–39` 的同一段 SQL 写入 `WS-MODE-FACTOR`、读取 `IN-PAYMENT-MODE`，并保留外部表 `SYN_MODE_FACTOR`；第 66–67 行的 COMPUTE 再读取该因子。这证明源码中这些关系存在，不证明实际因子值或完整 SQL 列级血缘。字符串和注释不能注入伪字段，未支持输出形式、批处理和不完整语法不生成方向事实。

索引增加独立解析器版本。升级后重新执行原索引命令会自动重建旧事实；COPY 改动会重新绑定未改动的消费程序。生成字段不会挤满搜索结果，COPY 来源引用仍经过原有证据发现、范围限制和完整性校验。

## 业务验收没有被缩成“找到公式”

新增 `business_acceptance.py` 按明确选择的 CALC-01 金标准做离线来源事实检查。公式、SQL 输入输出和控制关系必须落在对应语句上，并返回快照、源码范围与 Hash。它扫描已存索引，不重新读取当前工作文件，不做任意问题理解，也不证明 Agent 已检索到这些证据。

当前结果为 `PARTIAL`：16 项来源事实覆盖、3 项已审查业务缺口、4 项边界。三个缺口来自样例源码与目标规格的真实差异：

| 目标要求 | 当前缺口 |
| --- | --- |
| 所有有效附加保障逐项累计 | 样例只有单项处理；集合遍历与完整累计尚未证明 |
| 每个必要调整查询失败时终止有效金额 | 只在职业查询后检查 SQLCODE；折扣、缴费因子和费用查询的独立错误路径尚未证明 |
| 基础费率按计算基准日生效 | 基础费率查询没有基准日条件，路由日期筛选不能替代费率时点证明 |

人工审查缺口须重新审查并更新金标准，普通语法匹配不会自动消除它们。本轮没有改写业务样例去凑通过。实际动态目标、运行输入与外部数据、跨程序参数值流及模型完整回答能力继续保留边界。

演示仍使用 6 次工具调用、读取 12 段证据；金标准扫描独立运行，不计入这六步。`answer_preview.support_status` 不再因两条公式非空就标为支持。Agent 保留单条 COMPUTE 的支持状态，但另有应用生成的 `question_coverage.status=not_assessed`，正文先说明问题相关性与完整性未核验。`stop_reason_scope=investigation_loop` 防止把循环结束误读为业务分析完成。业务推测和待确认问题恢复显示，并保留未核验标签。

## 验证与复现

完整自动测试 164 项全部通过，保留原有 48 个 COMPUTE 金标子案例。新增回归覆盖 COPY 作用域与增量、条件续行与句末范围、SQL 方向与对抗输入、业务链变异、回答完整性和严格工具投影；子案例不与测试方法数相加。

删除状态续行、缴费因子 INTO、SQL 输入、错误清零、公式组成项或舍入标记，会使对应检查失败。测试通过表示检查能发现差异，不表示完整业务能力通过。

## 距离最终目标

下一步围绕完整问题补证据：CALL 参数到 LINKAGE 的值传递、错误传播与后续覆写、真正覆盖完整业务过程的正向样例，并保留当前反例。随后验证模型能按问题取得这些证据。六步预算及读取源码后关闭调查的限制是否足够，也须通过完整问题验收决定，不能靠提高单条公式通过率替代。

在此基础上再连接经批准的真实模型与界面。真实源码和外部数据继续留在批准环境。代码理解技能用于把预期业务关系与实际源码逐项对照，特别保留缺少的关系，而不是从已有公式推断整个目标已完成。
