# 升级恢复修复记录

本次修复解决原结果目录被拒绝、索引恢复失败时历史一并隐藏，以及已知旧版索引需要重新填写接入路径的问题。界面布局不变。回答内容质量仍未通过新的真实模型验收，本记录不将升级兼容测试当作业务解释质量改善的证据。

## 已复现的问题

已发布代码 `99d70d7` 的输出目录白名单遗漏了部分 SQLite 的 `-wal`、`-shm`、`-journal` 伴随文件；已有资料库中额外保存的笔记、导出文件也会触发 `INVALID_PATH`，统一提示又容易使人误以为必须清空 output。该严格白名单并非上一版才加入，但新版交付没有覆盖足够的旧工作区场景。

启动时，`_restore_workspace` 先恢复索引，再打开历史库。源码路径不可用、索引或诊断报告缺失/不兼容时提前返回，导致 API 返回空历史，即使 `conversations.sqlite` 中原会话和消息仍在。另有可重复的链路：一次提问遇到索引版本/配置不匹配，接入报告被写为不可用，下一次启动就不加载历史。

用户确认前后均直接启动 `COBOLWorkbench.exe`，新版解压到新目录。桌面默认 profile 路径并未改变。对实际 `.3 → .5` 源码归档做健康工作区交接能够成功恢复，尚不能据上述复现认定用户 Windows 上的具体触发条件，更不能声称已经删除或恢复了其电脑里的文件。

## 修复行为

历史现在按原源码与结果目录读取，独立于当前索引是否可用于新问题；没有当前有效索引时，新问题仍不可用，旧回答也不被标为已验证当前源码。同一范围更新回滚失败时保留历史入口，换源码或输出范围时仍隔离。

原结果目录可以保留 SQLite 伴随文件及不冲突的笔记、导出。识别依赖索引中的源码身份；索引缺失时，可用结构有效且具有相同源码身份记录的历史库确认目录归属。不会将陌生目录、矛盾身份或危险链接当作可覆盖的分析目录，也不会因检查而创建空历史库。

自动本地升级只支持已验证的解析器 `1.7/1.8 → 1.9`、前端事实版本 `5 → 6`，以及 schema `0.3 → 0.4`；当前版本复用原索引。编码、文件选择、COPY 顺序、编译条件等用户设置必须可复现。升级沿用普通备份/回滚路径，不调用模型，并记录同一来源快照和目标版本的尝试，失败或中断后不在每次启动反复执行。缺失、损坏、未来/未知版本、待恢复更新和用户配置改变继续要求明确恢复，不猜测迁移。

独立审查还补出了旧入口范围被扩大为全目录的迁移风险，已加上同源、同快照的完整资料库范围证明；按入口导入和未知范围不会自动扩大。旧报告快照不匹配时，即使为显示修补报告，也持久保留范围来源不可确认的标记，后续重启不会据此自动升级。同一失败尝试在读取大报告或完整扫描索引前退出，避免每次重启重复扫描。损坏的大报告投影会保留手动恢复状态，不导致启动崩溃。
