# P3-B 项目进度报告

日期：2026-09-07

P3-B 已把独立 Claim 核验的第一个切片接入 Agent：系统现在可以证明某段源码中 `COMPUTE` 语句的目标字段、算式 token 顺序和 `ROUNDED` 与提交的结构化断言一致，并生成带边界的中文陈述。这是范围明确的语句核验；真实公司 API 验收、执行路径证明和任意自然语言结论的完整语义核验仍未完成，P3 尚未整体关闭。

## 已完成的实现

[`claim_support.py`](../../poc/claim_support.py) 是独立于模型表达和结构索引结果的本地核验器。模型只提交 `compute_statement` 断言及 Evidence ID，断言包含 `target`、算式 token 数组 `expression` 和布尔值 `rounded`；该模式不接受模型陈述正文或自评支持状态。核验器要求引用单段已通过完整性校验且未截断的源码，独立解析完整的受支持 `COMPUTE` 语法，再逐项比较断言。缺少证据、语法不受支持或任一内容不匹配，均不能升级为支持，并保留可检查的拒绝原因。

核验通过后，中文陈述由本地模板生成，内容限定为这条语句写了什么。它不会把算式自动解释成生产最终值，也不推断语句是否执行、后续是否覆写、字段精度或舍入后的实际结果。支持语句核验的回答始终附带这一范围边界；当全部陈述都通过时，回答状态为 `SUPPORTED_WITH_BOUNDARIES`。

[`agent_loop.py`](../../poc/agent_loop.py) 接入新断言路径，并保留旧的自然语言路径。旧路径仍只校验引用和词面锚点，状态为 `CITATION_VERIFIED_ONLY`；模型自行写出的 `supported` 不构成独立核验结果。原有四工具白名单、最多六次调用、两次无进展停止、Evidence 范围与 Hash 校验、源码返回后关闭工具阶段等门禁继续生效。本轮不增加工具、第三方依赖或网络调用。

## 离线验收范围

本轮按 ai-evals 的方法，把确定性核验的正向与对抗样本固化为自动回归用例。样本核对算式、目标字段与 `ROUNDED` 的支持或拒绝结果，并覆盖证据不足和超出解析范围时的保守行为。评测的主要门槛是错误或未覆盖断言不能获得“支持”，而非提高回答的升级比例。这些是项目合成样本，不是经过业务专家标注的真实业务验收集，也没有训练或校准 LLM judge。

验收命令 `python3 -m unittest discover -s poc/tests -q`：105 项测试全部通过。新版本化金标集 `compute-statement-gold-v0.1` 含 48 个源码案例，其中 10 个预期支持、38 个预期不支持，逐例状态和原因码全部匹配；这些案例作为子测试计入测试方法，不应与 105 相加。另有断言字段、证据完整性和 Agent 接入测试，覆盖自评状态伪造、文本夹带、混合状态、核验器异常与不支持断言拦截。

源码格式测试包括固定列序号区、注释与调试指示符、72 列外内容、未结束语句、多语句拼接和运算符粘连。运算符分隔采用 [IBM i COBOL 算术运算符规则](https://www.ibm.com/docs/en/i/7.4?topic=ae-arithmetic-operators)中的空格要求，防止把 `1.0--RATE` 之类原文改写成另一个可接受的算式。核验器仍只实现明确限定的语法子集，不能替代方言解析器或编译器。

CALC-01 端到端测试从真实合成 fixture 重建结构索引，依次搜索字段、检查程序、追踪关系、读取源码，在四次工具调用内动态取得证据并核验结构化计算断言。Evidence ID 来自本次工具结果，不是固定答案或硬编码引用。该流程验证核验器与受控调查的接线；公司模型是否能稳定选择正确断言，仍需真实 API 验收。

自动测试使用本地执行及注入的假 API 传输。本项目环境未访问真实公司端点，测试结果不能替代公司网关兼容性、真实模型回答质量或私有方言适配的验收。

## 状态的使用边界

| 回答情形 | 状态与含义 |
| --- | --- |
| 所有陈述都来自通过独立核验的结构化计算语句 | `SUPPORTED_WITH_BOUNDARIES`：支持该语句写法，范围边界必须保留 |
| 模型给出普通自然语言陈述且引用有效 | `CITATION_VERIFIED_ONLY`：引用与词面锚定有效，语义未核验 |
| 任一结构化断言不匹配、证据不足或语法超出支持范围 | `ABSTAINED`：本轮全部陈述不进入答案，核验原因保留在 `verification.claim_checks` |
| 工具契约、快照或访问范围触发硬门禁 | 维持原有安全停止行为，不作为成功回答 |

结构化断言与旧式自然语言陈述混合时，逐条保留各自支持状态，整体仍为 `CITATION_VERIFIED_ONLY`；`claims_semantically_verified` 只有在非空陈述全部通过独立核验时才为 `true`。`verification.semantic_claim_support_checked` 表示本轮实际完成过结构化核验，不意味着所有陈述都通过。

## 下一个退出门槛

先在公司批准环境运行 capability probe，再用合成 CALC-01 验收真实模型的四工具调查、结构化断言、引用和边界。通过后，才把同一运行器接到获准的试点索引；真实源码和运行记录留在批准环境。

后续 Claim 核验按具体断言类型扩展，每新增一种类型都先建立正向、错误与超范围样本，再允许状态升级。条件、路径、跨语句数据流、最终值和完整自然语言语义仍需独立设计与验收。本轮完成的是这条路径中可执行、可回归的 `COMPUTE` 语句切片，不代表完整目标架构中的 Claim Support Checker 已交付。
