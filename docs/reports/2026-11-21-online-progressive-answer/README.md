# 同一笔扣费问题的分段交付

**拿到第一份足以证明扣减条件的原文时，在线工作台已经能显示这条结论。等第二份原文查实后，最终答案才补上退款的适用条件和剩余金额。** 在同题离线对照中，改动前后读到的两份源码相同，受控模型也给了同一句漏答。区别可以直接从会话中途和结束时的正文核对。[改前记录](before.json) · [改后记录](after.json)

原题是“保费收取时 reserve 和 refund 的扣减顺序及适用条件是什么？”两个程序和这句问法均取自[原有中性用例](../../../poc/tests/test_online_automatic_source_search.py)。这是可反复核对的公开例子。公司的原始源码、现场问题及设备不在本次实测中。

## 用户先看到什么

| 公开会话状态 | 修复前 | 修复后 |
| --- | --- | --- |
| 刚读完主程序，尚未继续补查 | 缺少业务正文 | 显示指定类型才扣准备金，其他类型跳过，引用主程序原文 |
| 子程序原文已读，最后一轮回复仍在等待 | 缺少业务正文 | 已查实的阶段结论仍可见，能打开固定版本的源码 |
| 单独将每次调查限为一次请求，第一轮额度用完 | 只有用户问题和“继续调查”状态 | 阶段结论和可打开的引用仍在 |
| 自动调查结束，或显式续查后结束 | 提示先用准备金、剩余应收大于零时调用退款处理 | 同一对话只保留一份最终答复，交代扣减顺序、跳过条件、退款边界和最终应收 |

## 最终答复核对

在这个中性例子里，只有项目类型等于 `1-RESERVECREDIT` 才用准备金扣减应收。随后独立判断剩余应收是否大于零。跳过准备金后，只要应收仍为正，也会进入退款程序。退款余额严格小于此时应收才扣减，相等或更大时保留当时的金额。子程序通过参数修改调用方的应收。最终应收等于进入时的金额减去实际生效的各次扣减，全部跳过时保留初始金额。[实际交付和两处引用](after.json)

用具体数字可以区分“进入退款程序”和“真的扣了退款”。假设应收 100、符合类型的准备金 20，第一步后剩 80。退款余额为 30 时应收变为 50。退款余额恰好为 80 时应收仍是 80。这是按原文和交付的规则手算的例子，未运行 COBOL 或查实际账本。

为检查答案是否只适配原例，第三组保持原问题和受控回复不变，更换文件、程序、字段、项目类型，把调用门槛由“大于 0”改为“大于 12”，退款条件由“严格小于”改为“小于或等于”。返回的条件与新原文一致。相同的 100、20、80 在新例中会得到 0，恰好与原例相反。[变体的完整答案](after.json)

## 能从哪些证据得出结论

同题首段只引用 `cash.cbl`。准备金条件与扣减动作在第 4 至 6 行，控制退款调用的另一段判断在第 7 至 9 行。读到 `return.cbl` 后，工作台在等待最终回复时增加了第二条阶段结论，其依据是该文件第 3 至 7 行的参数、退款条件和扣减语句。用户此时可以分别点开两份原文。最终答复才把调用顺序、传参回写和各步跳过的效果连起来。测试逐一回读了这些可见引用，核对提交、资料版本、文件摘要、行段和文字。[同题三个观察时刻](after.json)

静态合成最终答案的范围限于能读全并绑定的简单扣减路径。遇到复杂流程，阶段说明可以显示可核验的局部业务规则，或模型从当前原文中指出且能逐字复核的源码行。单个片段不能证明跨程序先后。模型提交复杂扣费题的完整答案时，系统核对每一步的适用条件、跳过条件、影响以及最终结果是否写在正文中，并核对对应引用和源码行。遗漏会触发补查或保留待查项。这些检查无法独立证明任意模型解释都正确。追踪现场动态绑定、运行配置以及实际入账仍需要相应证据。[源码结论的适用范围](../../../poc/online_grounded_findings.py) · [复杂答案的逐项核对](../../../poc/online_deduction_review.py)

## 复测方法

对照基线为 `97231568836ab4ae5e9e7cc6f58d4be19abfab5f`。三组均从公开的在线连接、创建对话、提问和状态查询入口进入，续查组使用同一对话的恢复入口。用事件分别暂扣首次原文读取后的调查，以及最后一次模型回复，在这两个时刻读取页面实际使用的状态。每条可见引用均通过公开证据入口重新打开，核对固定版本、文件摘要、起止行和字节对应的原文。

受控模型在未见原文时固定表示“没有足够的源码可确认扣减顺序”，没有提供搜索词或阅读范围。拿到原文后，两版都收到完全相同的漏答“先使用准备金，剩余应收大于零时调用退款处理。”受控回复没有讲出准备金类型、退款等额分支或最终金额。各组开始和结束共调用两次内存接口，外部模型调用为零。等待由实验控制，不据此估计真实用户的首答时间。

在项目根目录运行以下命令可重放。第一条从本机 Git 对象恢复基线产品代码，第二条使用当前工作树，输出包含所有在线模块的内容摘要。三个定向回归在基线均因缺少阶段正文失败。[基线失败输出](before-tests.txt)
