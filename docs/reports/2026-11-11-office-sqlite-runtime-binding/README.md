# BUG-20261111-022 办公验收包 SQLite 组件绑定

手动办公包组装入口在候选应用声明 SQLite 3.54.1、验收助手却声明 0.0.0 时仍生成了验收包。使用中性、不可执行的 PE 测试夹具，经过真实候选门禁、组装器和包读取入口。只替换了冻结语料的大规模生成步骤，未启动 EXE 或调用模型。[修复前证据](REPRODUCTION.json)

原因是应用和助手原本分别校验包结构和验收元数据，组装器没有核对两个包声明及实际附带的 SQLite。已发布的受控 CI 工作流分别校验应用和助手，未观察到它产生过这样的失配包。修复限定在手动和 CI 共用的办公包组装器，应用运行及历史验收入口不变。

应用和助手均声明私有组件时，组装器核对同一官方 pin、已编译探针与各自交付的 DLL 文件。任一侧缺失、声明无效、文件重复、路径不在程序目录或散列不同都会阻断组装。未声明私有组件的历史双包沿用原检查。

重放原始夹具后得到 `OFFICE_PRIVATE_SQLITE_PIN_INVALID`，没有输出办公包。完整声明下的版本失配另由新增回归验证为 `OFFICE_PRIVATE_SQLITE_PROBE_INVALID`。七项新增测试和 76 项既有定向测试均通过，零跳过。目标办公设备与真实模型验收仍待完成。
