## 同一业务问题、源码及手册

问题：**ENTRYJOB 的业务处理流程是什么？** 追问：**那更新阶段是不是一定会保存成功？**

固定中性材料：[源码](entry.cbl)、[手册](manual.md)。必要结论、条件、证据和禁止断言记录在[固定问答集](cases.json)。

| 业务解释依据 | 可核对位置 |
| --- | --- |
| 取记录阶段的职责是取得待审记录；更新阶段负责请求获批变更。 | `manual.md:7–8` 与 `entry.cbl:16、19`。 |
| MAIN 中先出现取记录阶段的 PERFORM 请求；更新阶段的请求受 `APPROVED = 'Y'` 限制。 | `entry.cbl:11–14`。编号 3000/2000 不决定执行次序。 |
| 取记录阶段设置 ADVANCE 并调用接口；更新阶段设置 STORE 并调用接口。 | `entry.cbl:17–18、20–21`。参数布局见 `5–7`。 |
| ADVANCE 要检查返回状态；STORE 请求本身不代表已经提交。 | `manual.md:20–21`，并与对应功能码赋值及 CALL 绑定。 |

这条证据链支持这样的业务说明：流程先请求取得待处理记录；取记录阶段返回后，只有批准条件成立才请求更新。更新请求本身不能证明提交成功。它没有证明实际运行、读取成功、最终持久化或生产调度方式。

## 修改与安全边界

- 仅在当前可见、同版本的框架阶段存在时增加阶段关系；普通无框架问题不增加这部分调查材料。
- 复用现有 COBOL 解析器，保留嵌套 IF、EVALUATE 选择字段、之前分支不匹配条件、实际物理位置和当前手册注意事项。
- 命名 PERFORM、唯一当前声明和阶段内调用均需源码证据。关系表达“请求”和“词法包含”，不表达已运行或无条件效果。
- THRU 范围、重名程序或段落、缺页、COPY 展开实例、格式冲突不强行连成阶段执行关系。
- 过程 COPY、REPLACE 和未解释编译指令的结构边界由完整源码绑定阶段记录；后续 MOVE、新段落或请求裁剪不能解除。旧 v1.5 框架缓存失效重绑。材料仍保留为观察依据，不能把尚未展开说成用户未导入代码。
- 读取页面只继承同路径、同源码 SHA256 的明确格式。未知或冲突配置不猜成 free format。
- 源码或手册改变、引用被裁剪时，重新核对并撤回失效关系；不要求用户维护检索词或文件清单。

九个生产文件的本轮变化及哈希见[源码清单](changed-source-hashes.json)。其中 `business_chat.py` 只有本轮新增的三句阶段解释约束，`quality_trace.py` 只有本轮版本标识变化；同文件中的其他会话改动不在受控差分中。
