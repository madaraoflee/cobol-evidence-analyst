# 默认业务问答修复与 Windows 候选验收

这版修复的核心，是让工作台交付已经有证据的回答，同时减少无效调查和重复请求内容。源码与最终 Windows EXE 离线机制回归已通过；真实公司模型和办公室电脑分别验收，不能把离线机制通过写成“现场已经全部解决”。冻结提交为 `3b099c058f258824237835d7ea802a90055dee02`。完整身份、哈希、配对和阶段数据归入[同目录验收 JSON](2026-10-15-final-exe-3b099c0.json)。

截图里的问题有明确的应用缺陷：整题时间目标同时控制调查和正在进行的模型请求，目标一到便取消首答，源码已读却可能只显示错误。现在时间目标只调度后续可选调查，已发出的请求由独立 HTTP 超时与用户取消控制；默认不设整题硬截止。请求次数、HTTP 超时和输出额度没有借此增加。远程结果未知时保存请求及已交付正文，不自动重复可能收费的请求。

这些改动进入现有 `indexed_chat → business_chat` 默认链。模型失败、没有正文或只返回计划时，系统可以解释本题实际供应的直接源码事实，仍核对真实证据 ID、原文件哈希、物理语句、限定字段、COPY 身份和控制条件，并经过同一个 ClaimLedger 出口。这类答复明确为本地源码解释和 `PARTIAL`，不会冒充模型完成或业务语义全部验证；没有相关事实时也不能拿附近公式凑答案。

质量检查补上了两个实际缺口。同一包含链的列表与元组表示曾触发错误的证据冲突，如今只接受有序内容等价，真实文本、行段、版本和包含路径差异仍拒绝。明确问“计算并累加”时，计划、首包供证和完成度共同要求实际累加步骤：正常月息回答覆盖公式与 ADD；错误常数被修成 1200 后仍漏 ADD 的固定反例继续标缺项，独立正确公式保留。正确中文短答可用，无关 ADD、常量重置、否定、缩放或错误数字不能关闭义务。

自然 batch 触发问题在首个模型请求前核对入口、真实调用点及同版本 IF 条件。程序 CALL 与外部调度绑定分别说明，缺少调度配置时保持未知。已有前端语义、字段来源、覆盖、调用链、错误公式、历史证据与恢复回归继续保留。源码版 IR、摘要和切片样例重新生成，83 项原文哈希与行段检查通过；这些仍是有限源码语义支持，不是完整 COBOL 运行时或企业方言认证。

性能改动减少实际工作：字段定位先用已有索引缩小范围，保留全部同名候选；发送投影共享重复导航，不删真实源码、证据、版本、公式、条件或框架原文。最终三个固定问题在同一 canonical 材料、同一外层请求下，完整 wire 减少 **6.73%–11.78%**，每题仍一次 fake 请求。含外层请求编码的本地 CPU 中位数，旧算法为 **0.79–1.80 ms**，当前为 **7.53–14.02 ms**，同题增加 **6.52–12.22 ms**；这不是模型速度提升。字段查询的顺序缓存实验也不当作受控冷启动倍数。

成熟项目提供的是具体机制参考：问题相关地图与缓存、局部及受约束的数据流、预算与持久恢复分离。来源与取舍见[此前的原仓库研究记录](https://github.com/madaraoflee/cobol-evidence-analyst/blob/3b099c058f258824237835d7ea802a90055dee02/docs/reports/2026-10-14-interactive-latency-reference.md)；本项目继续使用自己的 COBOL 前端、切片和证据核验服务。

本机冻结版本 Python **2,872 项通过，151.474 秒，无跳过**。源码 HTTP 合成回归 **19 案例、61 个顶层样本、14 个范围探针通过**，502.804 秒，零真实或收费模型调用。这里的“通过”是固定机制断言通过：顶层为 **24 ANALYZED、31 PARTIAL、6 生命周期**。把三项对话聚合行展开成实际九轮后，是 **61 次主答复中的27 ANALYZED、34 PARTIAL**；另14个探针均 PARTIAL，共48条实际 PARTIAL逐身份复核。生命周期不混入业务正确率分母。

这些 PARTIAL 分别包括真实运行输入未知、有限供证、答案漏条件或累加、以及核验器尚不支持的自然语言语义。三轮首答的证据异常已消除，但固定正文仍漏条件与累加；第三轮明确问累加，也被准确标缺项。不能为减少 PARTIAL 改造合成正文、迁移旧评分或放松完成度。

大库耗时同样保留边界。两轮保存数据中，一个主问由9.18秒变为13.97秒，但核心分析均约4.04秒、核验约0.118秒，差异主要在尚未分段的外围；首样本另有地图构建波动。两轮未经控制，不能宣布回归或无风险。冷导入、主问题 primary、精确范围 probe 单独统计；主问加探针的总时间不能冒充单题响应，源码运行也不能代替 Windows 性能。
