# M1 产品一页纸：解释保费与保单费用计算

> 核心判断：第一个产品楔子只回答一件事——针对一个保费结果，说明它如何计算、输入来自哪里、哪些条件改变结果，以及哪些部分不能由当前源码证明。

状态：`Draft for review`  
日期：2026-08-27

## 问题

遗留保险系统中的保费计算通常分散在入口程序、产品计算程序、COPYBOOK、费率表、附加保障、条件分支和错误处理之间。分析人员即使找到最终 `COMPUTE`，也可能遗漏费率选择、跨程序参数、例外条件或外部控制表，导致回答“局部正确、整体错误”。

## 目标用户与时刻

用户是需要解释既有系统行为的业务分析师或系统分析师。典型时刻是收到“这笔保费为什么是这个金额”“某个费用在什么条件下出现”或“修改这项费率会影响哪些计算”的调查任务。

## 试点承诺

对原创合成保费系统中的一个明确问题，Agent 应当：

1. 定位最终结果字段及其计算入口；
2. 追踪基础保费、附加保障、风险加费、折扣、保单费用和缴费因子；
3. 还原 `PERFORM/CALL` 路径、字段传递和控制表选择条件；
4. 输出业务解释、计算公式、适用条件、源码证据和待确认项；
5. 对源码或数据快照无法证明的内容明确拒答。

## 输入与输出

输入是一个绑定到确定源码快照的自然语言问题，可附带合成保单编号或一组输入值。输出包含：简明结论、分步公式、输入来源、关键分支、执行路径、证据引用、分析快照以及未确认内容。

## 成功标准

- 26 个金标准问题全部可以被归入明确的调查类型；
- 代码事实的证据覆盖目标 100%，不存在虚构程序、字段或源码位置；
- 至少 85% 的问题在 Top-5 证据包中出现正确证据路径；
- 不可回答问题能够拒答，不把合成规则解释成真实公司或监管规则；
- 人工复核者能够在不重新阅读整个代码库的情况下重放结论。

## 非目标

本试点不覆盖真实 DXC 规则、真实香港保险产品、监管计算、生产费率、客户数据、完整保单生命周期、自动修改代码或生成正式业务规格。它只验证代码调查和证据化解释能力。

## 最大风险

最大的风险不是模型回答得不流畅，而是合成程序过于简单，无法代表企业代码的跨程序和表驱动复杂度。因此蓝图故意加入动态计算程序、COPYBOOK 参数、时点费率、附加保障、异常返回和最终舍入；同时仍保持业务规则原创、可人工穷举。
