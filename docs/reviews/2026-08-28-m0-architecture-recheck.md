# M0 架构复检：有条件通过

> 核心判断：混合 Code RAG、确定性代码图和受控 Agent 的总体方向成立，可以继续下一步设计；但 M0 尚未完成，必须先补齐问题策略、IR、工具和证据契约，技术栈也必须经过公司内基准才能从 Proposed 转为 Accepted。

复检日期：2026-08-28  
复检范围：产品边界、事实权威、检索流程、调查状态机、核验职责、里程碑与验收策略

## 1. 复检结论

本次没有发现需要推翻总体架构的问题。当前设计已经把“找到相关代码”和“证明代码关系”分开，也没有让 LLM、向量库或 Agent 框架成为事实来源。主要缺口集中在契约精度，而不是架构方向。

判定为 **Conditional Pass**：

- 可以继续设计问题分类与调查策略；
- 暂不进入业务代码实现；
- LangGraph、Qdrant、Neo4j、Qwen3 和解析器组合继续保持 `Proposed`；
- 在统一 IR、工具契约和 Evidence Package 完成前，M0 不关闭。

## 2. 已发现并修正的问题

| 编号 | 严重度 | 问题 | 修正 |
| --- | --- | --- | --- |
| R-01 | 高 | 原始源码、IR、Neo4j、Qdrant 和 LLM 输出之间的权威顺序不够明确 | 固定为“源码 → 规范化 IR → 可重建查询投影 → 调查证据包 → 待核验回答”；冲突时停止回答 |
| R-02 | 高 | 精确源码符号与语义候选被描述成一起进入 RRF，可能让已验证符号被相似度压低 | 精确命中成为锚定调查种子；RRF 只融合稀疏和稠密候选，随后由应用层合并 |
| R-03 | 高 | IR 和回答契约使用“置信度”，与证据优先原则冲突 | 改用离散的 `relation_status` 和 `support_status`，不以模型主观概率替代证据 |
| R-04 | 高 | Claim Verifier 同时承担结构一致性和语义支持判断，失败原因不可定位 | 拆成 Evidence Integrity Validator 与 Claim Support Checker 两层 |
| R-05 | 中 | 状态机固定“只补查一次”，对复杂跨程序 COBOL 路径缺少依据 | 改为在节点、深度、工具调用、token 和时间预算内循环 |
| R-06 | 低 | 路线图图示仍把 M3 写成单一事实图 | 统一为“版本化代码事实与检索索引” |

## 3. 架构质量检查

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 产品聚焦 | 通过 | 第一版只回答计算、来源、条件、执行路径和不可回答边界 |
| 事实可追溯 | 通过，待 Schema 固化 | 已明确源码权威和索引投影，但实体/关系字段尚未形成完整契约 |
| 检索正确性 | 通过，待实测 | 精确锚定、稀疏/稠密融合、重排序和图扩展职责清晰 |
| Agent 可控性 | 通过，待工具契约 | 单 Agent、有限状态、预算和拒答方向正确 |
| 质量定位 | 通过 | 解析、候选召回、路径调查、证据完整性和 claim 支持可分别评测 |
| 隐私边界 | 逻辑通过，部署待审 | 全部组件可自托管；实际认证、网络、日志和模型策略须由公司批准 |
| 可替换性 | 通过 | 统一 IR、实体键和 Evidence Package 位于框架适配器之上 |
| 运维复杂度 | 有条件通过 | 双引擎有明确收益假设和降级方案，仍须容量与运维基准 |

## 4. 尚未关闭的风险

- 没有真实 DXC Smart COBOL 样本，无法证明解析器能够恢复动态调用、表驱动路由和跨程序字段流。
- 没有私有金标准问题，无法证明 Qwen3、BGE-M3、RRF 和重排序对公司缩写与中文业务问题有效。
- 双索引的一致性协议只有原则，尚缺完整快照状态、幂等构建和失效传播 Schema。
- “完整回答一个问题需要哪些证据”尚未形式化；这正是下一份问题调查矩阵要解决的内容。
