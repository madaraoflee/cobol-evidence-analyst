# COBOL Lens：領導 POC 工作台

這次工作台要展示一條可以查證的流程：**接入使用者指定的源碼，提出業務問題，核對回答證據，再匯出當次結果。** 領導應能分辨正在看合成示例還是本機源碼、是否真的調用了模型，以及哪些內容仍未確認。畫面完成、索引完成與業務驗收完成是不同的狀態。

新介面的實作位置為 `poc/web/`，由本機服務 `poc/web_app.py` 提供；啟動方式見[演示包首頁](./README.md)。本文件是資訊架構、演示操作及驗收依據；個別功能是否通過，以當次實際操作和後端報告為準。

本輪已完成本機瀏覽器的源碼接入演練：讀取一組包含兩個程式的測試源碼，畫面展示實際調用關係，並成功打開第 8 行的源碼證據。這項驗證涵蓋介面與本機索引、關係及證據服務的接線；本次未調用實際公司 API，也未完成 Windows 實機或公司真實業務驗收。

後續瀏覽器驗收使用另一組兩程式源碼及模擬模型回應，實際執行索引、證據讀取與單條公式核驗，確認回答、四條工具記錄、換題後清空舊結果，以及證據不足狀態的呈現。示例和本機 Markdown 摘要均完成下載並核對內容。全套 685 項測試通過；這些結果仍不包含真實公司模型的回答品質驗收。

## 舊原型與本次範圍

舊 [prototype.html](./prototype.html) 是固定合成案例的互動原型：問題、程式、數量、回答和部分時間均為預設展示，沒有把輸入的任意問題交給本機分析服務。歷史六步執行記錄證明的是特定合成案例的本地工具行為，不能證明畫面上的任意問題已由公司模型調查。

本次使用中性產品名稱 **COBOL Lens**，採紅、白、深灰及繁體中文的香港企業介面方向；品牌視覺評審參考 [AIA HK 官方網站](https://www.aia.com.hk/zh-hk)。這是設計參考，不表示產品獲該機構認證或已投入生產。頁面不使用外部品牌標誌、圖片或網上字體；程式碼、設定及測試名稱維持中性。

## 大規模接入與日常更新（2026-09-14）

網頁預設使用輕量目錄。接入不會先逐語句解析全庫；先識別頭部程式名，必要時保留檔名入口，提問時才讀取相關源碼。資料庫頁每頁 100 項，入口選單提供名稱／路徑搜尋，不一次塞入上萬選項。頂部數量仍表示全目錄，本次詳細範圍在回答旁另行顯示。

進度卡支援三語，展示真實計數、耗時、目前檔案、階段／單檔預估與停止按鈕。重新整理恢復任務；停止後可再次接入同一來源與輸出位置，重用已完成目錄快取。頁面斷連顯示重試，不把連線失敗當成背景工作必然結束。

一般更新比較檔案元資料並重用未變內容。「強制校驗全部檔案內容」會完整讀取正文，僅在需要強校驗時使用。目錄 Hash 不是全庫證據快照。單次詳細範圍有檔案、深度和 16MiB 原文預算；缺依賴／達到範圍上限均要可見。缺 COPY 或閉源物件時可返回 `PARTIAL`，回答不能推測其內部邏輯及實際返回值。

測試數據與限制見[本次報告](../reports/2026-09-14-large-source-intake.md)；本機 12,000 檔案混合基準不可當成公司 12,000 個超大程式的完成時間承諾。

## 三種介面語言

右上角提供「简体中文」「繁體中文」「English」，預設保留香港繁體中文。選擇只儲存在目前瀏覽器，重新整理後繼續使用；瀏覽器禁止儲存時仍可在當頁切換。

導航、接入表單、狀態、示例解讀、提示與 Markdown 匯出的介面標題隨語言切換。使用者輸入、程式名、路徑、源碼原文、模型回答及診斷原文不自動翻譯，既有答案與快照不因語言切換而改寫，也不會重新呼叫模型。若需要另一種語言的業務回答，可在問題中明確指定；語言選單本身不重新生成回答。JSON 保留原始分析資料。

維護翻譯時使用 `poc/web/i18n.js` 的三語文案表。`t()` 僅處理介面文案，`ui` 模板僅翻譯靜態片段，插入的源碼或結果保持原文。語言回歸檢查：`node --test poc/tests/web_i18n.test.cjs`；應同時核對三語導覽、表單、記憶與英文排版。

## 四步資訊架構

| 步驟 | 使用者的主要動作 | 必須看到的實際內容 | 下一步條件 |
| --- | --- | --- | --- |
| 源碼接入 | 選擇本機源碼模式，輸入源碼與輸出目錄，建立索引 | 本次路徑、快照、讀取文件數、實際程式清單、未確認的 COPY／CALL 及讀取問題 | 目標程式已被識別；阻斷問題已解決 |
| 業務問題 | 從實際程式清單選擇入口，輸入具體問題，按「開始業務分析」 | 所選入口、資料範圍、接口設定狀態，以及本次操作會使用模型的提示 | 已提供接口設定；提交後通過接口能力探測才進入模型調查 |
| 證據回答 | 閱讀核心解釋，點開引用核對源碼 | 答案狀態、相對路徑、行號、證據及未確認事項 | 結論能回到當次快照；無答案時顯示原因 |
| 匯出結果 | 保存當次回答及診斷 | 產生時間、問題、入口、快照、答案狀態、引用與邊界 | 匯出內容與本次畫面一致，不能混入舊答案 |

主內容先呈現目前這一步的工作；右側用於資料範圍及證據詳情。首頁不以固定的大型數字充當實際接入成果。主要操作使用紅色；警告、失敗與未確認事項同時以文字及圖示識別，不單靠顏色。

### 源碼接入

瀏覽器不會自動取得本機絕對路徑。這一版由使用者輸入資料夾路徑，本機服務讀取該目錄；沒有實作系統資料夾選擇器前，介面不應放置一個無效的「選擇資料夾」按鈕。源碼與輸出位置須分開，可取得的 COPYBOOK 及被調用程式放在所選根目錄之下；缺失或閉源依賴保留為邊界，不要求取得全部內容才可解釋可見程式。

編碼、固定／自由格式與副檔名放在讀取選項，但讀取失敗時應直接指出相關選項。來源檔案沒有副檔名時，目前網頁流程會納入；若需排除，可使用命令列的 `--exclude-extensionless` 選項。接入後的數量、程式名稱和路徑一律取自本次服務回傳。

選擇新源目錄或重新建立索引後，舊答案不可繼續當作當前結果。若仍需保留歷史結果，須另行標示它的快照與時間。每次正式提問經過 `analyze_source` 重用／更新目錄，再對所選入口建立有界詳細索引；源碼在調查期間改動而被阻斷時，畫面顯示重新分析的動作。

### 業務問題

問題輸入支援自然語言，首次調查同時鼓勵選擇一個實際程式入口，避免只憑抽象業務詞搜尋。程式選單來自本次清單；不得沿用合成示例的程式名。相同檔名可以用相對路徑分辨；重複 `PROGRAM-ID` 的入口優先以目錄中的相對路徑選定；同一詳細範圍仍有重名定義時按診斷縮小範圍。

「接口已設定」只表示本機服務已取得可用格式的配置；它不代表網絡、權限或模型能力已驗證。首次下載 GitHub 源碼後，將項目根目錄的 `.env.example` 複製為 `.env`，填寫三個必填項，之後雙擊 `poc\run_web.bat` 即可。設定對話框以簡體、繁體或英文說明這個流程；修改 `.env` 後重啟服務，既有環境變數優先於 `.env`。本機 `.env` 不上傳 GitHub，Key 不回傳或儲存在瀏覽器。

建立索引始終離線。實際問答按鈕旁明示：「發起分析將使用已設定的模型接口，傳送問題及有限源碼證據。」使用者按「開始業務分析」才發起這次模型問答；介面沒有額外的聯網勾選框。尚未提供設定時，先開啟連線設定說明，不提交模型問答。配置缺項、檔案格式或讀取錯誤只顯示安全的處理提示，不顯示密鑰值或檔案內容。

執行中只顯示實際階段或已回傳的調查記錄，例如更新索引、檢查接口能力和調查源碼。目錄階段顯示真實完成／剩餘檔案數、百分比、已運行時間、目前檔案與預估時間；大檔案解析另顯示行數及本檔案 ETA。掃描總量未知、模型或關係整理無可用分母時顯示估算中。不可補上演示倒數、虛構工具步驟或模型內部思維。

### 證據回答

回答先給主要解釋，再列支持該解釋的源碼事實與尚未確認事項。點擊引用可核對相對檔案路徑、行號、證據 ID 及快照；缺少可讀證據時直接顯示缺口，不用預設源碼填補。源碼內容作為資料呈現，不能當成瀏覽器指令或 HTML 執行。

「引用已核對」不等於整段自然語言的語義已驗證。少數受支援 `COMPUTE` 斷言通過本地核驗，也只證明該語句的寫法，不證明它已執行、決定最終金額或覆蓋完整流程。回答旁保留可見的未確認事項；問題完整性目前仍未評估。

### 匯出結果

提供當次回答 Markdown、JSON 與診斷檔案的保存入口。回答檔應保留所問問題、程式、快照和答案狀態；如果回答檔本身未包含完整接入資料，連同診斷一起保存。模式標記與未確認事項不能因為匯出而消失。

`structural-index.sqlite` 是本機事實索引；一般演示以可讀回答和診斷為主要匯出內容。沒有生成答案時可以保存失敗診斷，不能用上一份成功回答代替。資料仍保存在公司批准的本機位置。

## 模式與狀態必須分開

| 畫面模式 | 資料從哪裏來 | 可以說明甚麼 |
| --- | --- | --- |
| 示例預覽 | 明確標記的合成資料與預設呈現 | 展示操作結構、證據閱讀方式及理想呈現；不代表本次調用了模型或讀取公司源碼 |
| 本機源碼 | 使用者明確指定的資料夾，經本機服務實際索引 | 說明本次識別到的程式、源碼事實、缺口及實際問答狀態 |

模式標籤在接入、問題、答案及匯出時保持可辨。即使把合成夾具交給本機服務實際分析，其來源仍是合成資料；「真的執行了索引」不能改稱「公司真實業務已驗收」。未接入任何項目時可顯示示例預覽，但切換到本機源碼後不應自動保留示例問題的回答。

本次接線沿用 `analyze_source.py` 與 `run_agent.py` 的三層狀態。介面可用下列繁體中文說明，原始代碼留在診斷詳情中：

| 資料欄位／狀態 | 使用者可見說明 | 不可推論的內容 |
| --- | --- | --- |
| 接入 `PREPARING` | 正在更新源碼索引 | 已經開始模型調查 |
| 接入 `INDEX_READY` | 源碼已接入 | 所有方言和業務都已理解 |
| 接入 `NEEDS_ATTENTION` | 源碼已接入，部分資料待核對 | 缺失依賴可以忽略 |
| 接入 `BLOCKED` | 暫時無法開始分析，請按原因處理 | API 成功可以繞過源碼問題 |
| 問答 `NOT_REQUESTED` | 尚未提出問題 | 已有業務答案 |
| 問答 `NETWORK_DISABLED` | 本次未使用模型 | 模型不可用，或已完成分析 |
| 問答 `RUNNING` | 正在檢查接口並調查源碼 | 有精確進度百分比或固定完成時間 |
| 運行器 `NOT_READY` | 問答尚未就緒，查看接口或資料診斷 | 一定是 API Key 錯誤 |
| 運行器 `SAFE_STOP` | 調查已停止，保留原因與可用證據 | 任務已成功完成 |
| 運行器 `COMPLETED` | 本次調查已結束 | 已回答完整，或業務正確性已證明 |
| 答案 `CITATION_VERIFIED_ONLY` | 引用已核對，語義仍待覆核 | 內容已通過完整語義核驗 |
| 答案 `SUPPORTED_WITH_BOUNDARIES` | 部分源碼斷言已核驗，適用範圍有限 | 最終金額、真實執行與完整業務已證明 |
| 答案 `PARTIAL` | 保留可核對的局部解讀及未知邊界 | 閉源返回值、完整路徑或全库內容已被證明 |
| 答案 `ABSTAINED` | 證據不足，暫未形成可接受答案 | 可以用示例答案填補 |

`diagnosis.question_status` 會在問答完成後使用實際答案狀態，或保留失敗狀態；畫面應以當次回傳為準。`NETWORK_DISABLED` 是命令列或服務在未允許聯網時可回傳的狀態，並非網頁上的另一個操作模式。`agent_result.question_coverage.status = not_assessed` 與 `full_business_analysis_verified = false` 不能被一個「完成」綠勾蓋過。

## 三分鐘領導演示腳本

演示前先選定使用示例預覽，或已獲准的本機源碼；需要真實模型回答時，先在相同啟動終端配置公司 API 並完成一次演練。首次大批源碼索引可以在會前完成，介紹時說明使用已建立的本機快照，不把等待時間剪掉後當作性能數據。

| 時間 | 畫面與動作 | 建議講法 |
| --- | --- | --- |
| 0:00–0:25 | 指出模式標籤與目前資料範圍 | 「先確認我們正在看哪一批資料。這裏會清楚標明是合成示例，還是這部電腦指定的源碼。」 |
| 0:25–1:00 | 展示源碼接入頁、實際程式清單及一項待確認依賴 | 「我們先在本機建立可追溯的索引；缺少的程式或 COPY 會列出來。這些數量來自這次接入的資料。」 |
| 1:00–1:40 | 選擇入口，輸入問題，指出模型使用提示後按「開始業務分析」，展示實際運行狀態 | 「現在問這個程式的主要處理步驟。按這個按鈕才會使用已設定的公司接口，傳送問題及有限證據，讓模型組織答案。」 |
| 1:40–2:35 | 閱讀一段回答、打開其引用，接着指出一項邊界 | 「這個結論可以回到源碼位置核對。旁邊保留未確認事項，引用有效與完整業務驗證會分開標示。」 |
| 2:35–3:00 | 匯出本次回答與診斷，展示快照和狀態仍保留 | 「這次結果可保存供覆核；之後源碼改動，我們會重新建立對應的索引與答案。」 |

示例預覽時，第三段改為：「這裏展示預設的操作與閱讀方式，沒有聲稱本次調用了公司模型。」如果現場網絡未開啟、接口未就緒或證據不足，就展示相應狀態及下一步，不能切換成預設成功回答而省略說明。現場仍在執行時如實保留進行中狀態，三分鐘是講解節奏，不是回應時間承諾。

## 本次驗收邊界

| 驗收項目 | 通過時必須看見的行為 |
| --- | --- |
| 示例／真實分隔 | 模式全程可辨；切換源碼後沒有示例數字、程式或答案混入 |
| 真實接入 | 使用另一組中性程式名的源碼，清單、檔案數及來源均隨資料變更 |
| 增量更新 | 修改、刪除或更換源碼後重新分析，報告對應新快照；不存在的舊程式不再作為當前入口 |
| 接入失敗 | 路徑錯誤、零程式、編碼問題或入口歧義有可理解原因；模型不因接口可用而繞過阻斷 |
| 聯網狀態 | 索引離線執行；問答按鈕明示接口與證據傳送用途，點擊後才啟動模型流程；未配置先顯示設定說明；配置存在不等於能力已驗證 |
| 真實問答 | 答案及引用來自本次服務結果；錯誤、停止、拒答與不完整狀態保留 |
| 證據閱讀 | 引用打開正確來源與行號；缺少資料時顯示缺口，不能顯示固定示例片段 |
| 匯出一致 | 本次問題、答案、引用、快照及邊界能一同保存；失敗時沒有舊成功答案混入 |
| 本機啟動 | 頁面由本機服務提供；Windows 啟動須在實際 Windows 環境另外驗證 |

本地合成資料與模擬接口可以驗證接線、狀態和防止舊資料混入；公司真實源碼覆蓋、實際公司 API、業務問題完整性及生產語義仍需在批准環境驗收。介面不應顯示未經該環境驗證的「已上線」「全庫已理解」或「業務驗收通過」。
