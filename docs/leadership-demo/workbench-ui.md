# 业务分析工作台：界面与验收

更新：2026-09-28。设计保持红、白、深灰商务风格，支持简体中文、繁體中文和 English。内容围绕“接入代码库或选择合成案例 → 提出业务问题 → 连续追问 → 核对依据 → 导出业务说明”。当前验收边界见[当前实现与已知限制](../16-current-implementation-status.md)。

默认页是通用业务对话。申请受理、复核和夜间生效只是一份合成源码上的示例问题，不是系统的业务范围或固定分析路线。选案例后建立一次全库索引，示例问题可修改，切换案例复用索引；发送后可以在同一会话追问。框架类型、程序名和控制方式作为可展开的依据。引用来自本机实际案例文件，行号及摘要动态计算。

“合成源码导读”与“实际模型分析”必须可辨。导读标注未调用模型，不能把编排的说明或元数据声明标为已执行结果。载入案例只建立本地索引，发送问题才调用已配置接口。实际问答走普通聊天返回和按需检索，不以前置工具调用或严格动作 JSON 探测为门槛。

加载后的项目持续标记合成来源，Markdown 与 JSON 导出也保留该信息。旧回答保留在对话历史中，与新问题分开。切换语言只翻译界面和案例作者说明，不改写用户问题、源码、实际模型正文或 API 原文。

本机源码模式支持点击选取源目录与独立输出目录，也可直接输入路径，并保留编码、格式、扩展名与增量缓存。模型连接设置有一次实际简短问答检测；检测不发送源码或框架资料，只验证接口当次能返回非空文字。进度只报告实际阶段、计数、耗时和可估算的 ETA。执行中可取消；未知总量不显示伪进度。

可读业务正文优先展示，缺少 COPY 或生成对象时仍说明可见规则和相应业务影响。引用打开正确快照的文件行；未核验模型推断不会显示为已证明的生产结果。接口或部分段落失败时，已有正文和响应诊断仍可查看。

验收应实际点击三类示例问题、三语切换、源码引用、导出与案例加载，验证第二个问题复用索引且可以接着追问；另以文件变异证明行号、摘要和源码内容会更新，并覆盖等长修改且恢复原 mtime 的场景。该新鲜度回归未修复前不得判定源码变更验收通过。模型连接检测应分别验证非空回答、鉴权失败和空回复。真实模型回答必须来自接口调用，不以导读文本替代。公司源码准确性、完整性与目标电脑性能以现场案例为准。

业务验收以“不懂 COBOL 的业务人员能说明哪些对象被处理、为什么得到这个结果、哪些状态或数据改变、失败后有什么影响”为准。源码读取成功、引用有效或能解释调用顺序，只构成业务分析的基础条件。
