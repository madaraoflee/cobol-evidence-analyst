# 业务分析工作台：界面与验收

更新：2026-09-20。设计保持红、白、深灰商务风格，支持简体中文、繁體中文和 English。内容围绕“选择业务场景 → 提出业务问题 → 看懂规则与结果 → 核对依据 → 导出业务说明”。

默认页以申请受理、复核和夜间生效为主标题，服务于同一条服务申请业务链。正文说明业务用途、办理条件、决策规则、申请状态变化及异常影响。框架类型、程序名和控制方式作为可展开的技术依据。右侧源码来自本机实际案例文件，行号及摘要动态计算。数目取自服务返回，不写死文件、证据或步骤数量。

“合成源码导读”与“实际模型分析”必须可辨。导读标注未调用模型，不能把编排的说明或元数据声明标为已执行结果。“载入此案例”只建立实际索引；“开始业务分析”才调用已配置接口。实际问答走普通聊天返回和源码分段汇总，不再以前置工具调用或严格动作 JSON 探测为门槛。

加载后的项目持续标记合成来源，Markdown 与 JSON 导出也保留该信息。改问题、入口或阅读深度后隐藏上次回答。切换语言只翻译界面和案例作者说明，不改写用户问题、源码、实际模型正文或 API 原文。

本机源码模式继续支持指定目录、编码、格式、扩展名、独立输出目录、轻量目录及增量缓存。进度只报告实际阶段、计数、耗时和可估算的 ETA。执行中可取消；未知总量不显示伪进度。

可读业务正文优先展示，缺少 COPY 或生成对象时仍说明可见规则和相应业务影响。引用打开正确快照的文件行；未核验模型推断不会显示为已证明的生产结果。接口或部分段落失败时，已有正文和响应诊断仍可查看。

验收应实际点击三类案例、三语切换、源码引用、关系、导出与案例加载；另以文件变异证明行号、摘要和源码内容会更新。真实模型回答必须来自接口调用，不以导读文本替代。公司源码准确性、完整性与目标电脑性能以现场案例为准。

业务验收以“不懂 COBOL 的业务人员能说明哪些对象被处理、为什么得到这个结果、哪些状态或数据改变、失败后有什么影响”为准。源码读取成功、引用有效或能解释调用顺序，只构成业务分析的基础条件。
