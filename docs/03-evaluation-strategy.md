# 评估策略：分层定位错误，不用“回答看起来不错”代替质量

> 核心判断：解析、检索和回答必须分别评测。若只看最终答案，我们无法判断失败来自 COBOL 没解析出来、证据没找全，还是 LLM 超出了证据。

状态：`Proposed`  
日期：2026-08-27

## 1. 金标准集

M1 建立两套结构一致、内容隔离的评测集：公开侧使用原创合成保险代码验证通用能力；公司侧使用首批 20–30 个真实问题，由业务专家和熟悉代码的技术人员共同确认。建议覆盖以下结构，而不是只收集容易的“某字段在哪里”问题：

| 类型 | 建议数量 | 必须覆盖 |
| --- | ---: | --- |
| 计算与字段来源 | 6–8 | 多次赋值、条件计算、COPYBOOK、跨程序参数 |
| 条件与例外 | 4–5 | 88 级、嵌套条件、状态、异常和默认分支 |
| 调用与执行路径 | 4–5 | `PERFORM THRU`、`GO TO`、静态/动态 `CALL` |
| SQL、文件与控制表 | 3–4 | 输入来源、更新目标、外部配置依赖 |
| 方言与难例 | 2–3 | 企业宏、预处理、CICS、复杂数据结构 |
| 不可回答与对抗问题 | 3–4 | 业务原因、生产时值、库外逻辑、错误前提 |

每题不能只有参考答案，还必须包含：适用源码快照、入口实体、必要证据节点、必要关系路径、允许的业务推断、必须拒绝的说法，以及专家确认记录。私有评测只在公司环境运行；对外只输出聚合指标和不含公司内容的错误类别。

## 2. 四层评测

### A. 事实抽取层

这一层不调用 LLM，评估源代码是否被正确转换为事实。

主要指标是 Program/Section/Paragraph 识别率、`PERFORM/CALL/GO TO` 关系精确率和召回率、字段读写与参数映射准确率、COPY 展开后的源码映射正确率，以及未解析结构是否被显式报告。动态调用若只能产生候选集合，应评估候选召回，而不能强行按唯一调用计分。

### B. 调查与检索层

这一层分两步评估：先看 Qdrant/符号检索是否把正确实体排进候选，再看 Neo4j 调查是否找到“回答该问题所需的最小完整逻辑闭包”。主要指标包括：

- **Candidate Recall@5/@20、MRR、nDCG@10**：分别衡量是否召回、首个正确入口位置和多相关入口排序质量。
- **Evidence Recall@5**：前 5 个证据包中是否包含人工标注的必要路径；M4 目标 ≥85%。
- **Path Recall**：调用、控制和数据来源的必要边是否完整出现。
- **Evidence Precision**：证据包中真正有用的节点比例，防止把大量无关代码塞给模型。
- **入口排名与调查成本**：正确入口的排名、展开节点数、工具调用次数、证据 token、索引时间、磁盘、峰值内存和 p50/p95 延迟。

“检索到了同名字段”不算成功；若没有证明字段在目标路径上的读写与传递关系，仍是检索失败。

必须按固定阶梯做消融：仅精确符号锚定、仅稀疏词汇、仅 Qwen3 dense、稀疏+dense RRF、再加 Qwen3 reranker、对比 BGE-M3/multivector、再加类型化代码图、最后加证据预算。精确命中的源码符号作为独立锚定通道评测，不与语义候选简单混分。每次只增加一个信号，记录质量增益和资源成本；没有稳定增益的步骤不进入默认路径。

### C. 回答与核验层

最终回答按独立 claim 评分，而不是整体凭感觉打分。每个 claim 标成以下之一：

- 证据直接支持；
- 证据支持但表达范围过大；
- 合理业务推断且已正确标注；
- 缺少证据；
- 与源码冲突。

核心门槛是源码实体和位置虚构为 0、代码事实证据覆盖目标 100%、关键答案完整性、事实/推断/待确认项区分正确，以及面对不可回答问题时能够拒答。BLEU、ROUGE 或语言流畅度只能做辅助观察，不能作为产品通过标准。

### D. 领域恢复层

M7 的业务域发现不能把某一次聚类结果当真相。应使用专家参考架构做 Reflexion 对比，检查收敛、分歧和缺失关系；同时多次运行聚类并计算一致性，再逐一移除调用、词汇、依赖和共变更信号做消融。只有稳定且经过专家解释的候选域，才能进入人工确认的业务语义层。

## 3. 统一证据契约

每次分析至少输出以下结构，字段名可在实现阶段调整，但语义不能丢失：

```json
{
  "analysis_snapshot": {
    "repository_revision": "<commit-or-snapshot-id>",
    "fact_model_version": "<version>",
    "parser_versions": ["<name@version>"],
    "dialect_rules_version": "<version>"
  },
  "claims": [
    {
      "claim": "<业务语言结论>",
      "kind": "code_fact | business_inference | open_question",
      "evidence_ids": ["E-001"],
      "proof_obligation_ids": ["PO-001"],
      "support_status": "supported | partial | unsupported"
    }
  ],
  "evidence": [
    {
      "evidence_id": "E-001",
      "entity": "<program/paragraph/field/statement>",
      "source_file": "<path>",
      "source_range": "<stable range>",
      "content_hash": "<hash>",
      "relation_path": ["<typed edge>"]
    }
  ]
}
```

## 4. 错误分类与改进顺序

所有失败都进入统一错误分类：`parse_miss`、`resolution_miss`、`source_map_error`、`index_divergence`、`retrieval_miss`、`slice_incomplete`、`unsupported_claim`、`claim_overstatement`、`answer_omission`、`stale_evidence`、`scope_leakage`、`wrong_abstention`。

每轮迭代先找占比最高、影响最大的错误层，再修改一个主要变量并重跑完整金标准集。若一次同时更换解析器、切片逻辑和模型，即使分数提高，也无法知道真正有效的是哪一项。

## 5. 阶段门槛

| 阶段 | 必须通过的评测 |
| --- | --- |
| M2 → M3 | 结构识别、调用关系、源码映射和关键方言样本达到门槛 |
| M3 → M4 | Qdrant/Neo4j 双索引键一致、可从 IR 重建；各检索信号完成质量与资源消融 |
| M4 → M5 | 正确证据路径 Recall@5 ≥85%，且图扩展相对纯检索有稳定增益、多跳调查可复核 |
| M5 → M6 | 无虚构源码实体/位置；事实有证据；不可回答集能拒答；专家可用性 ≥80% |
| M6 → M7 | 真实工作负载下质量可复现，权限与审计合格，回归集持续运行 |

评测集应同时保留稳定回归题和每轮新增的盲测题，避免系统只对少量已知问题过拟合。
