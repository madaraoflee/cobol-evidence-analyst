# 框架控制来源与版本契约分别建模

Smart Developer 类框架的业务控制可能来自过程 COPY，而 I/O、数据访问路径和调度含义还依赖版本化外部资料。决定将“原始源码证据、带包含链的派生过程观察、profile 声明、运行验证”分开保存；公开内核及夹具只使用中性名称，私有映射在获准公司环境中加载。把声明直接当执行规则实现更快，但会在缺少控制源码或目标版本资料时制造貌似完整的业务结论。

| 来源 | 接收组件 | 允许输出 |
| --- | --- | --- |
| 原始源码 | 既有结构索引、只读调查工具 | 原始 Evidence 与哈希 |
| 同版宿主 + COPY | 有界展开器 → 框架审查 | COPY 原行 + 宿主包含链的派生观察 |
| 版本 profile | 契约校验 → 框架审查 | 独立标明来源的待验证含义 |
| 获准参考执行与专家答案 | 后续业务验收 | 独立验证记录，不覆盖源码事实 |

F01 不将派生行冒充原始文件行号，也不改变既有 CFG / Agent 的证据标识。代价是派生结构尚需 F02 接入路径引擎，当前报告不能作为完整业务答案。展开不完整时停止过程观察；后续扩语言子集必须附对应反例，不能仅降低拒答门槛。
