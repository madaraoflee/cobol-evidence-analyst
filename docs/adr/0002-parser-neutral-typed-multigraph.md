# 采用解析器中立的类型化多图

系统定义自己的 COBOL 中间表示和证据契约，通过适配器接入 CodeGraph、ProLeap、Tree-sitter 或后续自研解析器；不同问题所需的调用图、控制流图、数据流图、词汇图和演进图保留独立关系类型，不提前压成一张无语义的加权图。这样可以替换解析器、比较关系质量，并针对问题选择正确的图；代价是需要维护统一映射层和关系级验证。

事实权威顺序固定为：版本化原始源码是最终证据，统一 IR 是从源码与可重放规则生成的规范化事实表示，Neo4j 与 Qdrant 是可重建查询投影，Evidence Package 是某次调查的只读选择结果，LLM 输出永远不是代码事实来源。任何投影与 IR 冲突时必须停止回答并重建，不能选择“看起来更合理”的一侧。

## Considered Options

- 直接以某个开源工具的数据模型作为产品模型：起步更快，但一旦缺少动态调用、字段流或企业方言能力，替换成本很高。
- 把所有关系合并为单一相似度图：查询简单，但不同关系回答不同问题，混合后难以解释和评估。
