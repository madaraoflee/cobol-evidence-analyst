# 采用混合 Code RAG，而不是纯向量 RAG

系统先把已验证的精确源码符号作为锚定调查种子，再使用稀疏词汇和稠密语义召回未知候选，通过 RRF 融合和查询—候选联合重排序后，沿调用、控制、字段流和外部数据关系执行图引导程序切片，最终只把版本化证据包交给 LLM。纯向量 RAG 起步较快，但代码块相似度不能证明执行路径、参数传递或计算来源；纯图查询关系准确，却难以把业务语言映射到未知源码名称。混合方案增加了统一 IR 和多索引的实现成本，但能分别评测候选召回、关系证明、上下文预算和答案生成，也避免向量库或 Agent 框架成为不可替换的事实来源。

目标实现栈与降级条件见 [ADR-0006](./0006-adopt-langgraph-qdrant-neo4j-target-stack.md)。
