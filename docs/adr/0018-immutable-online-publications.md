# 在线资料采用不可变发布与显式版本选择

在不新增常驻查询服务器且冻结本地核心的约束下，在线资料按内容地址生成和分包，通过独立存储适配器读取。Downloads 发布先核验固定 Git 版本与分析范围，再上传并回读分包、清单，最后写入不可变 release；客户端明确选定完整 release 后固定其源码 commit 和资料修订。此决定已落实为代码和合成验证，不表示公司存储资格、部署或业务验收已通过。

同步流程与分析任务独立：默认仓库快照模式使用 `online-release/v2`，记录 `sync_completeness: not_verified`，不依赖同事的同步机器或完成凭据。若同步方已有真实完成声明，保留 `online-release/v1` 及其核验方式。两种模式明确选择，发布资料成功不等于上游本周同步全部完成；该边界细化见 [ADR-0019](./0019-index-repository-snapshots-independently-of-sync.md)。

不使用由并发任务覆盖的单个 `latest` 文件。文件托管接口没有提供本实现可依赖的跨对象事务或条件更新，较早版本晚完成时可能覆盖新指针；保留全部不可变 release 并显式选择避免这个回退路径，代价是用户需核对并选择版本。最终写入回执丢失时保留“结果待确认”和确定的 release 名称，不能将网络错误解释为未发布。

小 postings 内联，其他逻辑对象组合成有界分包，减少上传文件数量；逻辑索引身份和摘要不随分包位置改变。分包会多传同包内未命中的资料，因此读者的预算与测量使用实际包字节，不能只报告逻辑对象大小。目录和通用 HTTPS 读取仍使用原始对象格式，生产存储适配可独立替换。

工作区与历史使用独立本机状态，固定版本对话不随新发布迁移。公开入口只复用原 HTTP 鉴权和公司模型配置，不重构本地调查核心。后续增量计算、自动版本选择或发布协议变更需维持上述一致性和回执语义。实现与边界见[在线工作台](../20-bitbucket-online-workbench.md)，测量见[验证记录](../reports/2026-11-07-online-materials/README.md)。
