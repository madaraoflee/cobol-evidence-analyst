# 离线编译框架约定，再绑定具体调用

2026-10-02。用户确认将已知框架约定前移到离线构造链。此前主问答把匹配的手册节录与源码交给模型临时解释，缺口调查却只按目标源码是否存在分类。一个已有明确约定的公共接口仍可能被列作外部资料缺失。

决定区分三类对象：**框架约定**是具体版本资料明确声明的含义；**框架调用解释**是将约定绑定到源码中某次调用、功能赋值和参数的结果；**运行结果**是给定实际输入、数据和环境发生的行为。前两项可以在不调用模型时构建，不自动推出第三项。

```mermaid
flowchart LR
    M[本机版本化手册] --> R[带出处的框架约定]
    S[源码与字段声明] --> B[调用与布局核对]
    R --> B
    B --> I[本地解释缓存]
    I --> V[按本次实际供应材料筛选]
    V --> G[区分已知公共接口与具体缺口]
    G --> A[模型解释业务]
```

本版从显式功能、状态、阶段表编译类型化规则，从明确调用示例和功能字段模式编译接口模板。规则全部来自配置的资料，公开内核不包含机构、产品或供应商标识。编号阶段需要完整名称及其来源，命名相似和资料词面命中不足以覆盖依赖缺口。截断资料、冲突定义、未知接口形式只保留边界。

调用解释要求静态目标、对应参数、明确的局部字面赋值和唯一规则；字段长度、类型、参数组关系还须核对。普通数据 COPY 可以提供声明，但调用者或所引用 COPY 中未解释的替换、条件编译指令不能被忽略。源码已有实现时优先读实现。源码缺失但以上条件成立时，可以解释约定操作，无需要求用户补交公共实现；动态目标、未解析常量、缺失业务公式、运行数据和真实返回值仍各自保留。独立运行契约引擎继续用于明确场景，不因加载自然语言手册就自动执行模拟。

缓存与源码内容、手册集合摘要及解释器版本绑定，存入原有本机 SQLite，不增加网络、模型调用或服务。新增字段声明使稀疏索引升级，需要一次重建；之后按变化复用。完整扫描后的缓存可以支持局部问答；缓存失效或达到条数上限时，对本题稳定副本重新分析完整文件并只保留关注范围，防止漏掉前文替换指令。暂时读取失败不缓存成成功的空结果。

模型请求仍受原有字符和字节预算限制。长程序中远离调用点的参数声明，在原有阅读额度内定点补读；没有额度时不能跳过核对。框架事实、调用赋值、必要声明和手册出处必须共同存活；裁剪任何必要依据后，重新计算依赖缺口。最终结果保存实际作答轮的解释，复审失败保留旧答案时不能套用后一轮的事实。

替代方案是继续加强提示词、让模型每题读手册，或把整本手册转成可执行 I/O 合同。前者不能让离线缺口判断理解公共接口，后者会补造手册没有声明的键、布局和事务行为。因此本版选择确定性约定编译与保守绑定，代价是复杂赋值、动态分派及未支持预处理仍需要后续分析。验收检查真实请求内容和反例；模拟模型响应只证明工程链路，不证明业务答案已在生产环境通过评审。
