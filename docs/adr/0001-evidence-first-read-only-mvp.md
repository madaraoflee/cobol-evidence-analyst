# 第一版采用证据优先的只读业务分析

我们先交付能够回答“在哪里计算、如何计算、数据从哪里来、哪些条件会改变结果”的只读 Agent，并要求每条代码事实绑定源码证据。完整 SDLC 编排或自动改码虽然更吸引人，但会在事实层尚未可靠时放大错误，因此推迟到证据检索和回答核验达到里程碑门槛之后。

## Considered Options

- 纯向量 RAG：开发快，但无法可靠证明调用、控制流和字段流转。
- 一步到位的 SDLC Agent：业务覆盖广，但会把尚未验证的代码理解扩散到需求、设计和变更。

## Consequences

第一版范围更窄，但可以建立后续影响分析、UR/FS/TS 和测试生成共同依赖的可信事实底座。
