# 默认业务答案使用同源事实与逐项核验

默认业务链继续采用 Python 模块化单体和本机 SQLite。轻量索引、局部解析、切片与答案核验使用同一词法和语句事实来源；检索复用语句形态，分析保留每次出现位置。这样纠正底层语义时可以同时修正供证和核验，避免问答层长期维护第二套 COBOL 正则解释器。

结论账本在最终答案出口核对实际供应的版本证据，只对受支持的公式、条件及显式效果发布支持结果。错误陈述根据已核验源码结构局部修正，独立业务解释继续保留；不支持的语义记录为未知。整篇解释、分支可行性和运行值不会因为一条语句匹配便获得完整核验状态。代价是需要维护受支持语义的精确回归，而不是用引用存在或第二次模型判断替代语义支持。

长调查用 SQLite 保存完成步骤、证据、游标、剩余额度和远程请求生命周期。结果未知的请求需要明确处置；已收到的业务正文可以重放本地处理。此契约不宣称 exactly-once。外部解析器通过固定版本、受限本机桥协议转换为中立 IR；办公室默认运行不需要 Java、图数据库、向量服务或本地模型。

## Considered Options

- 继续在问答层修补读写事实：改动较小，但限定字段、同一行语句和异常作用域会在各层产生不同含义。
- 所有答案再调用模型作自评：增加费用和延迟，也无法保证同一个错误公式不会再次被接受。
- 先迁移到新的 Agent 或外部编排框架：运行依赖增加，现有工作台仍可能绕过新核验；因此先在现有默认入口落实契约。
