# 用明确场景驱动框架路径，运行契约不冒充源码

F01 已有 COPY 来源观察，数值错误模型却不能解释文本状态、框架 section 和批次循环。决定复用既有控制流构建器的显式框架模式，在隔离的派生索引上增加条件化路径执行器；原有数值错误接口和模型问答工具保持原契约。源程序存在时进入实际程序体，不能用配置覆盖它；仅对没有源程序实现、且调用布局吻合的显式外部接口应用版本化 I/O 契约。

| 输入 | 进入组件 | 输出性质 |
| --- | --- | --- |
| 宿主 + 控制/数据 COPY | 有界展开 → 临时派生索引 → 既有 CFG 框架模式 | 带原始行和包含链的控制路径 |
| 子程序源码 + USING/LINKAGE | 标量/组布局核对 → 参数带入 → 普通返回回写 | 当前调用帧的实际源码效果 |
| 契约 + 场景记录/故障/检查点 | 到达外部 CALL 时应用有状态模型 | 声明条件下的文件、游标、锁和事务变化 |
| 独立预期 | 报告运行器逐项对照 | 本场景的断言结果，不是通用业务认证 |

本版只推进由已知输入和故障场景确定的一条路径；未知条件停在边界，而不把任意选中的分支当成已证明结果。代价是没有自动穷举所有失败模式，源程序调用也仅按普通调用/返回假设执行。对比扩展旧数值接口，这种隔离增加了一层接线成本，但避免将既有错误断言、普通模型问答和新状态机的证明范围混在一起。

临时源码与索引必须位于批准环境，结束后清理；交付原始来源映射与源/契约/场景哈希，不交付伪造的原始 Evidence ID。版本 profile、状态校验和及检查点一致性都是可复核条件，不是生产运行认证。模型未完成时不得输出“整业务验证完成”；完整路径、所选业务预期通过和生产验证必须分别标示。
