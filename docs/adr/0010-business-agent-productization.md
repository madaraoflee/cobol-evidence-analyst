# ADR-0010：以真实业务回答质量驱动 Agent 产品化

当前本地系统已有 SQLite 全文/结构检索、源码阅读和多轮问答，真实业务回答质量仍未完整验收。第一阶段优先改善业务问题定位、计算与条件上下文完整、Smart COBOL 动作/参数理解和多轮调查，以检索率、关键规则遗漏率、引用支持和 BA 可用性判断成效。编排框架和存储改造由实际失败与性能数据决定，不排在回答质量之前。完整方案见[业务 Agent 演进设计](../18-business-agent-evolution-design.md)。

## 状态与历史关系

本 ADR 保持 **Proposed**，表示长期设计待验证，不表示用户已经批准收费试验，也不表示本文涉及的组件已部署。本轮已授权的可逆开发可以先实现独立部分，其完成与测试单独报告。

本提案更新 [ADR-0005](./0005-hybrid-code-rag.md) 的实施优先级：保留精确标识、全文召回和关系扩展，稠密向量、RRF、重排序按问题集评测增益后加入。它拟替代 [ADR-0006](./0006-adopt-langgraph-qdrant-neo4j-target-stack.md) 对 LangGraph、Qdrant、Neo4j 的统一目标栈承诺。旧 ADR 均保留原文与原状态；本 ADR 未接受前，不将它们追溯改写成已经实施或已经废弃。

## 选择与边界

1. **产品以业务回答质量为先。** 自然语言问题不限于预置主题；默认给业务结论、规则、条件、口径与影响。先补业务定位、必要条件及参数上下文、框架对应和多轮追问，再通过独立真实测试集判断是否有用；安装框架、迁库或测试数量不能替代质量成绩。
2. **知识绑定修订与来源。** 本地目录和未来 Bitbucket Cloud/Data Center 通过来源接口产生修订；源文件、COPY 包含链、关系事实、手册约定和模型归纳分开记录 provenance。缺源码接口保留为图中节点并结合调用方与手册解释，不制造其内部行为。
3. **确定性解析与模型决策分工。** 语法、参数布局和关系提取保留规则代码；资源默认值归入运行策略；私有术语与框架约定外置知识包；示例题特判不得成为生产答案路线。Agent 可以补查源码或框架资料，应用控制访问范围与资源。
4. **本地存储先保留 SQLite，团队部署优先评估 PostgreSQL。** 索引、关系和会话已有数据库实现；部分 JSON 仍承担恢复/控制职责，需显式迁移后才成为纯导出。长 `TEXT` 字段不是泄漏诊断，优先修复全量读取、无界缓存和重复正文，测量持续运行内存。
5. **RAG 与具体库解耦。** 现有全文和结构查询已经构成 RAG；语义向量是可选召回，不能证明调用链。LangGraph 作为可恢复运行候选，只有适配现有工具、降低维护成本并通过恢复测试后启用；Qdrant、Neo4j 不再作为必需部署条件。
6. **沿用公司保密环境，收费仍需批准。** 当前不继续发展新增安全功能，不新增外发目的地；真实收费试验先取得用户同意，调用上限不能替代授权。未来 Bitbucket 和多用户阶段再对接公司已有身份、项目权限和审计能力；不承诺本地存储即可保证没有泄漏。
7. **coding agent 与分析权限分开。** 后续复用知识和检索底座，在隔离工作区生成补丁、编译/测试并展示差异；源码推送、合并和作业执行需要独立权限。当前只读分析不隐含任何写仓库授权。

## 考虑过的替代方案

**直接落地 ADR-0006 全套数据库和编排框架。** 长期可以承载复杂检索，但当前会同时增加进程、备份、迁移、安全和性能定位成本，且没有真实私有业务评测证明收益。保留适配接口，暂不把组件数量当作成熟度。

**纯向量检索加长上下文模型。** 对业务术语发现可能有效，但精确表名、调用参数和影响枚举不能只依赖语义相似度；还增加 embeddings 费用、数据发送范围和索引失效管理。先建立当前基线，实测新增召回是否弥补遗漏。

**继续只扩充固定问题规则与 Prompt。** 开发快，但很难应对新业务术语和跨程序追问，也无法解决恢复、修订一致性和资源无界增长。改为通用工具与框架知识包；Prompt 负责表达和工具选择，不保存公司知识的唯一副本。

**立刻把全部数据迁到 PostgreSQL。** 团队部署有价值，但本地单人安装增加运维负担，也不能自动修复 Python 对象滞留或全库 JSON 加载。先明确权威数据模型与读写接口，在团队访问确有需求时迁移。

## 影响与验证

这一路线保留了已经验证的离线索引与问答资产，使 Bitbucket 接入和后续 coding agent 复用同一来源/知识底座。代价是需要维护修订、关系 provenance、兼容迁移与工具接口，短期也不会自动获得向量召回或成熟编排库的全部能力。

第一阶段先执行设计文档第 3 节的真实问答验收：五类通用任务、开发/独立测试集分离、BA 与开发共同标注关键规则和来源、经费用批准后小批量调用真实模型、逐题区分检索与上下文/框架解释/模型失败。优先看检索率、关键规则遗漏率、引用支持、业务可用性和追问承接，再看耗时与费用。模拟回答不计质量分。

中断恢复、存储迁移和团队权限在其真正影响使用或进入远程/多人阶段时推进；公司已有保密能力作为接入条件，不发展为当前独立项目。离线合成样本、模拟模型以及测试数量不能替代真实业务成绩。
