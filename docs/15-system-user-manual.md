# 业务分析工作台使用手册

更新：2026-09-28。当前主线是通用业务问答：用户输入实际业务问题，由系统自行查找本地代码库中的相关实现。没有固定业务主题清单，演示问题不构成能力范围。

## 1. 准备与启动

Windows 电脑准备 Python 3.10 或更高版本及 Git。项目使用 Python 标准库，不需要额外安装 Python 包。源码和输出建议放在本机磁盘，例如 `D:\cobol-data\source` 和 `D:\cobol-output\analysis`，不要放进公开代码仓库。

首次下载项目：

```bat
git clone https://github.com/madaraoflee/cobol-evidence-analyst.git
cd cobol-evidence-analyst
git config core.hooksPath .githooks
```

已有项目在项目目录执行 `git pull --ff-only` 更新。在项目根目录将 `.env.example` 复制为 `.env`，填写公司接口地址、密钥和聊天模型：

```dotenv
COMPANY_API_BASE_URL=https://approved-gateway.example/v1
COMPANY_API_KEY=填入自己的接口密钥
COMPANY_CHAT_MODEL=填入公司的模型名或部署别名
```

地址要包含公司网关要求的版本前缀；以上值须替换。`COMPANY_API_STYLE` 默认 `openai_compatible`，`COMPANY_EMBEDDING_MODEL` 不是业务问答必填项。`.env` 保存为 UTF-8，Windows 换行和 BOM 均支持；核对文件名不是 `.env.txt`。值中的 `$` 或 `${...}` 按字面保存，不执行或展开。

网页和命令行都读取项目根目录的 `.env`。配置优先级为显式命令行参数、启动进程已有环境变量、`.env`。修改配置后重启工作台；若仍显示旧配置，检查同名环境变量。已有 `.env` 更新代码时保留，不提交到 Git，密钥不传到页面。在“模型连接设置”中点击“测试模型连接”会实际发送一个不含源码、框架资料和业务问题的简短请求，并确认模型返回非空文字；页面只显示检测结果和安全的错误类型。配置状态显示“已提供”仅代表字段齐全，仍应做一次检测。检测成功只证明当前接口能完成这次简短聊天，不代表后续业务答案质量已经通过验收。

私有框架资料可以在“连接设置”中填写文件或目录，点击保存后立即核对“已读取多少份框架文件”以及具体错误。支持子目录中的 `.md`、`.markdown`、`.txt`，包括 UTF-8 和带 BOM 的 UTF-16。Windows 从资源管理器复制的带引号路径和 `%变量%` 路径可识别。网页保存的本机路径优先；未指定时沿用 `.poc-data/framework/reference.md` 或 `.env` 的 `FRAMEWORK_REFERENCE_PATH`。相对路径按项目根目录解析，保留标题、表格及可选的 `SOURCE_PAGE` 页码标记。框架资料不会随公开代码更新分发，换电脑时需单独复制；现有私有资料可继续使用。框架资料和分析产物与源码同级保管。

Windows 双击 `poc/run_web.bat`，或在项目根目录运行：

```sh
python poc/web_app.py --port 8765
```

浏览器打开启动时显示的本机地址。不自动打开浏览器可加 `--no-browser`；端口被占用时用 `--port 8787` 换端口。在“接入本机源码”中点击目录旁的“选择文件夹”，从运行工作台的电脑选取 COBOL/COPYBOOK 目录和独立的输出目录；也可以直接粘贴路径。源目录与输出目录不能互相包含，以免分析结果被当成输入源码。无扩展名成员默认纳入；必要时选择实际编码和 fixed/free 格式。电脑无法弹出系统选取窗口时，继续使用路径输入框即可。

首次接入会扫描全部所选源码，建立轻量结构、调用/COPY 关系、去重的业务语句与字段使用索引，以及全文搜索索引，不调用模型。后续接入核对内容并更新新增、修改或删除的文件。升级到新版索引时会进行一次重建，之后的提问直接复用。文件数量和大小不再使用旧业务路径的固定截断；首次全库读取仍需要实际磁盘时间与存储空间。

工作台支持简体中文、繁體中文和 English；界面语言不改写源码或模型回答。服务只监听本机回环地址，一次运行一个任务。仅启动网页、配置接口或导入资料不会发起模型问答。

## 2. 连续业务对话

接入一次源码后，在对话框输入业务问题并发送。可以直接追问“为什么”“这个失败之后会怎样”，不用重新接入、重复问题背景或选择程序。按 Enter 发送，Shift+Enter 换行。回答和输入框留在同一页面；需要看来源时展开该条回答的引用。

“业务案例”使用项目附带的合成源码帮助演示操作。选择案例后，工作台只建立一次该合成源码的全库索引，示例问题进入可编辑输入框；点击发送才调用模型。切换示例问题不重新扫描同一份源码，随后可以在同一对话里追问，也可以新建对话自由提问。案例导读是预写的操作提示，不能充当模型回答，更不能替代真实代码库验收。

系统复用已有索引，先定位问题直接命中的源码，再沿程序调用、COPY 使用与相邻业务语句扩展调查范围。与问题相关的计算、条件、字段输入和输出会优先提供原文；长调用链末端的规则也可以直接定位，不需要把链上的每一页轮流发送给模型。资料足够时通常只需一次模型请求，确实缺线索时模型才会继续搜索或按行补读；中文问题未命中英文源码时，会先引导模型提出源码检索词。日常问答不会重新扫描整个目录。当前实现是本地全文、结构关系和业务语句结合的检索，不依赖额外的向量数据库或嵌入模型。

一轮问答目前最多进行五次模型往返，最后一次整理已有资料，避免无限补查；这不是固定业务主题或整库页数限制。模型速度、问题复杂度和接口响应仍影响耗时，页面显示当前真实阶段，不使用逐页百分比冒充完成程度。

左侧“新对话”开始独立话题，“分析记录”恢复既有对话。完整消息保存在输出目录的 `conversations.sqlite`；浏览器刷新或重启本机服务后可恢复。发送给模型的上下文保留近期消息及较早问题摘要，历史原文不会从本地记录中删除。新对话不继承其他对话背景。

源码新增、删除或修改后，用“接入源码”更新同一输出目录。平时只核对本轮命中文件的大小和时间信息；如果变更内容与索引不一致，就提示更新相应源码，不拿旧文本当现状。不会为发现新文件而在每次提问时遍历全目录。需要逐文件强制核验时在接入中选择内容校验。

## 3. 框架公共程序缺源码时

缺少被调用对象源码不是整份问答的前置障碍。系统读取调用者中的触发条件、功能码、传入业务字段与返回后的分支，并从实际框架资料匹配约定行为。框架资料跨本次相关的多个程序和 COPY 检索。

答案应先解释已知业务。只有确实影响当前问题的未知实现、参数值或运行数据才简短说明，不堆叠泛化的“证据不足”或技术校验状态。框架约定可以支持行为解释，但不能被写成已经执行成功或不存在的闭源代码。

## 4. 阅读答案与调查过程

业务答案是对话主体。每条回答可展开相关源码清单、源码引用和框架依据；源码清单用于继续调查，具体业务判断以引用的原文为准。历史引用绑定当时的源码快照；源码版本更新后，不会错误跳转到新版本同一行。当前模型回复、检索信息和具体错误放在次级详情中，不占据对话正文。

“API 返回”仍保留接口诊断。401 表示接口鉴权失败，403 表示服务拒绝访问，超时说明本次接口未及时返回；这些都与缺少业务源码不同。回答失败或取消后，对话与索引保留，可以继续发送。

对话页面固定使用按问题调查。旧“完整业务链”逐页解读保留为命令行兼容能力，但不再作为页面提问选项；它会产生大量模型请求，不适合日常业务问答。

完整结果保存在输出目录；大报告的网页展示副本仍保留来源与省略信息。全库索引、命中片段和模型实际使用的内容是不同范围，不能用命中数量证明答案完整。

## 5. 命令行

```bat
python poc\analyze_source.py ^
  --index-mode catalog ^
  --source "D:\cobol-data\source" ^
  --output "D:\cobol-output\analysis" ^
  --question "这里输入实际业务问题" ^
  --allow-network
```

不传 `--entry` 即全库调查。省略问题和 `--allow-network` 可以只做本地接入。命令行默认业务模式；Python 库和旧底层调查器保留严格模式默认值以兼容历史调用，程序化使用时传 `analysis_mode="business", reading_strategy="retrieval"`，连续对话历史通过服务端保存。

主要产物包括 `diagnosis.json`、`programs.json`、`framework-context.json`、`agent-result.json`、`agent-result.md` 、`conversations.sqlite` 和本地源码索引。取消后可以继续对话；中断的模型请求本身不会自动续传。

编码或格式已知时可加 `--encoding gb18030`、`--source-format fixed` 或 `--source-format free`；使用 `--exclude-extensionless` 排除无扩展名文件，或用 `--extensions ".cbl,.cpy,.member"` 指定完整扩展名集合。默认 `auto` 适合先接入，再核对源码是否正确显示。

`--index-mode catalog` 在当前默认业务模式、无入口时仍会建立全库业务结构与全文索引，不是旧手册所说的只读取文件头。显式入口分析和旧严格模式继续保留原有兼容路径。

## 6. 当前交付与后续接入

当前接入来源为本地目录。AS400、Bitbucket 接入及真实作业调度关系属于后续能力，没有在本轮伪装为已实现。分析没有固定业务分类；本地测试检验跨语言检索、任意新概念、继续搜索、跨程序阅读和缺源码仍回答的执行流程。实际模型答案的相关性、完整性和准确性仍需使用公司接口与真实业务问题验收。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| `python` 或 `git` 找不到 | 安装后重新打开终端，确认程序已加入 PATH。 |
| 接入时间较长 | 首次业务接入扫描全库。查看当前文件和索引进度，复用同一输出目录；不要把建立索引与模型业务阅读混为同一步。 |
| 缺少 COPY 或框架公共程序源码 | 可以继续提问。系统结合已有源码和实际框架资料解释业务，只保留相关未知事项。 |
| 框架资料未加载或没有匹配 | 在连接设置检查实际资料路径、已读取文件数和错误；目录可直接使用，无词项匹配时仍提供资料背景，不等于加载失败。 |
| 框架资料或源码更新后仍看到旧答案 | 重新接入并发起分析；旧答案绑定当时的内容快照。 |
| 源码在索引或分析中发生变化 | 等同步/复制完成后重试，避免把不同版本的行号混入答案。 |
| 配置已填写但仍显示未提供或旧值 | 核对根目录 `.env`、实际文件名和三项必填值，检查环境变量，重启服务，再在“模型连接设置”测试。 |
| 模型连接检测失败 | 看页面显示的配置、鉴权、超时或空回复类型；检查 `.env` 和网关权限。检测只发送简短中性问题，不会发送源码。 |
| 点击“选择文件夹”没有弹出窗口 | 确认工作台运行在有桌面的本机登录会话；服务器无图形桌面时可直接粘贴完整路径。 |
| 出现 `AGENT_SAFETY_STOPPED` | 打开“API 返回”看具体停止原因与已有正文，区分鉴权、接口错误和旧严格协议问题；不能只按汇总代码判断为证据不足。 |
| 页面显示会话失效 | 刷新页面；必要时关闭并重新启动本机服务。 |
| 结果体积很大 | 网页使用展示副本，完整结果仍在输出目录；省略范围显示在页面，不会静默丢掉原报告。 |

索引就绪表示可以开始调查；生成业务答案表示本次已完成或部分完成阅读，不能代替业务专家对实际答案的核对。模型回复即使格式不规范也尽量保留正文；引用指向当前源码、接口鉴权和文件完整性仍需保持正确。

## 8. 开发验证与维护

修改代码后运行：

```bat
python -m unittest discover -s poc\tests -p "test_*.py" -q
node --test poc\tests\*.test.cjs
```

2026-09-27 本地回归：1005 项 Python 测试、72 项页面测试通过，覆盖模型连接检测、目录选择、合成案例索引复用和连续追问，以及持久对话、长程序深部引用、按需补查与框架资料加载。81 文件合成库连续三次检索不遍历源码目录、不打开源码正文。连接检测向当前配置的接口发送了不含源码的中性请求，实际返回 HTTP 401；未取得模型答案，因此不报告真实问答耗时达标或真实业务准确性达标。

开发者提交前核对 `git status`，确保真实源码、密钥、框架原文和分析产物没有进入公开仓库。本仓库已有提交后自动推送钩子；启用 `.githooks` 后，提交会尝试推送当前分支。只在明确准备提交和发布代码时执行提交。

后续说明直接更新本手册、README 和对应现有章节，保持唯一操作入口；不要为每次改动增加重复手册或日期报告。

当前对话功能使用本机 SQLite 保存会话、消息、来源引用和索引快照。首次接入建立索引；日常追问复用索引，只核对命中的文件，源码变化后重新接入即可。一般问题可直接回答，需要时再执行有限的本地搜索或源码补读；历史文字只帮助理解追问，不能代替本轮源码证据。真实接口返回 401、中文业务词无法命中英文源码等情况，应在页面的 API 返回和本次查找区域核对，不能把本地模拟响应当成真实业务验收。
