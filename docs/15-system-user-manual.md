# 业务分析工作台使用手册

更新：2026-09-21。当前主线是通用业务问答：用户输入实际业务问题，由系统自行查找本地代码库中的相关实现。没有固定业务主题清单，演示问题不构成能力范围。

## 1. 准备与启动

Windows 电脑准备 Python 3.10 或更高版本及 Git。项目使用 Python 标准库，不需要额外安装 Python 包。源码和输出建议放在本机磁盘，例如 `D:\cobol-data\source` 和 `D:\cobol-output\analysis`，不要放进公开代码仓库。

首次下载项目：

```bat
git clone https://github.com/madaraoflee/cobol-evidence-analyst.git
cd cobol-evidence-analyst
git config core.hooksPath .githooks
```

已有项目在项目目录执行 `git pull --ff-only` 更新。在项目根目录将 `.env.example` 复制为 `.env`，填写公司接口地址、密钥和聊天模型：

```dotenv
COMPANY_API_BASE_URL=https://approved-gateway.example/v1
COMPANY_API_KEY=填入自己的接口密钥
COMPANY_CHAT_MODEL=填入公司的模型名或部署别名
```

地址要包含公司网关要求的版本前缀；以上值须替换。`COMPANY_API_STYLE` 默认 `openai_compatible`，`COMPANY_EMBEDDING_MODEL` 不是业务问答必填项。`.env` 保存为 UTF-8，Windows 换行和 BOM 均支持；核对文件名不是 `.env.txt`。值中的 `$` 或 `${...}` 按字面保存，不执行或展开。

网页和命令行都读取项目根目录的 `.env`。配置优先级为显式命令行参数、启动进程已有环境变量、`.env`。修改配置后重启工作台；若仍显示旧配置，检查同名环境变量。已有 `.env` 更新代码时保留，不提交到 Git，密钥不传到页面。

私有框架 Markdown 默认放在 `.poc-data/framework/reference.md`；也可在 `.env` 使用 `FRAMEWORK_REFERENCE_PATH` 指定本机文件。相对路径按项目根目录解析，支持 UTF-8 Markdown 标题、表格及可选的 `SOURCE_PAGE` 页码标记。框架资料不会随公开代码更新分发，换电脑时需单独复制；现有私有资料可继续使用。框架资料和分析产物与源码同级保管。

Windows 双击 `poc/run_web.bat`，或在项目根目录运行：

```sh
python poc/web_app.py --port 8765
```

浏览器打开启动时显示的本机地址。不自动打开浏览器可加 `--no-browser`；端口被占用时用 `--port 8787` 换端口。选择本机源码，填写 COBOL/COPYBOOK 目录和独立的输出目录。源目录与输出目录不能互相包含，以免分析结果被当成输入源码。无扩展名成员默认纳入；必要时选择实际编码和 fixed/free 格式。

首次接入会扫描全部所选源码，建立轻量结构与全文搜索索引，不调用模型。后续接入核对内容并更新新增、修改或删除的文件。文件数量和大小不再使用旧业务路径的固定截断；首次全库读取仍需要实际磁盘时间与存储空间。

工作台支持简体中文、繁體中文和 English；界面语言不改写源码或模型回答。服务只监听本机回环地址，一次运行一个任务。仅启动网页、配置接口或导入资料不会发起模型问答。

## 2. 直接提问

保持调查范围为“整个代码库 · 自动查找”，输入业务问题，再点击“开始业务分析”。用户不需要预先知道程序名、字段名或入口。问题可以使用自然语言，内容不限于示例中的业务主题。

如果已经知道希望聚焦的程序，可以选择入口；这属于可选的范围限定。旧分析记录中的显式入口会恢复，可以重新切回全库自动查找。

系统先从本地源码全文查找，再通过已配置的模型理解问题与实际检索片段，补充同义词、标识符和后续线索。最多三轮检索细化后读取选定源码；规划建议允许普通文字和常见列表/JSON包装，不要求旧 Agent 动作协议。规划临时失败时回退本地查找；无词项命中时继续全库阅读。

匹配到程序或 COPY 后，继续调查调用者、被调用程序及共享定义。仅从依赖中遇到的公共 COPY 不会自动把所有其他业务拉入；公共节点的大量反向候选另行保留供核对。全文命中文件不按模型片段展示数量截断。

## 3. 框架公共程序缺源码时

缺少被调用对象源码不是整份问答的前置障碍。系统读取调用者中的触发条件、功能码、传入业务字段与返回后的分支，并从实际框架资料匹配约定行为。框架资料跨本次相关的多个程序和 COPY 检索。

答案应先解释已知业务。只有确实影响当前问题的未知实现、参数值或运行数据才简短说明，不堆叠泛化的“证据不足”或技术校验状态。框架约定可以支持行为解释，但不能被写成已经执行成功或不存在的闭源代码。

## 4. 阅读答案与调查过程

- 业务说明优先展示，相关引用可以回读当前源码和框架片段。
- “本次查找”显示实际检索词、命中文件、本次纳入文件和需要继续核对的候选。
- “依据与补充说明”收纳实际阅读缺口、未解析目标和来源信息，默认不占据正文。
- “API 返回”保留接口诊断和已返回的正文，便于区分连接、鉴权、模型格式与分析过程。
- “完整业务链”连续分批读取本次调查范围；12/48 段是批次大小。“按问题重点阅读”则是有限选读。

全库已建立索引、本次选中多少文件、实际得到多少页解读分别统计。检索命中是业务线索，不能仅凭同名字段认定实际共享数据或业务因果。

大结果完整保存在输出目录。超过网页直接读取容量时，系统生成与原报告哈希对应的展示副本，保留正文、来源和覆盖信息，并显示省略项；不把展示裁剪计作已完成分析。

## 5. 命令行

```bat
python poc\analyze_source.py ^
  --index-mode catalog ^
  --source "D:\cobol-data\source" ^
  --output "D:\cobol-output\analysis" ^
  --question "这里输入实际业务问题" ^
  --allow-network
```

不传 `--entry` 即全库调查。省略问题和 `--allow-network` 可以只做本地接入。命令行默认业务模式；Python 库和旧底层调查器保留严格模式默认值以兼容历史调用，程序化使用时传 `analysis_mode="business"`。

主要产物包括 `diagnosis.json`、`programs.json`、`framework-context.json`、`agent-result.json`、`agent-result.md` 和本地 SQLite 索引。取消后可以重新发起；当前不承诺恢复中断的模型请求或免除重新阅读费用。

编码或格式已知时可加 `--encoding gb18030`、`--source-format fixed` 或 `--source-format free`；使用 `--exclude-extensionless` 排除无扩展名文件，或用 `--extensions ".cbl,.cpy,.member"` 指定完整扩展名集合。默认 `auto` 适合先接入，再核对源码是否正确显示。

`--index-mode catalog` 在当前默认业务模式、无入口时仍会建立全库业务结构与全文索引，不是旧手册所说的只读取文件头。显式入口分析和旧严格模式继续保留原有兼容路径。

当前接入来源为本地目录。AS400、Bitbucket 接入及真实作业调度关系属于后续能力，没有在本轮伪装为已实现。分析没有固定业务分类；本地测试检验跨语言检索、任意新概念、继续搜索、跨程序阅读和缺源码仍回答的执行流程。实际模型答案的相关性、完整性和准确性仍需使用公司接口与真实业务问题验收。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| `python` 或 `git` 找不到 | 安装后重新打开终端，确认程序已加入 PATH。 |
| 接入时间较长 | 首次业务接入扫描全库。查看当前文件和索引进度，复用同一输出目录；不要把建立索引与模型业务阅读混为同一步。 |
| 缺少 COPY 或框架公共程序源码 | 可以继续提问。系统结合已有源码和实际框架资料解释业务，只保留相关未知事项。 |
| 框架资料未加载或没有匹配 | 核对路径、UTF-8 编码及资料是否已复制；没有匹配仅表示本次未找到可引用章节，不阻断已有源码分析。 |
| 框架资料或源码更新后仍看到旧答案 | 重新接入并发起分析；旧答案绑定当时的内容快照。 |
| 源码在索引或分析中发生变化 | 等同步/复制完成后重试，避免把不同版本的行号混入答案。 |
| 配置已填写但仍显示未提供或旧值 | 核对根目录 `.env`、实际文件名和三项必填值，检查环境变量，重启服务。 |
| 出现 `AGENT_SAFETY_STOPPED` | 打开“API 返回”看具体停止原因与已有正文，区分鉴权、接口错误和旧严格协议问题；不能只按汇总代码判断为证据不足。 |
| 页面显示会话失效 | 刷新页面；必要时关闭并重新启动本机服务。 |
| 结果体积很大 | 网页使用展示副本，完整结果仍在输出目录；省略范围显示在页面，不会静默丢掉原报告。 |

索引就绪表示可以开始调查；生成业务答案表示本次已完成或部分完成阅读，不能代替业务专家对实际答案的核对。模型回复即使格式不规范也尽量保留正文；引用指向当前源码、接口鉴权和文件完整性仍需保持正确。

## 8. 开发验证与维护

修改代码后运行：

```bat
python -m unittest discover -s poc\tests -p "test_*.py" -q
node --test poc\tests\*.test.cjs
```

2026-09-21 本地回归：955 项 Python 测试、59 项页面测试通过。检验的是调查流程、源码与引用一致性、缺源码处理和界面行为；模型调用使用模拟接口，不代表公司 API 及真实业务答案已验收。

开发者提交前核对 `git status`，确保真实源码、密钥、框架原文和分析产物没有进入公开仓库。本仓库已有提交后自动推送钩子；启用 `.githooks` 后，提交会尝试推送当前分支。只在明确准备提交和发布代码时执行提交。

后续说明直接更新本手册、README 和对应现有章节，保持唯一操作入口；不要为每次改动增加重复手册或日期报告。
