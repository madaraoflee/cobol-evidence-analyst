# 公司 Windows 验收包

这套包验收已经冻结的 Windows EXE，不重建或替换它。辅助工具已带运行时，公司电脑无需安装 Python、Git 或编译器。先完成本机离线回归，再运行真实模型，最后逐题核对。缺项和未查清的 PARTIAL 均不能正式发布。

1. 将 `COBOLWorkbench-office-acceptance-windows-x64.zip` **完整解压**到新目录，双击 `OfficeAcceptanceKit/START-ACCEPTANCE.cmd`。保留 DLL、Tcl/Tk、源码、合同和候选包文件。报告目录选择另一个本地目录，不能放在验收包或源码内。公司限制运行未签名程序时，按公司已有软件运行流程处理。
2. 点“生成无网络计划”，核对原 EXE 提交、包哈希、**38 个真实问答轮次、最多 114 次模型请求**。先不选择密钥、不调用接口。套件包含以前的语义/公式/覆盖/调用链/公开业务反例，以及组内裸字段、IN 限定别名、同名字段歧义、三轮覆盖追问、原页/账户汇总三轮指代问题和五轮大库问题；新增两题检查 CL 批次提交、库列表、文件覆盖及长文件靠后调用；全部问答在冻结的 **12,050 文件**目录上运行。公开 CardDemo 有固定版本和许可；合成数据不代表企业方言或真实生产记录。
3. 点“本机离线回归”。它会启动原 EXE，在这台电脑重新执行 25 案例、79 样本及样本内新增的范围、组字段、调用来源检查，包括批次与在线业务概览、限定两次请求的业务语义修订，使用本机 HTTPS 合成接口，**零远程模型请求**。等待完成后保留 `COMPILED-ACCEPTANCE.json`；窗口自动选择本次报告。失败先处理本地报告所指问题，不能把 CI 报告当作公司电脑报告。大库导入和全套回归可能需要十余分钟，单题会记录耗时与停止原因。
4. 选择本机获准的 `.env` 公司模型配置文件和需要的 CA 文件；密钥只在电脑上选择，**不要贴到聊天或上传**。需要时选择已有编译配置 JSON。检查当前获准接口、材料发送范围和预算，勾选本地授权，再点真实执行。默认单题验收目标与整题硬截止均为 120 秒、p95 目标 60 秒、关键供证召回 100%；持续返回的内容也不会延长整题期限。到期停止继续调查，记录已得到的正文、用时和停止原因；截止时尚未完成的回答不能视为验收通过。这些是运行前冻结的验收目标，尚不是公司模型基线或达标结论。需要调整目标或预算时由维护者在调用前生成新冻结计划，不能在看过结果后改门槛。工具没有额外 ping，不自动重试；远程结果不确定会停下并保留请求记录，不要直接重复收费运行。
5. 真实问答完成后，打开逐题评审。对照**实际回答、实际供应源码和逐条金标准**，分别记录关键结论 met/omitted/incorrect、错误新增结论是否出现、业务可用性及追问连续性。窗口直接显示本次模型请求归档的源码/框架节录、证据 ID、行段和哈希，冻结金标准源码另列；不能把金标准或后来修改的源码当作本次实际供证。每个 PARTIAL 必须选择具体分类、填写原因和受影响结论 ID，核清哪些事实独立成立、哪些部分仍未知；“已查清”不能代替关键结论正确。单纯填满表单不表示达标。六项办公检查也要实际操作后逐项确认：桌面窗口、导入、会话重启恢复、取消后恢复、原版本历史证据、真实公司接口及 CA。可从向导打开本次隔离工作台查看回答和引用；取消/重启沿用本次验收目录，不覆盖日常配置。企业源码/企业方言需要另加获准目标题和冻结配置，不能靠公开样例代替。
6. 保存评审，查看 `LOCAL-RELEASE-GATE.json`。只有候选原生回归、同机现场回归、全部真实问答/评审、供证、速度及六项现场检查都通过，才可能得到 `publish_allowed=true`。辅助工具本身不会上传或发布。维护者仍须通过 `tools/publish_desktop_release.py` 重算同包门禁并核对 GitHub 草稿资产，再正式发布。

报告目录含回答、源码节录、运行日志及用于隔离会话的配置副本，只留在获准环境。不要把整个目录上传 GitHub。可先将窗口显示的错误代码和不含密钥的验收决定交回维护者；原始材料与评审是否可移出仍按现有公司授权处理。未完成真实模型/现场验收时，保留候选，不替换正式版本。

现场重启与历史证据检查使用副本：将包内 `sources/synthetic/overwrite.cbl` 复制到包外新建的 `manual-source` 文件夹，在向导打开的隔离工作台中导入这个文件夹。在已有获准预算内询问 `OVERWRITE-CASE 在 FLAG=1 时，OUT-AMOUNT 和 FINAL-AMOUNT 怎样变化？`，保留答案及其源码引用。然后用记事本把副本的 `MOVE 0 TO OUT-AMOUNT` 改为 `MOVE 7 TO OUT-AMOUNT`，以 UTF-8 保存并刷新索引；打开旧答案的引用，应仍显示原版本的 `MOVE 0` 及原哈希。关闭并从同一向导入口重开工作台，再检查对话、原问题和旧引用恢复。不要改验收包内的冻结源码，也不要用新答案给旧答案评分。

取消检查在工作台实际操作：优先在明确尚未发出模型请求的准备阶段取消，再确认可以继续操作。如果取消时请求已经发出，查看本地运行记录；远程结果不确定必须保留不确定状态，不能自动重发。手动题和取消实验只在既有获准预算内进行；没有额外调用授权时保留该项未验收。上述操作完成后才逐项确认对应现场检查，不用自动回归的通过状态代填。

114 次是自动题集的请求上限。打开隔离工作台本身不发模型请求；手动另问、取消及恢复实验可能产生额外请求，只在既有获准预算内操作，远程状态不确定时不得自动重复。

维护命令和门禁合同见仓库 `docs/joint-release-acceptance.md`。跨构建取得冻结候选产物使用 [GitHub 官方 download-artifact](https://github.com/actions/download-artifact/blob/v7/README.md) 的 run-id/artifact-ids 接口；辅助工具采用 [Nuitka standalone](https://nuitka.net/user-documentation/user-manual.html) 并在 Windows 实际启动 Tk 自检，使用者不需要打包工具。

本轮更新保持工作台现有交互。本地只补充本题实际供应源码中的遗漏事实，不增加远程校核请求；CL 的命令声明与实际作业、对象或覆盖生效分别说明。使用旧工作区时，通过现有“更新源码”操作升级索引，保留原对话和历史证据。新建验收目录运行本轮候选，不覆盖上次冻结报告；新答案与新提示版本须重新评分。
