# 按完成度推进的多轮业务分析

默认业务问答围绕同一个原始问题，交替执行源码检索、按行补读、回答和缺口复核。下一轮可携带上一轮草稿及未完成事项，并继续调用读取工具。草稿本身不成为源码证据；引用仍须对应实际供应的文件版本与行范围。

## 大源码如何跨轮累计

默认使用显式的 `prior_source_memory` 携带早先已读源码对应的候选解释。它既可来自带引用的回答段落，也可来自补查工具请求附带的 `findings`。因此，尚未生成完整草稿的工具轮也能保存发现。`findings` 必须伴随补查动作，不能单独充当最终答案，也不会作为工具 JSON 展示在回答预览中。调查模式、源码记忆与预算独立：设置有限请求次数仍保留记忆；维护者可用 `source_memory_enabled` 单独关闭。

每条记忆绑定原始问题、调查运行及上下文，并记录实际发送源码的请求、文件版本、行范围、片段内容和 COPY 包含及替换上下文。未实际发送的源码、未知引用或仅由工具名称暗示的内容不能获得引用资格。记忆中的解释始终标记为未经核验的候选，不会因重复传递而变成源码事实；后续读到的新逻辑仍可要求修改早期结论。

早期源码退出当前原文窗口后，只有明确列入当前模型请求的有效记忆才能继续授权其历史引用。请求大小不足时按整条记忆裁剪，被裁掉的记忆不再提供引用资格；仍在当前原文中的引用按原文处理。系统不会把所有历史读取记录自动视为本轮可用依据，也不保证任意多的内容都能一直保留。最终核验重新读取并检查原始证据归档，归档缺失或校验失败时撤销相应历史引用。恢复调查还会核对源码及 COPY 来源版本，版本变化需要开始新的调查。

当前记忆仅承载源码页引用。同一候选段落混用框架资料与源码引用时，整段不进入记忆；框架资料继续遵守当前请求的供应规则。历史记忆也不会把当前源码覆盖率直接提升为全文已供应。默认质量诊断保存记忆及来源的指纹和元数据，不保存候选正文；只有显式开启上下文捕获时才额外记录完整记忆快照。

## 默认何时结束

标准模式不设置固定整题截止时间，默认共享 6 次模型请求额度，最多 5 个调查轮、2 次无新证据的定向修订。计划、调查、综合、复核、输出续接和重试均计入请求额度。有新的有效材料或需要纠正的具体业务解释且预算允许时继续调查；资料已足够时直接交付，不等待额度耗尽。相同材料、相同缺口反复出现，或补查持续没有有效进展时，整理现有结论和具体未知项后结束。重复或调整同一缺失断言的排列顺序不算新进展。

用户可随时取消。接口错误、无活动超时等仍会停止当前请求；不自动重发结果未知的远程请求。取消本地等待不代表服务端一定停止处理或计费。源码片段大小、单轮工具调用及本地分析资源仍有独立预算；新默认没有取消这些资源保护。

本地语义分析也不再默认用首轮 3 秒、累计 15 秒决定是否跳过。Windows 回归曾在一个完整的 12 行文件上触发这个门槛，使必要语义范围没有进入请求；这属于供证缺陷。默认按最多 32 个语义文件、32 MiB 原始源码、4 次扩展、12 组证据及每轮 2 项语义动作推进，仍检查取消和显式整题期限。上述数量限制不是响应时间承诺；慢环境下不能仅因经过几秒便把已选材料当作缺证。

接口连接建立与非流式响应继续遵守请求超时。对支持的 SSE 流，收到有效生成活动会续期无活动超时；仅心跳、注释或空白不续期。接口提供的非空推理活动也可维持连接，但其内容不进入预览、答案或诊断，也不作为业务调查取得进展的依据。隐藏推理另受请求输出额度乘以 16 的 Unicode 字符上限约束；这不是精确 token 计量，也不是另一项总时间截止。超限停止本地读取，保留已收到正文并将未完成的远端请求记为结果未知，不自动重发。显式设置整题硬期限时，流式活动不能延长它。具体行为仍受网关是否支持流式返回影响。

断线重连或恢复沿用同一调查的请求账本以及原来显式设置的期限，已消耗的时间、断线时间与请求不会清零。只有已收到但未处理的完整响应可以本地重放，结果未知的请求不自动重发。原调查额度耗尽且不存在结果未知的请求时，用户主动重试可开始新的有限调查，保留原记录及关联；这与自动重连延续原调查不同。

## 页面进度和答案

页面可展示正在定位、补读、复核等进度，以及生成中的草稿预览。预览可能尚未完成引用、完整性和局部语句检查，也可能被后续修订替换，不能当作最终结论。工作完成后以正式保存的答案及其引用、状态和限制为准。

应分别看待三个问题：源码是否实际供应给模型、答案是否解释了所问业务点、解释是否获得语义核验。前两项改善不意味着第三项已经完成。系统不能保证任意 COBOL 方言、动态调用、运行配置和完整业务路径均被正确解释；普通自然语言判断仍可能有遗漏或错误。`ANALYZED` 不表示所有业务结论已经证明正确。

## “源码缺失”应如何理解

| 状态或现象 | 含义 |
| --- | --- |
| 文件已在目录或索引，但尚未阅读 | 还需要检索或读取；不能据此判断文件缺失。 |
| 文件已读取，但本轮只发送部分行 | 请求大小或材料选择限制了模型可见范围；不表示本地源码不完整。 |
| 早期原文已退出当前窗口，但仍有有效的显式记忆 | 可保留该记忆绑定的历史引用；不表示本轮重新发送了全文，也不代表候选解释已获语义证明。 |
| `verified` | 所选物理源码通过版本与内容检查；不证明业务执行结果。 |
| `unresolved` | 动态目标、多个候选或其他绑定条件尚未解析；不表示实现文件不存在。 |
| `not_found` | 静态目标在当前索引中未定位；范围是当前索引，不是整个磁盘或企业源码库。 |
| `outside_investigation` | 已知目标不在本次读取范围内。 |
| `excluded` | 文件验证失败或无法按当前快照读取，其文本和引用不能使用。 |

只有实际查证后才能声称物理文件不存在。单一根文件全文已供应，也不能推导依赖实现、整个代码库或运行资料都齐全。系统会检查与实际供应原文矛盾的源码缺失断言，并保持上述区别。

## 已有配置如何采用新默认

旧部署中显式保存的更严格值仍生效，例如 `max_model_requests: 5` 和 `max_question_seconds: 120` 不会被升级扩大。缺省或 `null` 的整题时间配置不设置整题截止，请求次数缺省或 `null` 仍为 6 次。明确写入的 120/180 秒继续生效，不猜测该值的来源；要采用无固定总时限的新问题策略，可明确将两个整题时间字段改为 `null`。这不会给旧调查重置已消耗的额度。自定义路径由 `AGENT_SETTINGS_PATH` 指定；未指定时使用应用默认数据目录。页面在每个新问题开始时重新读取配置。

若曾复制旧模板，还需检查 `max_initial_context_seconds` 与 `max_local_analysis_seconds`：明确保存的 `3`／`15` 继续生效，因为无法区分旧模板与有意设置。删除这两个字段或改为 `null`，才采用新的默认行为。系统不会自动改写用户设置、旧运行记录或请求账本；没有设置文件的部署直接使用新默认。显式本地时限仍是可选资源限制，触发时保留已读源码并记录具体限制，不能把被跳过的语义阶段标成完整。

```json
{
  "version": 1,
  "agent": {
    "max_model_requests": 6,
    "max_question_seconds": null,
    "hard_question_seconds": null,
    "delivery_target_seconds": null,
    "max_initial_context_seconds": null,
    "max_local_analysis_seconds": null,
    "investigation_mode": "adaptive",
    "source_memory_enabled": true,
    "max_investigation_rounds": 5,
    "max_no_evidence_revisions": 2,
    "finalization_reserve_seconds": 45
  }
}
```

`max_question_seconds` 与 `hard_question_seconds` 只在显式设置时生效，取更严格的有限值并保留原有最多 300 秒的配置上限；此时才使用 45 秒收尾预留及近期模型等待来提前综合。两项均为 `null` 时按证据进展、回答完成度和调用次数收敛。接口请求超时、密钥、模型配置、单轮材料和输出限制仍分别生效。`investigation_mode` 支持 `adaptive` 与 `single_pass`，预算不会隐式切换调查行为。

`delivery_target_seconds` 是可选交付目标，缺省或 `null` 时沿用显式本题期限；总期限也为空时则没有时间目标。单独设置它只指导收尾，不产生硬截止。它只让调查更早收尾，不取消已经发出的请求，也不能延长硬期限。例如总预算 120 秒、交付目标 1 秒时，1.25 秒返回的首答仍可接收；总预算本身设为 1 秒时仍须在 1 秒截止。交付目标不得被误写到 `max_question_seconds` 中；恢复任务仍保留已消耗时间和原先更早的截止点。

`max_answer_revisions` 保留旧的 `0/1` 配置格式，不把新值 `2` 写入旧字段。旧 `0` 继续关闭无新证据修订，旧 `1` 保守限制为最多一次；未设置旧字段时采用 `max_no_evidence_revisions` 的默认两次，二者并存时取更严格值。修订必须指出已供应材料中要补全或纠正的具体内容。输出长度限制触发续写后，拼接后的正文仍须经过同一质量复核；续写与修订共享模型请求总额度。

## 验证与发布范围

多轮调查及跨轮记忆的离线验证入口如下，可在仓库根目录运行：

```bash
python -m unittest poc.tests.test_completion_driven_chat poc.tests.test_prior_source_memory poc.tests.test_prior_source_memory_chat poc.tests.test_quality_trace_memory poc.tests.test_findings_preview_boundaries -v
```

`test_prior_source_memory_chat.py` 使用真实索引和材料预算覆盖早期源码自然退出窗口后的草稿、工具发现继承及无有效记忆的边界。其他记忆测试检查来源伪造、COPY 绑定、整条裁剪、恢复与归档校验、诊断记录和预览隔离。策略和期限测试位于 `test_agent_policy.py`、`test_question_budget_delivery.py`，流式期限反例位于 `test_company_api_streaming.py`。测试入口不等于本次运行结果；实际通过数量与发布状态以对应提交的验证记录为准。

离线模拟接口不代表真实网关、私有源码或办公设备验证，也不能证明真实业务答案质量已经达标。本文说明当前源码行为，不宣称桌面正式版本已经发布或现场验收完成。

正式 Windows 发布仍须通过 [`tools/publish_desktop_release.py`](../tools/publish_desktop_release.py)，按[同包联合验收流程](joint-release-acceptance.md)取得最终 ZIP/EXE 的原生离线结果、真实模型问答、逐条人工评审和目标办公设备验收。缺项时保留候选，不修改草稿状态绕过门禁，也不自动替换现有正式版本。
