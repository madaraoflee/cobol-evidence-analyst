# 2026-11-08 缺陷补录与回归门禁审计

本次以已发布候选的源码 `3d01ef7fa2c0b11f3565f2de15f4c428bc813773` 为基线，使用独立工作目录。产品运行代码、既有回归测试、桌面/办公室工作流、原有资料库和进行中的在线分析改动均未修改；未构建应用、发布或调用真实模型。

账本补录 225 条能够从历史提交/故障报告追溯并绑定现有测试的故障，另登记本次维护门禁确认的 4 条缺陷，共 229 条已修复源码机制记录。9 条仍缺验证或结案依据的记录保留为 open，不能算作全部通过。原始历史可能还有未细分小修或 Git 之外的现场现象，本次不宣称历史绝无遗漏。

## 本次确认的门禁缺陷

旧汇总器 `tools/check_python_regression_reports.py` 对每次分片执行完整性有检查，但没有持久的历史测试最低集合。使用其现有合成 `fixture_reports`，把一个非强制测试从所有分片的发现及执行集合删除，并重算自报清单摘要后，8 项变成 7 项，汇总仍返回 passed、零验证错误。这不能证明被删测试对应的旧故障没有复发。

同一合成夹具把非强制测试标记 skipped，写入原因 `old regression disabled`，汇总也返回 passed。旧汇总接受 expected_failure；这与“每个旧故障必须真实通过”的要求不同。新维护入口要求所有实际结果为 passed，不把跳过或预期失败记为已验证。

新增入口的第一版在审查中发现两处遗漏：只纳入 `poc/tests` 而漏掉 `tools/tests`；只扫描浅克隆可见历史，可能看不到先前已被删除的合同。前者已把维护测试纳入独立完整执行组；后者已要求完整 Git 历史，并以真实 depth=1 临时仓库验证被阻断。两处均在本次提交前修复并登记，不掩盖开发过程中发现的缺陷。

新入口还检查旧条目及测试映射不可删除、已提交的删减不能重置合同、每项测试恰好执行一次、浏览器实际测试身份和完整结果、验证前后源码内容一致。测试可增加，不能通过缩减旧合同换取通过。独立审查没有发现本轮范围内其他可证的错误放行；这不是对未来代码或未覆盖场景的绝对保证。

## 保留未验证的事项

`BUG-20261007-901/902` 来自历史真实评测报告：保存前状态被用于返回后路由，以及动态调用失败说明混淆字段阶段。历史报告有实际失败，但缺当前版本同题重测和人工结案，不用相邻源码测试替代。

`BUG-20261020-901` 与 `BUG-20261021-901` 是历史修复线索尚未完成精确测试映射：前端固定一秒采样遮蔽更新、晚出现控制条件及原因丢失。它们不等于已确认当前版本仍会复发，需要补完对应证据和测试映射。

`BUG-20261106-901/902/903/904` 保留现场启动耗时、HTTP 500、TLS 失败线索和复杂业务顺序回答质量。用户截图证明错误或不完整回答出现过；它们不能单独确定服务端根因。已修复的启动、供证、压缩和记忆继承问题各有独立回归，但不能据此宣布公司设备、实际接口及该业务题全部通过。真实源码、模型和设备验收仍限于既有授权。

`BUG-20261108-901` 是当前开发基线的集成风险：原工作目录仍位于 `aa6b89b`，含并行在线分析的未提交改动；候选版是 `3d01ef7`。二者之间还有四个本地运行模块和五个回归文件的已发布修复差异：`analysis_compaction.py`、`business_chat.py`、`conversation_analysis_handoff.py`、`prior_source_memory.py`，以及 deferred retry、multiturn handoff、restore efficiency、cancellation、failed handoff 的测试。后续若从旧分支生成应用，就有带回旧问题的风险。本次没有为修复集成风险擅自修改被冻结的本地核心，也没有覆盖并行在线改动。

可选处理是用户允许后，把已经审阅和发布过的差异合入在线开发基线，再验证所有本地与在线回归；另一选择是继续隔离分支，在正式集成前保持这条记录未验证。单纯复制新门禁不会把旧运行代码变成最新版本。已有本地冻结要求不因维护工具增加而解除。

## 运行与报告边界

本次维护入口纳入所有现有 Python 测试（含维护工具测试）和浏览器测试。每轮结果单独保存，精确数量和逐条状态见对应 `BUG-REGRESSION-REPORT.json`。报告必须分别说明源码回归是否通过及全部登记缺陷是否已经验证；9 条 open 存在时，后者只能为 false。源码验证不触发打包，也不修改正式发布门禁。
