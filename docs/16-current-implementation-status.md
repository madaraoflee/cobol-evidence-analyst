# 当前实现与已知限制

更新：2026-09-29。本文是项目当前实现状态的单一事实入口；产品愿景、目标架构和带日期的历史报告仍保留各自原有语境。操作步骤见[系统使用手册](./15-system-user-manual.md)。本轮产品化方案见[业务 Agent 演进设计](./18-business-agent-evolution-design.md)，当前第一优先级是业务回答质量。

## 当前可用路径

网页和 `analyze_source.py` 的默认业务问答使用本机 SQLite、FTS5/BM25、静态程序结构及 CALL/COPY 关系定位候选源码；模型可根据已读片段请求补充搜索、按行阅读或主动检索框架手册。当前没有启用稠密向量检索，也没有把完整控制流/数据流路径工具接入默认问答。目标架构中的 Qdrant、Neo4j、LangGraph、完整 IR 与双层 Claim 核验仍属后续设计，不应描述为当前已部署能力。

默认回答面向 BA，以 Markdown 解释业务结论、条件、计算口径和影响。源码只在用户明确要求时出现在正文，引用可展开查看。调查轮数、上下文及工具数量从运行策略读取；本轮增加的框架补查仍在既有调用预算内执行。主索引和会话已有 SQLite 数据库，部分 JSON 仍参与工作区恢复与报告控制，不能随意删除。

长对话供模型读取的历史有数量与字符预算；框架文档缓存有条数和估算字节预算。原始 API 响应需在连接设置中明确选取下一次保存；一般回答和引用仍保留。公司电脑已有保密基础，本轮不扩展企业安全平台。

回答可带有效源码引用，但默认自然语言回答没有完成通用语义 Claim 核验；机器结果将 narrative 标为 `unverified`、`claims_semantically_verified=false`，问题完整性也未验证。`ANALYZED` 仅表示本轮取得了可用回答，不等于业务结论正确或相关逻辑已找全。合成测试通过证明的是受测代码与流程，不是公司方言覆盖或真实业务有效性。

## 已复现的快照新鲜度缺口

2026-09-28 在临时源码目录复现：先索引包含 `ALPHA` 的源码，再将它等长度替换为 `GAMMA` 并恢复原 mtime；搜索 `ALPHA` 仍返回旧源码片段，校验状态为 `size_mtime`。增量构建在 `verify_content` 未启用时按大小和 mtime 复用旧 Hash；在线命中校验也在这两个元数据相同时跳过实际内容 Hash。相关实现见 [`business_index.py`](../poc/business_index.py) 与 [`repository_discovery.py`](../poc/repository_discovery.py)。

因此，快速复用不能保证每次问答所用片段与磁盘上的同路径源码内容一致。该缺口影响快照新鲜度、证据引用及据此生成的答案。此复现使用临时合成源码，没有读取或修改任何企业源码。

当前已加入“等长内容替换且保留 mtime”的回归，确认主动完整内容刷新可识别这种变更；默认快速模式仍按大小和修改时间复用，创建时间 `ctime_ns` 不参与阻断。下一阶段设计把分析绑定到导入内容快照或固定仓库提交，避免用每次问题全库扫描换取新鲜度。元数据复用属于性能优化，不应表述为重新验证了全部源码字节。

## 真实环境验收

此前配置曾返回 HTTP 401。用户随后更新了 `.env`，并明确要求所有费用先经同意；更新后没有执行真实模型验收，不能把旧 401 当作新配置的检测结果。离线测试使用合成样本和模拟接口，不替代获准 API、公司真实 COBOL/COPYBOOK、Windows 实机和业务专家的答案评审。测试数量记录在相应日期的验收报告中，不等于业务正确率。

## 优先顺序

1. 以业务回答质量为主线：检查相关程序和规则是否找到、计算条件和参数链是否完整、框架原文是否正确对应当前调用、追问是否承接正确对象。
2. 经费用批准后，用真实接口评测未预写业务问题；分开记录候选程序、实际供模型阅读的源码、答案引用、规则遗漏和专家评分，不用检索命中或模拟答案代替质量分。
3. 按真实遗漏原因接入更深的路径工具或语义召回，同时建设版本化知识与运行恢复；随后接入 Bitbucket。coding agent 复用知识底座，单独增加修改、编译、测试及写入权限。
