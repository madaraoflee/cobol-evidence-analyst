本轮回答检查发现了能改变结果的遗漏：完整源码规定基础值大于零才乘以二，否则归零，随后复核标志为 Y 时把结果覆盖为 19；旧检查会接受“金额等于基础值乘以二”的普通或简短答复而不复核。基础值 −5、标志 N 对应 0，基础值 10、标志 Y 对应 19，无条件算式分别给出 −10、20。现按实际供应原文中的目标赋值和控制语法提示适用条件、分支、舍入及后续覆盖，预算内复核遗漏；“等于”单独出现不能充当条件解释。明确请求简短只改变篇幅，不能省略影响结果的规则；无分支单一公式仍可一轮完成。提示是保守的词法覆盖检查，不是 COBOL 执行器或语义判分。

修订采纳也增加了不退化检查：在修订请求裁剪后的同一供证上评估两稿，修订若新丢失初稿已解释的业务项，保留初稿及其原轮次引用；仍有缺项但补足其中一项的修订可以采纳。“算式”提问已同时进入调查和回答检查。新增离线反例使用真实临时源码与固定响应，分别隔离源码供应、遗漏复核和修订保留行为，不能据此报告真实模型准确率提升。

2026-10-04 针对实际界面中“我会继续核对”却结束回答、反复说同一程序材料不足的问题，确认了请求供应链的三处缺口：自然提问中的“逻辑／邏輯／logic”未触发业务步骤补读；明确单程序的全文受普通片段 36,000 字符限制提前回退；调查承诺会被当作可交付正文。离线对照的合成程序有 51,317 字符、948 行，旧默认首轮只供应约 19,400 字符的 14 个片段；修复后同题首轮供应完整 948 行，实际请求约 74 KB。该对照只证明源码供应行为改善，不是公司源码或真实模型回答准确性的验收。

现将唯一明确程序的全文额度独立为 `max_complete_source_characters`，默认 128,000 字符；普通检索片段与其他来源仍受 `max_source_characters` 默认 36,000 字符限制，实际请求仍不得超过 230,000 字节。全文装不下实际请求时退回本题相关片段并撤销完整供应标记，不用删空源码伪装完成。通用业务描述或多个候选尚未明确时继续调查，不把自动默认入口认定为用户指定的唯一程序。独立额度可通过本机 `agent-settings.json` 配置，模板见 [`poc/agent-settings.example.json`](../poc/agent-settings.example.json)。请求字节限制不等于模型的 token 上下文限制，现场接口能否接受仍须实际验证。

“我会继续核对，再说明”等第一人称未来调查承诺会触发预算内的实际调查机会；反复承诺不能被标为完整业务回答，也不能覆盖此前已保存的规则和引用。本轮补读额度耗尽、但仍有明确未执行的本地源码动作时，可以进入剩余预算内的下一轮；已执行、失败或只是传输裁剪的动作不会因此反复读取。分享诊断同时导出普通源码、全文源码与请求额度，以及完整供应状态和早期预算遗漏；“已入库但未送全”与“外部实现确实缺失”分别记录。接口 HTTP 500 仍停止请求并保留已有正文及原轮次引用，本次未定位现场服务端返回 500 的内部原因。

最重要的工程变化是“实际发给模型的原文”成为引用依据。材料选择按结果、条件、输入、调用与返回处理排序；最终请求裁剪后重新计算可见源码、框架节录、调用点和 outline 覆盖。前一轮发送过、后一轮已经挤掉的材料不能支持最终引用。read 的未完范围保留游标；新增原文或明确回答缺项可触发预算内一次初稿修订，失败时保留初稿及其作答轮引用。默认预算为每题最多五次模型请求、36,000 普通源码字符、128,000 唯一明确程序全文字符、18,000 历史字符、8,000 框架字符、230,000 请求字节。

本题首次真正使用某个文件时按字节采集并计算 SHA-256，之后的阅读、COPY 展开和语义分析复用该捕获。若捕获与主索引不同，仅替换该文件的索引事实、搜索页与受影响关系，并重算 SQLite 快照；不按全库磁盘元数据逐文件扫描。等长且保留 mtime 的修改因此可被选中文件的首次采集发现。索引目录中尚未登记的新增文件仍须重新接入；“本题已核对选中文件”不等于全库实时一致。历史上已丢失的旧节录无法凭当前 live 文件恢复；本轮开始保存的答案引用使用版本化节录，侧库缓存淘汰也不删除这些节录。

已支持的过程 COPY 使用明确的 SQL 目录解析唯一成员，按需采集展开依赖，派生解析行通过 source map 回到原文件、行号与包含位置。动态调用、复杂别名、COPY REPLACING、部分条件编译及未支持的控制形式仍只提供有出处的候选和缺口，不宣称完整运行路径。公共实现无源码时仍结合调用者条件、实参、返回处理和匹配手册解释已知部分；手册约定与实际执行事实分开。
