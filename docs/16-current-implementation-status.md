# 当前实现与已知限制

更新：2026-10-02。默认网页冷问与已有索引的追问都经过同一条业务调查链：SQLite 全文与稀疏关系定位、本题选中文件的内容采集、按需语义侧库、证据组装、有限补查、普通 Markdown 回答。工作台仍使用原模型适配器、会话存储和界面。主索引仍是 `business_sparse`；语义侧库只分析本题选中的文件，不把所有问题变成全库结构解析。

2026-10-02 已将框架约定接入离线导入与默认网页问答：本机手册的明确功能、状态、阶段表先编译为带版本和出处的规则，再绑定源码调用、赋值及参数布局。已解释的公共静态调用在实际材料完整供应时可解除对应的外部实现缺口；它不补齐业务算式，也不证明调用成功。已有源码实现优先；未知常量、动态目标、资料冲突、布局不符仍保留具体原因。缓存位于主索引的 `framework_knowledge_cache` / `framework_file_semantics`，按源码、资料和编译器版本失效。稀疏索引升级为 `business-sparse-v1.3`，补充 DATA 声明，需要一次重建。设计与边界见 [ADR-0011](./adr/0011-offline-framework-conventions.md)。

2026-10-01 已修复纯业务描述零命中时直接接受“没有资料”的流程缺口、直接命中长程序却遗漏深处计算的候选缺口，以及公共字段关联先扫描全库的性能问题。无命中先进行有预算的源码词项规划，目录样本不作为答题证据；源码、手册与未定位状态分开记录。同一合成 12,000 文件索引的广泛查询，本地业务导航中位数从 9.624 秒降至 0.820 秒，未包含模型等待；这不代表公司实际问答已验收。复现、修复范围与现场核对方式见[本轮报告](./reports/2026-10-01-business-query-recovery.md)。

最重要的工程变化是“实际发给模型的原文”成为引用依据。材料选择按结果、条件、输入、调用与返回处理排序；最终请求裁剪后重新计算可见源码、框架节录、调用点和 outline 覆盖。前一轮发送过、后一轮已经挤掉的材料不能支持最终引用。read 的未完范围保留游标；只有取得新相关原文且仍有请求额度时才允许一次初稿修订，失败时保留初稿及其作答轮引用。默认预算仍为每题最多五次模型请求、36,000 源码字符、18,000 历史字符、8,000 框架字符、230,000 请求字节。

本题首次真正使用某个文件时按字节采集并计算 SHA-256，之后的阅读、COPY 展开和语义分析复用该捕获。若捕获与主索引不同，仅替换该文件的索引事实、搜索页与受影响关系，并重算 SQLite 快照；不按全库磁盘元数据逐文件扫描。等长且保留 mtime 的修改因此可被选中文件的首次采集发现。索引目录中尚未登记的新增文件仍须重新接入；“本题已核对选中文件”不等于全库实时一致。历史上已丢失的旧节录无法凭当前 live 文件恢复；本轮开始保存的答案引用使用版本化节录，侧库缓存淘汰也不删除这些节录。

已支持的过程 COPY 使用明确的 SQL 目录解析唯一成员，按需采集展开依赖，派生解析行通过 source map 回到原文件、行号与包含位置。动态调用、复杂别名、COPY REPLACING、部分条件编译及未支持的控制形式仍只提供有出处的候选和缺口，不宣称完整运行路径。公共实现无源码时仍结合调用者条件、实参、返回处理和匹配手册解释已知部分；手册约定与实际执行事实分开。

“相关对象”结果保留已索引文本命中、语句关联、静态调用路径、对象类型与未解析外部目标。完整结果在本地句柄中分页及导出，模型仅收到最多 20 条预览。普通文本或注释命中不能被写成真实运行影响。多轮追问恢复有界的关注对象、来源定位和未完任务；明确新对象以新问题优先。`ANALYZED` 仍只表示取得可用回答，`claims_semantically_verified=false` 不代表业务正确性已经核定。

逐轮元数据位于输出目录 `quality-traces/`；只有显式 `capture_context` 保存评测所需的实际节录。语义缓存位于 `semantic-scopes/`，旧引用节录位于 `versioned-evidence.sqlite`，完整相关对象位于 `impact-results/`。这几处是本机运行存储，不应提交公开仓库。

2026-09-28 的大小与 mtime 快速校验缺口保留在历史审查中。2026-09-30 的离线回归已覆盖默认问答路径上选中文件的内容哈希和局部刷新；其他兼容入口仍可能采用旧元数据检查，不能将默认路径结果外推为所有读取方式都具备同样新鲜度。现有结构关系是保守候选，不是完整执行图。

2026-10-02 本轮完整回归通过 1,437 项 Python 测试和 87 项页面测试。新增检查包括离线规则编译、调用与参数绑定、源码或手册变化后的缓存失效、COPY 预处理边界、请求裁剪撤销覆盖，以及长程序局部提问在原阅读预算内补齐声明。模型请求使用合成资料和假 transport，检查的是实际请求内容及缺口分类。

默认问答针对明确 HTTP 500、502、503、504 增加整题最多一次、延迟一秒的同请求重试，计入原有模型请求额度，不调整输出额度。实际发送次数、请求摘要与最终答案轮次一致；恢复成功的历史错误不污染最终失败诊断，连续失败或复审失败仍保留错误和可用初稿。质量记录与结果指标中的 `provider_retries` 保存尝试轮次、请求字节数、有效输出额度及恢复结果。10 项新增反例覆盖重试额度、最后一轮禁止继续查工具、取消等待及初稿引用保留。该机制只缓解间歇性失败，未定位公司服务端 HTTP 500 的具体根因。

连接诊断保留原错误码和 HTTP 状态，追加经过封闭枚举校验的 `transport_reason`。网络库包装的超时正确归为超时；只有异常类型或系统错误号明确时才区分 DNS、证书、TLS 建连、拒绝连接、连接重置及网络不可达。代理返回的任意异常文本不用于猜测原因，也不回显。连接测试将公司接口 5xx 响应、网络故障和浏览器无法取得本机测试结果分开提示。本轮未改变接口地址、认证、代理设置、证书校验、测试请求额度或连接方式；尚未取得用户公司现场完整错误，不能宣称实际连接已恢复。

真实模型连接、公司源码问答和收费评测本轮均未运行。离线假 transport 的答案与测试数量只证明请求装配、版本、分页、预算和失败处理的工程行为。真实业务相关性、关键条件遗漏、框架解释、最终结果和 BA 可用性须在费用范围获批准后，用独立 holdout 问题与人工金标准验收。可执行计划和未评分模板见 [`docs/eval/`](./eval/)；本页作为离线证据的唯一维护入口。
