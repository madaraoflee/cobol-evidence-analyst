# 当前实现与已知限制

更新：2026-09-28。本文是项目当前实现状态的单一事实入口；产品愿景、目标架构和带日期的历史报告仍保留各自原有语境。操作步骤见[系统使用手册](./15-system-user-manual.md)，任务与验收进度见[进度总表](./12-task-plan-and-progress.md)。

## 当前可用路径

网页和 `analyze_source.py` 的默认业务问答使用本机 SQLite、FTS5/BM25、静态程序结构及 CALL/COPY 关系定位候选源码；模型可根据已读片段请求有限的补充搜索或按行阅读。当前没有启用稠密向量检索，也没有把完整控制流/数据流路径工具接入默认问答。目标架构中的 Qdrant、Neo4j、LangGraph、完整 IR 与双层 Claim 核验仍属后续设计，不应描述为当前 POC 已部署能力。

回答可带有效源码引用，但默认自然语言回答没有完成通用语义 Claim 核验；机器结果将 narrative 标为 `unverified`、`claims_semantically_verified=false`，问题完整性也未验证。`ANALYZED` 仅表示本轮取得了可用回答，不等于业务结论正确或相关逻辑已找全。合成测试通过证明的是受测代码与流程，不是公司方言覆盖或真实业务有效性。

## 已复现的快照新鲜度缺口

2026-09-28 在临时源码目录复现：先索引包含 `ALPHA` 的源码，再将它等长度替换为 `GAMMA` 并恢复原 mtime；搜索 `ALPHA` 仍返回旧源码片段，校验状态为 `size_mtime`。增量构建在 `verify_content` 未启用时按大小和 mtime 复用旧 Hash；在线命中校验也在这两个元数据相同时跳过实际内容 Hash。相关实现见 [`business_index.py`](../poc/business_index.py) 与 [`repository_discovery.py`](../poc/repository_discovery.py)。

因此，当前不能保证每次问答所用片段与磁盘上的同路径源码内容一致。该缺口影响快照新鲜度、证据引用及据此生成的答案，是 P1 证据底座的阻塞项。此复现使用临时合成源码，没有读取或修改任何企业源码；本次只更新文档，没有修改实现。

在实现修复并加入“等长内容替换且保留 mtime”的回归测试前，高风险分析应先执行接入时的完整内容校验并重建索引；若无法确认该次索引确实完成了内容校验，应将答案视为可能基于旧快照，不用于业务决策。元数据复用只能作为性能优化，不能单独作为内容完整性证明。

## 真实环境验收

截至 2026-09-27，配置的模型接口连通检测返回 HTTP 401，没有取得真实模型回答。项目当前的 1005 项 Python 测试与 72 项页面测试使用本地合成样本和模拟接口；它们不替代获准 API、公司真实 COBOL/COPYBOOK、Windows 实机和业务专家金标准验收。P0 接入、P1 证据新鲜度、P2 单流程完整分析和 P3 真实问答质量仍不能据本地测试宣布通过。

## 优先顺序

1. 修复索引构建与在线证据读取的内容新鲜度核验；添加保留 mtime 的同长度变更测试，并验证旧索引不能继续提供旧证据。
2. 用获准的公司 API 完成真实调用，再对未预写的业务问题评测检索遗漏、结论支持、答案完整性和拒答。
3. 在真实案例明确瓶颈后，再决定是否把深层路径工具接入问答、增加语义检索或引入目标架构中的外部组件。
