# 从 Bitbucket 接入源码

新增入口位于左侧栏原有本地源码卡片下方，先把指定版本的源码下载到独立本机快照，再复用现有索引和业务分析流程。原本地目录入口继续使用；远程下载和索引全部成功后，才把当前资料库切换到新快照。下载、解压、索引失败或用户取消时保留原资料库和对话。两种来源共用问答、结果展示、引用、对话记录及导出，回答详略、阅读范围、回答要求与可选编译／框架设置也沿用相同逻辑。

## 使用方法

1. 在左侧栏原有本地源码卡片下方选择“从 Bitbucket 接入”（窄屏先展开左侧导航），粘贴仓库页、目录页或 HTTPS clone 链接，例如 `https://code.example.invalid/projects/DEMO/repos/business-source/browse/stage?at=refs%2Fheads%2Fmain`。
2. 分支／标签／提交和仓库内目录可以留空，沿用链接中的设置；链接也没有版本时，使用仓库默认分支。显式填写的非空值优先于链接中的设置。目录填写 `stage` 这类仓库相对路径；要包含该目录下的多个源码子目录，选择它们的共同父目录。
3. 私有仓库填写具有仓库读取权限的 HTTP 访问令牌。令牌仅供本次请求，不写入工作台配置、资料库或日志；再次获取时需重新填写。公开仓库可留空。浏览器已经登录不会自动为工作台下载授权。
4. 核对编码、固定／自由格式；需要时在“进阶读取选项”填写框架资料、编译／COPY 设置和扩展名，再提交。界面显示解析版本、下载、解压和原有索引进度；完成后即可使用原有问答与引用功能。接入本身不调用模型。

支持含部署前缀的链接，如 `https://code.example.invalid/code/projects/DEMO/repos/business-source/browse/stage`，以及 `https://code.example.invalid/scm/DEMO/business-source.git`。链接不能包含账号、密码或令牌。第一版支持 Server / Data Center；`bitbucket.org` 的 Cloud 链接、SSH clone、浏览器 SSO 登录和自动同步暂未实现。

## 快照和原资料如何保存

每次主动获取都创建新的源码目录及结果目录，不覆盖以前的本地目录或远程快照。默认保存在应用数据目录下的 `remote-sources/<随机编号>/source` 和同级 `analysis`；源码运行通常位于 `.poc-data/remote-sources/`，配置了 `WORKBENCH_DATA_DIR` 时使用该目录。索引、对话与来源信息随本机数据保管，不提交到公开仓库。

下载前先把所选分支解析为完整提交编号，再按该编号下载，避免下载时分支变化导致来源不明。源码资料页展示仓库链接、版本选择、目录和实际提交编号。重启只恢复本机快照，不重新连接仓库。想获取后续代码时点击“重新取得 Bitbucket 快照”；它会创建另一份资料库，目前不跨这两份资料库自动迁移对话，也不自动删除旧快照。

先前本地路径和读取设置仍保留在本地接入表单。右侧“最近对话”按“本地源码”和“Bitbucket”分组，并显示所属目录或仓库；点击历史对话会恢复它自己的源码资料库、索引和框架资料。不同资料库的对话不会混用当前源码，删除另一资料库的对话也不会切换当前分析对象。原源码暂时不可用时仍可查看已保存历史，但需要恢复源码与有效索引后才能继续分析。

对话标题从第一个有实质内容的问题提炼主题，保留程序名、字段名与关键条件，去掉请求套话和输出格式要求，例如“REQUEST01 的金额检查流程”。简单的“继续”“为什么”等追问不会覆盖原主题。旧的自动截断标题在读取时显示为摘要标题，原消息、时间和自定义标题保持不变；生成标题不增加模型调用。

最近对话只读取工作台已登记的资料库，不扫描其他磁盘目录；最多保留 100 个资料库登记，合并展示最近 200 段对话，超出显示范围不会删除磁盘数据。旧版本保留的当前资料库与可验证的本地路径会自动纳入；其他旧资料库可通过“切换源码目录”重新接入原源码和原结果目录。下载失败会清理本次未完成的缓存；异常退出或清理时磁盘故障可能留下未采用的目录，应先确认它不是正在使用的快照再处理。

## 连接和容量边界

运行工作台的电脑需要能够访问仓库，必要时先连接企业网络或 VPN。HTTP 401／403 表示令牌或读取权限问题，404 也可能由权限隐藏造成。服务器跳转到登录页时，使用最终 HTTPS 仓库地址和有效令牌；工作台不跟随重定向。企业证书需被 Python 的 HTTPS 信任配置接受，程序不会关闭证书校验。

当前限制为压缩下载最多 512 MiB、解压文件总量最多 2 GiB、归档条目最多 100,000，ZIP 中央目录元数据最多 32 MiB。网络读操作超时为 30 秒，获取和解压还受 15 分钟总预算约束；阻塞读取可能到单次超时才响应取消。超限时选择较小目录。子目录外的 COPYBOOK 不会一起下载，应选共同父目录来覆盖分析依赖。Git LFS 实体和子模块内容不会另外拉取。

实现参考官方 [Bitbucket Server REST API](https://docs.atlassian.com/bitbucket-server/rest/7.17.0/bitbucket-rest.html) 的 commits 与 archive 接口，以及 [HTTP access tokens](https://confluence.atlassian.com/bitbucketserver086/http-access-tokens-1188782454.html) 的 Bearer 认证方式。

## 验证范围

自动回归使用中性合成源码和模拟仓库响应，覆盖链接解析、固定提交下载、安全解压、凭据处理、成功切换、失败／取消回滚、重启恢复、三种界面语言及原本地入口。另以本机 HTTPS 测试仓库运行实际提交解析、ZIP 下载、解压和索引流程，验证认证失败后的原资料库恢复；这没有连接用户的真实企业仓库。

整合测试同时检查跨来源问答和自定义回答要求：同名程序在两个资料库使用不同规则，切换历史、重启和重试后仍取各自源码与对话，保存的回答要求进入实际模型请求。前端回归涵盖导入取消时恢复框架设置、历史恢复期间的操作冲突、迟到响应隔离，以及摘要标题不会截成错误程序名。

使用隔离浏览器实际点击了来源分组、历史对话、源码引用和回答要求入口，并核对刷新后的来源与草稿行为。入口布局见[界面截图](./reports/2026-10-28-remote-source-ui/left-entry-grouped-history.jpg)。源码流程的真实模型测试与最终 Windows EXE 的离线回归分别记录，不能互相代替；企业服务器版本、代理、证书、真实权限及同包办公设备验收仍需在获准环境完成。
